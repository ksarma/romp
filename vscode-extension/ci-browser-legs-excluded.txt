# The browser legs the gating CI job does NOT run, each with its reason. The step "Browser legs (node --test over
# ci-browser-legs.txt)" in .github/workflows/ci.yml runs the legs in ci-browser-legs.txt with a browser; every other
# browser leg of the extension's test build is listed here, so a leg added later takes a verdict: it is in the roster or in this file,
# never neither. A browser leg is what the census, scripts/browser-legs-census.mjs, reads from a test module's tree
# with the TypeScript compiler: it calls the shared launcher (inBrowser in ui/webview/real-viewer-leg.ts) through its
# import under any binding, or names a playwright package by any specifier, or holds a driver string that loads one; a
# form the census cannot classify is refused with file and line, never counted absent, and so is a module that reaches
# inBrowser or playwright only through another module of the tree it loads (the census reads a loaded module for what it
# binds or calls, transitively, and follows nothing through it). ui/webview/ci-browser-legs-census.test.ts
# (the vscode-extension job) holds the roster plus this file to that census and scripts/ci-browser-legs.sh checks the
# same before it runs a leg; tools/ci-browser-legs.test.mjs (the Shell job) holds the two files' shape and reasons
# without the compiler. A line whose source moved or was deleted turns all three red.
#
# Format: one compiled bundle path per line, relative to vscode-extension/, as the Test step's npm test builds it
# (ui/webview/<name>.test.ts builds to out-tests/ui/webview/<name>.test.js), then a TAB, then the reason. Blank
# lines and lines starting with # are ignored. The reasons at the roster's creation are derived from the sources: a
# leg that reaches Firefox or WebKit (the census reads the engines from playwright-derived expressions, not from
# strings) cannot run green in a job that installs Chromium only, and its reason names the engine, checked both ways
# (these legs launch on their own and never read the switch, so under the step they would skip as they do without it;
# the one that calls inBrowser beside its own Firefox launch is refused by the roster gate too); a leg whose only
# playwright is in a driver string it runs as a child process carries the sentence "loads playwright in a child process
# it drives from a string; the switch never reaches it", checked both ways, and can never be rostered; every other leg
# carries the grandfather reason, the sentence quoted on the next line, so its owner moves it to the roster with the
# step's measured numbers.
# Every grandfather reason, "existing before the roster, unmeasured in the gating job; its owner moves it to the roster with measured numbers", is bound to commit ff436587f4e826e2450517517efdf0b3208c9359: a source that did not exist at that commit may not carry it; the bound reads the file's age, not what it did there, so a source that existed at that commit without a browser launch may carry it, and one that gained its launch later is rostered once it passes the gate, or carries the engine or embedded-driver form when one is true of it.
# That commit is main at the roster's creation, and this line is the bound's one home: ui/webview/ci-browser-legs-census.test.ts
# (the vscode-extension job) reads the commit and the sentence from here, fetches the commit at depth 1 when the checkout
# lacks it (a fetch or object read that fails is a red naming the reason, never a pass), and refuses a row carrying the
# sentence whose source is not in the tree at that commit; tools/ci-browser-legs.test.mjs (the Shell job, a depth-1
# checkout that fetches nothing) holds this header to one such line and does not run that history read. Both read a reason
# as one of four forms: the grandfather sentence as quoted on the line above, whole and exact; an engine reason, "launches
# <Firefox|WebKit|Firefox and WebKit>; the gating job installs Chromium only", a tail after the phrase allowed; the
# embedded-driver sentence, whole and exact; or a pending line. A reason that is none of them is refused by name (there is
# no reason of its own, so the exemption cannot be made in another spelling), and one that reads as one form while its text
# carries another form's phrase is refused as ambiguous, so a tail cannot carry a second claim.
# To move a leg, delete its line here and add
# the bundle path to ci-browser-legs.txt (a leg in both files turns the checkers red); a leg that launches through
# its own playwright copy first switches its launch to inBrowser in ui/webview/real-viewer-leg.ts, the one shared
# launcher and the one read of ROMP_BROWSER_LEGS_REQUIRE, and drops its own playwright, launch, skip and todo, or the
# roster gate refuses it with the gap it read.
# A reason reading "pending #<PR>: <why>" names a browser leg an open PR brings and is allowed only while the leg's
# source is absent from the tree: the line is then in neither the roster nor the census, and the equality the checkers
# hold is the roster PLUS the lines here whose source is present EQUALS the census's legs. Once the source is present
# (the PR merged main, or the checkers run on the PR's own branch) every checker turns the line red with the promotion
# remedy derived from the source (a roster line for a leg that passes the gate and reaches Chromium alone; the engine
# form, or the embedded-driver sentence, when one is true of it; for a Chromium-only leg that misses the gate, pass the
# gate and roster it, since no form here admits such a leg; no line for a module that is no leg), so the owner promotes
# it in that merge; a pending reason that names no PR is red. A pending line whose PR closes without the leg never turns red
# on its own (nothing in the tree reads a PR's state) and is removed by hand;
# `grep '^out-tests.*pending #' vscode-extension/ci-browser-legs-excluded.txt` lists the pending lines (the rows alone: a
# grep for the bare prefix would list this header's two lines that spell the form as well); tools/ci-browser-legs.test.mjs
# runs that command as written here and holds its output to the pending rows.
# The pending rows at the roster's creation were DERIVED, not recalled: on 2026-09-22 at 00:01Z the fork's open PRs were listed with
# `gh api "repos/<owner>/<repo>/pulls?state=open&per_page=100" --paginate`, each PR's added or modified .test.ts files under
# the census's directories (LEG_DIRS in scripts/browser-legs-census.mjs) were read with
# `gh api "repos/<owner>/<repo>/pulls/<N>/files?per_page=100" --paginate`, and each candidate's content at the PR's head was
# classified by that module's classify(); the rows name every leg that read found absent from this tree. A PR opened after
# that read is not in the rows: its leg is red as in neither file when it arrives and takes the pending-row remedy then, never
# a guessed roster or exclusions line. A pending row alone does not clear a PR whose module the census refuses: the census
# refuses before the equality runs, so that PR stays red until the form is rewritten or the census is taught it.
