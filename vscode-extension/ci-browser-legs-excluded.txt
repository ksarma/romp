# ci-browser-legs.txt)" in .github/workflows/ci.yml runs the legs in ci-browser-legs.txt with a browser; every other
# browser leg in the tree (a test module that launches a Playwright browser: it requires or imports "playwright", or
# imports ./real-viewer-leg and calls inBrowser) is listed here, so a leg added later takes a verdict: it is in the
# roster or in this file, never neither (tools/ci-browser-legs.test.mjs and scripts/ci-browser-legs.sh hold that, and
# a line whose source moved or was deleted turns both red).

# Format: one compiled bundle path per line, relative to vscode-extension/, as the Test step's npm test builds it
# (ui/webview/<name>.test.ts builds to out-tests/ui/webview/<name>.test.js), then a TAB, then the reason. Blank
# lines and lines starting with # are ignored. The reasons at the roster's creation are derived from the sources: a
# leg that launches Firefox or WebKit cannot run green in a job that installs Chromium only (and the switch would
# make its launch skip a failure); every other leg predates the roster and has not been measured in the gating job,
# so its owner moves it to the roster with the step's measured numbers. To move a leg, delete its line here and add
# the bundle path to ci-browser-legs.txt (a leg in both files turns both checkers red); a leg that launches through
# its own playwright copy first switches its launch to inBrowser in ui/webview/real-viewer-leg.ts, the one shared
# launcher and the one read of ROMP_BROWSER_LEGS_REQUIRE, and drops its own launch and skip, or the roster refuses it.
