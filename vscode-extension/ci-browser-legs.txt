# The browser legs the gating CI job runs with a browser. The step "Browser legs (node --test over
# ci-browser-legs.txt)" in .github/workflows/ci.yml reads this file into node --test (scripts/ci-browser-legs.sh)
# after the job's Chromium install, with ROMP_BROWSER_LEGS_REQUIRE=1: the one shared launcher, inBrowser in
# ui/webview/real-viewer-leg.ts, reads the switch (any non-empty value arms it) and under it a leg that cannot launch
# fails naming the switch and the reason instead of skipping. The Test step's npm test runs every leg too, before
# any browser is installed, so each leg skips there at launch; this step is the job's only run of a rostered leg
# with a browser.
#
# Format: one compiled bundle path per line, relative to vscode-extension/, as the Test step's npm test builds it
# (ui/webview/<name>-browser.test.ts builds to out-tests/ui/webview/<name>-browser.test.js), for example
#   out-tests/ui/webview/gear-sub-focus-browser.test.js
# Blank lines and lines starting with # are ignored. A PR that wants its legs run adds them as lines here and puts
# the step's measured seconds in its body. The script refuses a malformed or duplicated line, a line whose source
# moved or was deleted, and a line whose bundle is not built; tools/ci-browser-legs.test.mjs (the Shell job) holds
# the same shape.
#
# The roster rule is checked by the PR's reviewer, not by the step: a leg listed here launches its browser through
# inBrowser alone (an alias is a call), with no playwright load, launch, skip or todo of its own, in Chromium, the one
# engine the job installs. Only inBrowser reads the switch, so a launch or a skip of the leg's own stands outside it:
# a private skip stays a skip, and a private launch that fails is never the failure naming the switch. Nothing in the
# tree reads a leg's source for the rule, so the step reads these four cases green: a rostered leg that launches its
# own browser and swallows a failed launch without skipping; a rostered module that launches nothing; a leg that
# drives a browser from a child process and tolerates the child's failure; a todo test that passes beside a real pass.
# tools/ci-browser-legs.test.mjs runs a synthetic leg of each case and reads it green.
# Nothing checks that every browser leg in the tree is rostered, and main has no such check. After the run, a skipped
# test, a failure inside a todo, a file that failed as a whole, or a leg that ran no passing test is red: each is
# coverage the step would claim and not have. A leg's Firefox and WebKit runs live elsewhere (a served pytest step,
# a local run).
#
# The switch test below spawns three child node --test runs of its own first test (the switch set to "1", to another
# non-empty value, and unset) with PLAYWRIGHT_BROWSERS_PATH pointed at an empty directory, and asserts that the two
# children under the switch fail and the one without it skips: that is its test of the switch, not a browser driven
# from a child process, and its own first test opens a page through inBrowser.
