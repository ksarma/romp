# The state root's trust boundary: the method

**Status:** design note for a fix PR (874, branch `state-root-mode-refuse`), written 2026-09-20 against the round-2 head 9748684d3 and rewritten 2026-09-21 for round 4 (romp-manager's round-3 ruling). This note records the METHOD: how the population of reads under the state root is derived and pinned, what the guard promises, what a quarantine is, and where the boundary lies. It is not a list of paths: the list is produced by code and kept current by a test, and a hand-kept list is what round 3 refuted (a roster of two against a population of at least eight, built on a wrong belief about which read happens first).

## The defect and the shape of the fix

`kernel/judge.py` makes the state root 0700 at import, best-effort, swallowing the OSError; until 2026-09-20 the mode was read back once and said in one stderr sentence when it was not 0700, refusing nothing. A root this uid did not own stayed loose with a line nobody read, a root loosened after boot was never read again, and `_atomic_write`'s interim-mode argument ("the owner-only state root is what makes that interim safe") rested on a diagnostic. The root's mode is the premise of every credential file under it and of the no-heal rule for those files.

The fix gives the check a consequence, and the consequence is one shape everywhere: the process stops (exit 2). Round 1 answered with a runtime 503 latch that closed the kernel's two doors and left every internal writer running under the hostile root; round 2 replaced the latch with the exit, at the kernel's import before any entry under the root is read, at boot before any thread, from whichever thread finds it at runtime, and in the postal bus at start and on every poll. Round 2b settled one question the other way (a pre-existing root that read a write bit at import but read 0700 after the judge module's own chmod booted, loudly, and was not refused), resting on two named artifacts being guarded. An artifact enumeration (strace over hermetic roots at 9748684d3; kept in the review notes) refuted the settlement: the kernel import touched thirteen paths under the root after the gate and the bus start ten, most unguarded, and one of the adopted entries was executable code (the SDK venv's site-packages, put on `sys.path[0]`). Round 3 ruled: stop enumerating; derive the population; put one shared guarded reader over all of it; pin the population so a new reader cannot join unguarded; quarantine rather than skip; make the discriminator ownership plus the absence of a symlink, never the directory's mode; gate every long-lived writer; keep the predicate in one text. Round 4 builds that.

## One implementation

`kernel/state_root_mode.py` (stdlib only) is the one text: the root's verdict (`check`, `import_read_refusal`), the discriminator (`writable_by_another`, `private_group` with its bounded, memoized lookup), the guard (`trusted_path`), the quarantine (`quarantine`) and the guarded readers (`Reader`). `kernel/judge.py` loads it by `load_source` under the fixed module name `romp_state_root_mode` (reusing a copy the event model loaded first); `kernel/event_model.py`, `postal/postal_service.py`, `kernel/session_host.py`, `bin/romp-session-host` and the six kernel-side modules the kernel hands its root to per call (`kernel/logins.py`, `kernel/palette.py`, `kernel/host_transport.py`, `kernel/sdk_backend.py`, `kernel/codex_backend.py`, `kernel/codex_runtime.py`) load the same file by path under the same name, so a process holding several holds one module object and one `Reader` class. The five root binders hold one reader each (`_gr`); the six handed-root modules build one per call over the root they were given (`_reader(state_dir)`, or the backends' `self._gr` over their own state directory), and a reader built with no row hook of its own files through the module's `REFUSED_HOOKS`, where the kernel registers its error-centre hook, so a helper module's refusal is the same row as the kernel's. `tests/test_state_root_mode.py`'s `OneText` holds, as an AST fact, that none of the loaders defines a function or class the module exports, that each names the module, and that no KEEP IN SYNC comment about the state root remains. The one copy the repo keeps on purpose, the serve-token loader in the kernel and the bus, stays under its own AST-identity gate (`ServeTokenLoadersMatch`).

## The rule (as round 4 leaves it)

**The discriminator.** "Writable by another local user" means: the mode carries an OTHER write bit, or it carries a GROUP write bit and the group is not the owner's private group (the group database lists no member but the owner and no other account has the gid as its primary group). On a box with user-private groups a directory made at the umask's mode under umask 0002 reads 0775 and is writable by nobody but its owner, so it is warn-class (re-tightened and reported once); the same 0775 under a shared group is refused; an other write bit is refused with no lookup. A group database that cannot be read or does not answer within the bound (a daemon thread joined with `LOOKUP_BOUND_S`, 3 s) counts as writable, the restricted side, with its own remedy ("the group database could not be read (ENAME or timeout): check getent group <gid> and the name service; romp refuses until it can tell who else can write here"), never the distrust remedy. A definite answer is memoized per (gid, uid) for five minutes together with the callables it came from, so the readers cost one lookup per group and a patched database in a test is always seen; the judge primes the process's own group at import.

**Read before repair; unknown restricted; ENOTDIR.** Every check reads first and takes its verdict from the read; the best-effort chmod runs after and is reported. A root whose mode cannot be read is refuse-class. A root path that exists and is not a directory is verdict refuse with ENOTDIR and its own remedy (remove it and recreate the root as a directory), at every check; the judge import records the mkdir's EEXIST and never chmods the file.

**The import-read rule and the creation exemption.** A pre-existing root whose mode as read at the judge module's import, before its own chmod, was writable by another local user, AND WHICH HELD ENTRIES at that read, refuses at the kernel's import (exit 2) whatever the chmod did afterwards, with the distrust remedy (entries planted while it was writable are not to be trusted; remove serve-token, repo-root and every entry you did not make, or recreate the root, then chmod 700; what the next boot's readers refuse lands in the quarantine directory). A root that was EMPTY at that read is a creation default, whoever made it: the manager's mkdirSync, the CLI's mkdir -p and every harness's makedirs make the root at the umask's mode a moment before the first romp process tightens it, and nothing could have been planted in an empty directory, so the ordinary first boot is silent. The same at boot (the two doors agree), in the bus's start gate and in the session host's start gate, each on its own first read.

**Every long-lived writer runs the check.** The kernel at import, at boot, on the housekeeping pass's cadence and before every request. The bus at its import in every mode (the module reads or mints the serve token under the root at import whatever argv says, so `romp mail` and each session's MCP process are gated too), in `serve()` and on every monitor poll; the root the bus creates is made 0700 at the mkdir (the token loader's `mkdir(mode=0o700)` and `serve()`'s), with no looser instant. The session host at its start (before the spawn spec is read, and before the CLI is spawned) and on every lease beat (3 s), exiting 2 with one `state-root-refused` row in `host.log`. A client frame on an already-open WebSocket runs its op without a read of its own; the socket road relies on the request road's check and the pass's, and honours an exit already taken (`_STATE_ROOT_REFUSED`; pinned by a test that upgrades a socket on a 0700 root, sets the flag as a first finder would, and sends one frame: nothing is dispatched).

## The guard's property

`trusted_path(root, path)`: the root is resolved (a legitimate root reached through a symlink stays legitimate; `tests/test_asm_checkpoint.py` relies on it) and judged; then every component from the root down to the path is `lstat`'ed and must be not a symlink, owned by this process's effective uid, and not writable by another local user by the discriminator. Never the directory's mode alone, and never a plain "no group or other bit": a 0775 venv or a 0664 parked-ops mirror under the owner's private group passes (the refuters' legitimacy cases). A path not under the root is not the root's to guard, and the readers pass it through (a transcript under the Claude config directory). The root's own failure is the gates' case: the readers read absent and quarantine nothing there.

## The quarantine contract

A guarded reader that meets a failing component renames it, the first failing component under the root, to `<root>/quarantine/<utc-stamp>.<its path below the root with slashes as dots>` (the `quarantine` directory created 0700; a `quarantine` entry that is itself not a trusted directory is moved aside first), says one stderr line naming the entry, the reason and the destination, files one refused-kind row through the caller's hook (the kernel's error centre; the bus's log; the host's `host.log`; the shared module's `REFUSED_HOOKS` for a reader built without one), and then behaves as if the path were absent: `FileNotFoundError` from the readers that raise it for a missing file (`read_text`, `read_bytes`, `open`, `os_open`, `gzip_open`, `stat`), an empty answer from the directory readers (`listdir`, `scandir`, `iterdir`, `glob`), False from `isdir` and `exists`, nothing added from `sys_path_dir`. A quarantine that itself fails (EPERM, a busy mount) says so and still reads absent. A FAULT IS NOT A PLANT (round 4d): an EACCES or EPERM (any errno but ENOENT and ENOTDIR) on the `lstat` of a component whose parent the walk has just trusted (this uid's, not a symlink, not writable by another local user, so holding nothing another uid put there; an owner-only directory of ours with no search bit is the case met) is the directory's fault, not an entry's untrustworthiness: nothing is quarantined, no line and no row, and the reader runs the site's primitive, which raises the fault as the bare read raised it before round 4 (`PermissionError` from `Path.read_text`; `Path.exists` answers as the interpreter's pathlib does), so the caller's own fault handling still runs (the judge's `_reg_spawned_at` files its judge-errors row and plans the session on a sentinel; the round-4 readers answered absent there, and `tests/test_planner_skip.py`'s unreadable-sdk case held on 3.12 only because `_sdk_owned`'s `Path.exists` raised the same EACCES, which 3.14's pathlib swallows). A ROOT that itself fails the guard (gone, not a directory, another uid's, writable by another) is the gate's case and not an entry's: the readers under it read absent, quarantine nothing, file no row, and say it once per process per root and cause (a backend over a root that is gone would otherwise say it on every read). Nothing planted is adopted, and nothing is merely skipped: a plant that was only skipped stood on disk and was re-adopted at the next boot (the ruling's B); a quarantined one is out of the root and kept for review. The checkpoints directory is judged once at `_ckpt_dir()` by the judge's provider (`_ckpt_dir_guarded`) and cached until a rebind, since every checkpoint door, the boot sweep included, builds its paths under it (the ruling's C: the guard belongs at `_ckpt_dir()` itself).

## The census: how the population is derived and pinned

`tests/test_state_root_readers.py` is the derivation and the pin. It is an AST census over eleven modules: the five that bind the root at import (`kernel/kernel.py`, `kernel/judge.py`, `kernel/event_model.py`, `postal/postal_service.py`, `kernel/session_host.py`) and the six the kernel hands its root to per call (`kernel/logins.py`, `kernel/palette.py`, `kernel/host_transport.py`, `kernel/sdk_backend.py`, `kernel/codex_backend.py`, `kernel/codex_runtime.py`; the review of round 4's tree found their reads outside the first census's view, a planted `codexvenv` reaching `sys.path[0]` and a planted login record reaching the login-billing road among them). It reads source text alone and loads no romp module.

Seeds. Each module is seeded with its ROOT NAMES: the expressions that are the state root or a directory bound from it at import. The judge's seeds are the globals its `_rebind_state` declares (the test derives that list from the AST and holds the seed set equal to it), plus the call-time derivations (`_overrides_dir()`, `em._ckpt_dir()`) and the event model's constants; the kernel's are the same names through `jd.`; the bus's are its module constants (`STATE`, `MAILROOT`, `TLDIR`, `PIDFILE`, and so on); the session host's are the attributes its spec binds (`self.state_dir`, `self.dir`, `self.spec_path`). A parameter a caller outside the module hands a root path is declared in `PARAM_SEEDS` (`read_journal_dir`'s `directory`, handed by `kernel/host_transport.py`). For the six handed-root modules every parameter named `state_dir` or `state`, in every function, is the root (`PARAM_NAME_SEEDS`), and so are `self.state_dir` and `self.state`.

Derivation, to a fixpoint. An expression is a path under the root when it is a seed; a module-level name bound from one; a `/` or a join onto one (`Path(...)`, `str(...)`, `os.path.join`, `.with_name`, `.parent`); a scandir entry's `.path`; a call of a function whose return is one (or `self.<method>()` of a class method whose return is one); a parameter some call site in the module hands one; a local bound from one, keyed on the NEAREST PRECEDING binding of the name (a 1000-line dispatch reuses `p` for a client's path and a root path in different branches; a fallback binding to an empty literal in an `except` arm says nothing); a loop, `with` or comprehension target over one; or an ENTRY a guarded listing answers (`_gr.iterdir(...)`, `_gr.glob(...)`, `_gr.scandir(...)`). The BYTES a read answers are data, not a path: a names entry's recorded cwd used as a browse path is not a root read, and the file viewer's helpers stay out of the census.

Reads. Over those expressions the census lists every read: `read_text`, `read_bytes`, `open` in a read mode (the mode is the first argument of the method form, the second of the function form), `os.open` without a write or create flag, `io.open`, `gzip.open`, `glob`, `rglob`, `glob.glob`, `os.listdir`, `os.scandir`, `iterdir`, `is_dir`, `os.path.isdir`, and `sys.path.insert` or `append` of one. A write (`open` in a write mode, `_atomic_write`, an O_EXCL temp) is not a read; a bare stat is not a read of bytes.

The pin. Every read either goes through a Reader or sits on the ALLOWLIST with a one-line reason. A reader instance is recognised by its binding: a module global assigned from `<module>.Reader(...)`, a call of a module function whose return is one (`_reader(state_dir)`, the per-call shape), a name ending in `_gr` (a global, `self._gr`, a local) or a parameter named `gr` (a caller's reader handed down). The allowlist at round 4 has nine entries: the serve-token loader's own reads in the kernel and the bus (its own guards, the AST-identity gate), the mint's sweep of its own temps (unlinked by name), the kernel's `os.listdir` of the root itself for the judge-child pid records (kept for its raise on an unlistable root, which the orphan sweep's mark depends on), the judge import's own read of the root (is it a directory; is it empty), and the two directory descriptors opened for fsync after an atomic publish (the bus's and the Codex registry's). A stale allowlist entry (one that no longer names a read the census finds) reds the module too, so the list cannot outlive the code. The test `test_the_census_reds_on_a_planted_unguarded_reader` proves the pin can red: a copy of the kernel with one new `Path.read_text` of `jd.STATE / "planted.json"` and one `os.listdir` of a root subdirectory comes out with exactly those two unguarded; the same copy through `_gr` comes out clean. `test_a_reader_through_a_parameter_a_helper_and_a_loop_is_seen` pins the derivation's reach, and `test_a_handed_root_modules_planted_reads_are_seen` the handed-root shapes (a `state_dir` parameter, a `gr` parameter, a listing entry's `.path`).

How to re-run it: `python3 tests/test_state_root_readers.py --list` prints every read (file:line, function, kind, target, guarded or allowlisted or UNGUARDED) and exits 1 when an unguarded, unallowlisted read exists. After the review of round 4's tree the census sees 424 reads: 415 guarded, 9 allowlisted, 0 unguarded (kernel 178, judge 79, event model 22, bus 99, session host 5, sdk_backend 27, codex_backend 8, logins 2, host_transport 2, palette 1, codex_runtime 1).

What the census does not see: a read through a name the derivation cannot follow (a path stored in a dict and read back; a path handed in from a module outside the eleven). When such a road is found, the seeds or the parameter seeds are where it is declared, and the census then follows it. A path derived from a process argument is one such road, declared as a seed (the session host's `Path(argv[0])`, its spec path three levels under the root; round 4f's review). The derivation binds a comprehension's target in the comprehension's own scope, as Python 3 does: round 4f's review found a generator that rebound the kernel's `p` over the notice rows hiding the notice file's republish on a later line from both censuses (the nearest preceding binding of `p` was the generator's data row), and the scoping fixed it in the shared derivation; the readers census's planted kernel pins both halves (a def's `p` read after such a generator is seen; a comprehension's target over a root listing is a root entry inside it).

The primitive rule (round 4c). After the guard's walk a reader performs the read through the same pathlib or os call the site used before round 4, chosen by the argument's kind: a `Path` takes `Path.read_text`, `Path.read_bytes`, `Path.stat`, `Path.exists`, `Path.is_dir`, `Path.iterdir`, `Path.glob`; a `str` takes `os.stat`, `os.path.exists`, `os.path.isdir`, `os.listdir`, `glob.glob`; `Reader.open` is `builtins.open`, `Reader.os_open` is `os.open` with the flags as given, `Reader.gzip_open` is `gzip.open`; `listdir` and `scandir` are `os.listdir` and `os.scandir`. The nine sites that used `glob.glob(str(...))` before round 4 pass a `str` base so they use it again. Round 4's readers opened by descriptor (`os.open` with `O_NOFOLLOW | O_CLOEXEC`, then `io.open(fd)`), and `Reader.stat` called `os.stat`: the round-4 sweep showed 95 failures in 22 test modules that are byte-identical to the round-2 head, every one of which counts, faults or races a read of the state root by interposing on `Path.read_text`, `Path.read_bytes` or `Path.stat` (`tests/test_cleared_set_memo.py` counts reads, `tests/test_kernel_order.py` raises EACCES from a stat fault, `tests/test_ledger_unproved_reads.py` publishes under a read), and none of them met the descriptor reads. Those tests state a contract of the suite: the kernel reads state through pathlib. The Reader keeps its guard and its quarantine unchanged and reads through the site's own primitive, so the 22 modules pass with no change (one exception, a source-text pin: `tests/test_fleet_restart.py` asserted the string `FLEET_REPORT.read_text()` in the handler's source, and now asserts `_gr.read_text(FLEET_REPORT)`; the delegate can revert that one line if the pin is to stand).

The test seams. A test that faults or counts a read of a file under the root replaces `Path.read_text`, `Path.read_bytes`, `Path.stat` or `builtins.open`, and since round 4c meets the guarded read that way again. `tests/guarded_reads.py` is a second seam one level up: it patches the shared `Reader` class (`fault`, `stat_fault`, `count`, `before_open`, `wrap_open`, `start_spy`), so one fixture reaches a read whichever reader and whichever primitive it takes; because the five opening methods each call their own primitive, a hook on every open patches all five. Twelve test modules use it (the round-4 fixtures that moved to it); the three that had kept the old seam beside it and summed both counts (`tests/test_usage_limits_split.py`, `tests/test_stage0_log_readers.py`, `tests/test_judge_stage_gate.py`'s CourierGate count) are back on the old seam alone, as at the round-2 head. Two more seams belong to the tests: `jd._rebind_state(root, make=True)` makes a test's state root and floors it at 0700 in the one place the floor lives (`TheFloorReachesEveryMintedRoot` holds, over every `tests/*.py`, that no test makes its root bare), and `tests/conftest.py` replaces the kernel's runtime exit with a raising double for every test's length, so a hostile root met inside a test reds with a traceback instead of ending the worker.

## The boundary no check can close

A file or directory descriptor a peer opened inside the root while it was writable survives the tightening: POSIX checks permission at open, not per operation, so a directory descriptor another account kept open on `<root>/postal/` keeps letting it create and replace entries there after the root is 0700, and a file descriptor kept open on a memo file keeps letting it write. No read of the root's mode, before or after the chmod, can see or close that, and no guard on the entries can either (a write through a held descriptor changes bytes under a name that stays this uid's). Removing and recreating the root is therefore the boundary of what any of this promises: the checks refuse the window, the readers quarantine what was planted in it, and only removal and re-creation close a descriptor a peer already holds. Stated in the code (`kernel/state_root_mode.py`, `kernel/kernel.py`'s import gate) and in `docs/reference.md`.

Beside it, the window between a reader's guard walk and the primitive's own open (round 4c). The walk lstat's every component and refuses a symlink at any of them; the read that follows opens the path again. Between the two, a component could be replaced by a symlink only by this process's uid: the gate admits only a root not writable by another local user (0700 in the ordinary case; a looser mode writable by nobody but its owner, 0755 for one, when the chmod was refused and the boot warned), and the walk has just judged every directory from the root down to the path the same way, so no other uid can create, rename or link an entry in any of them, and a process is not defended from itself. Round 4's `O_NOFOLLOW` on the final open closed nothing a peer could use and made the readers invisible to the suite's pathlib seams; round 4c removed it. The residual is stated in the Reader's docstring.

Beside both, a transient loosening a sibling repairs (round 4d's finding, round 4f's word). Every writer on the root reads its mode before it repairs it, on its own cadence: the kernel on the housekeeping pass and before each request, the bus at import and on each poll, the host at start and on each beat. A root loosened and re-tightened between two of the kernel's reads by a sibling's gate (the bus the kernel's boot starts, a host's beat) is therefore never read loose by the kernel: for a transient loosening repaired before the kernel's cadence sees it, the bus's refusal line is the trace, and the kernel's rows carry nothing; the kernel does not report a repair it did not see.

## Residuals and follow-ups

- The token loader's ownership argument rests on mode plus chmod, not on owner: a self-owned file a co-tenant could move into place (a shared writable directory on the same filesystem) is adopted. An owner-plus-inode check beside the mode check is a follow-up of its own.
- The bus's `mkdir exist_ok` of `postal/`, `postal/mail` and the box directories adopts a directory whatever its owner; every READ under them is now guarded (a foreign-owned box or a planted message file is quarantined at the first read), but a directory descriptor a peer already holds is the boundary above.
- `_sdk_problem`'s seq collision (extra7-3 of round 2) is pre-existing; the state-root rows no longer ride it.
- The shell picker's guard (`pick_python` in `bin/romp-serve`, `bin/romp-sdk-setup`, `bin/romp-codex-setup`, byte-identical) runs the module over the SDK venv's `pyvenv.cfg` when a `python3` and the checkout are at hand; on a bare PATH with neither (the bats fixtures) it falls back to what bash can judge alone, ownership and the absence of a symlink on the cfg, the venv and the root, without the group judgment.
- The Codex runtime's tree (round 4f): `install_runtime` tightens pip's staging directory to 0700 before the rename publishes it under `codex-runtime/`, but the files and directories pip made inside it keep pip's modes (the wheel's, clipped by the umask), as the SDK venv's do under `sdkvenv/`; a component the readers judge on the way to a file inside is owner-only at the top and pip's below, admitted by the discriminator under the ordinary umasks and quarantined under one that leaves an other write bit. A mode walk over an installed tree is a follow-up of its own.
- An entry made before round 4f at the umask's mode is tightened on its next use by the creator that touches it (a directory by `make_dir`, a file by `born_owner_only`; the CLI's and the manager's files by the `chmod` after their next write); one no creator touches again keeps its mode, as `_atomic_write`'s interim argument always had it: no boot-time walk re-modes the root. The far root's `kernel.log` and `update.log` are made empty at 0600 before the first append on a host that has none; one a login shell made loose before round 4f's review keeps its mode until the far kernel's own creators touch it, which for those two logs is never (the kernel's stdout is the shell's redirect, not a creator's).
- `perf-exports/`, settled by execution (2026-09-21, romp-manager's question). A `perf-exports/` born 777 by `cli/perf_export.py`'s bare `mkdir(parents=True)` under a 0700 root boots clean and is neither quarantined nor refused: a served kernel at b8c691ba7 ran the import gate, the boot check, the request road's re-check on three requests and the housekeeping pass's stage (re-check interval 0) and the judge-child record sweep over that root with no state-root line, no `quarantine/` and no refused row, and the directory stayed 777 (the judge serve child's `sweep_stale_temps` and the bus's and host's start gates are covered by code reading: each judges the root's own inode, or lists the root's NAMES and drops every name it does not select before any lstat). The WHY, in the boundary's terms: the gates judge the root's own inode and at most count its entries for the empty-root exemption; the guard judges only the components of a path a reader asks for; the roads that list the root's names (`_judge_child_records`, `sweep_stale_temps`, the `session-flags.json.corrupt-*` globs) select by name before reading; and no reader of the kernel's, the judge's, the bus's or the host's is pointed under `perf-exports/` (`trusted_path` would judge it writable by another local user if one were). The umask pin's population is the four processes' own roads over a hermetic root, and its docstring says so. What the probe DID find is the defect of the five CLI mkdirs in a third place: on an ABSENT root under a permissive umask the same `mkdir(parents=True)` made the ROOT at the umask's mode and the export filled it (measured: root 777, perf-exports 777, the file 600 under umask 000), which the next boot's import refusal would have met; `cli/perf_export.py` now sets `os.umask(0o077)` first in `main` (a `--out` parent it has to make is 0700 too; the file was 0600 already) and tightens an older loose `perf-exports/` of its own under the root on the next export. What a loose `perf-exports/` left by an older export carries until then is the tool's own exposure under a warn-class root (another uid that can traverse a 0755 root can list the 0600 exports' names), not the boundary's.
- The codex judge's reply file (round 4f's review): the vendor's CLI creates `judge-scratch/codex-<pid>-<rid>.out` at the child's umask, which the site sets to 077, so the guarded read of it admits it under any umask; a child that ignored its umask would be outside what any creator of ours can promise, and the judge would then record "codex empty reply" and a refused row, as before.
