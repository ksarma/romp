Upstream ships the walk this pins: the wake-only mode is its #936, the parse gate its T401 and the shared decision read its #1141, and jobs stage 1 (fork PR 784) made the wake-only look record and skip on the ten-file key. Fold ruling A condition 7 required exactly one shared load per alive session with the toggle off; stage 1's first wording made that at most one and dropped the floor. The reviewer's ruling of 2026-09-19 restored the floor and then restated the condition per mechanism, since two loaders read a session's store on the walk's road and a single call count is falsified by any new legitimate reader where a named mechanism adds a clause: the walk takes at most one shared goal-store load per alive session per pass, exactly one when its look reaches the store and zero when the look is skipped (a skipped look repeats its verdict and writes nothing, so it needs no data) or ends at a state gate before the store read; the placement gate's post-derivation currency check is a separate load, at most one per derived session, counted apart. The ruling asked for a test that counts loads per pass against whether the look ran or skipped, red in both directions, with a counter added if none exists. None did: memos.nudgeWalk counted looks, parses and skips but not the store reads, and memos.shared counts every reader's calls on the shared cache, not the walk's. So this adds memos.nudgeWalk.loads, bumped at the walk's one call site (the gate's check is the gate's own and is not counted there), names it in the _PerfStats gloss and the reference's memos.nudgeWalk entry, states both bounds in the reference's jobs block, and pins them in tests/test_nudge_walk_one_load_per_pass.py: the real pass over two alive sessions with real transcript files and stores, a recorder on the name the walk resolves at call time (km.jd.load_goals_shared_or_fault) that records the caller and calls through, the walk's and the gate's counts asserted separately per pass and per session and never summed, the served counter beside the walk's count. Per session: the walk loads once on the first pass and on a ledger-driven run pass, zero on the skip passes, one beside zero when one session's transcript moves, and zero on a look a state gate ends first; the gate checks once per derived session and never when served or skipped; no writer load. Tier fix because a served counter is added. Mutations, each landed and reverted: a load in the skip path (a read before the memo is consulted, or the skip's early return dropped) reds the skip pass on the walk's bound; the load gone from the run path (a stale per-sid snapshot reused) reds the run pass on the walk's bound.
