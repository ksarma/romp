A real postal bus started from tests/test_kernel.py's peer-notify guard test (an in-process kernel whose refused bus call revives the bus on a thread, running the postal service's ensure with the test process's environment) and outlived the run in one CI cell of fork PR #813, writing into a shared state root every 30 s and turning another module's snapshot test red. The child's environment was the sum of three import-time writes in other modules: tests/test_kernel_tunnels.py's module-level ROMP_POSTAL_PORT (the run's own, so the bus's fixed-port belt licensed the bind) and ROMP_POSTAL_CLIENT_ONLY (inert while peers are on), and the ROMP_SESSIONS_FILE seam ten postal modules set at module level (one live row, so the bus never autostopped). The fix is fitted to the class rather than the instance: the tunnels module sets all three postal legs per test and patches the kernel's import-time BUS_PORT beside them, restored by cleanups; the guard test stubs the revive road (subprocess.run recorded), waits for it and asserts the ensure argv, so a real child is never attempted and a revive no longer attempted fails the test; conftest pops ROMP_POSTAL_PORT before every test; the seam and the postal host move per test in the ten modules; and the repo-wide pin in tests/test_hermetic_kernel_postal.py holds the set of environment names the test modules write at module level EQUAL to a licensed set, each licence checked per write (a value, a per-test re-assert in conftest, a date and the item a temporary licence waits on), with a census command for the counts by name and shape. Beside it, tests/conftest.py gains a run-end check in the controller: every live process whose environment or cwd holds one of the run's temp roots is named (pid, command line, the names it holds the root through, the test phase current at its spawn when it carried one) after a bounded wait for its exit, and the run is red; it found the tunnels mocks' orphaned trailing sleep on its first run. What stays unknown is what put the first write inside the asserting test's 50 ms window on that cell. Reading rules out a kick, a restart road or a removal of postal/ in the 21 modules between the bus-restore module and the asserting module (server.pid and server.log were not among the files added, so no bus started inside the window), and it read only those modules. One source it did not rule out ran in every run at the round-1 head of fork PR #894, deterministic and seen in 4 of 5 CI cells: every kernel a test module loads in-process read BUS_PORT 25302, the machine's fixed bus port, so its bus calls reached the bus a developer's box runs there (the postal service loaded in-process built its client's BASE from the same popped name, and three set_working tests of tests/test_postal_relay_honesty.py beat the bus through it), and where nothing listened three tests' refused detach notify revived the bus with a real romp-postal-service ensure from the test process (tests/test_kernel_known_hosts.py's two KnownHostMemory detach tests and tests/test_peer_reconnect.py's test_detach_is_the_one_end_of_intent). This PR closes it: conftest gives every loaded kernel module a dead BUS_PORT and every loaded postal module a dead BASE for each test, the three detach tests stub the revive, and the pin in tests/test_hermetic_kernel_postal.py runs the modules whose kernels dialled the fixed port (derived by a spy over one full serial run) together in both orders under a connect and spawn spy, with no connect to the fixed port and no postal-service process. What would settle fork PR #813's cell: that spawn spy over one serial run of its head, or PYTEST_CURRENT_TEST and the thread name logged beside the kernel's refusal line. The disclosure is conditional: a run carries the contaminant only when the revive wins the race AND a write lands in an asserting window, the witness being the leaked process the run's log names, with the test name when the spawn carried it. Upstream's tests carry the same module-level writes, the same guard test and the same conftest (their PR #999 took the temp-root hygiene the check reads); tests and docs only.
