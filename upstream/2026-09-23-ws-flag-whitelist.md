The setSessionFlag socket op wrote any flag name an authenticated dashboard client sent, while POST /flag refused a name outside `_LANE_FLAGS` with a 400. So a client could set `threadMail` on a comment thread, the key that turns its mail on (fork PR #897 discloses what follows on the fork: the deadness mirror's roster then omits comment-thread sids that relay), or the legacy `postalOff`, which the kernel and the postal bus read as isolation. Upstream main carries the same arm and reads the same keys. Both flag doors now ask one predicate, `_lane_flag_refusal`, over the one list: the socket answers an unlisted name on the settingRefused frame with the route's sentence inside and `value` null, and writes nothing. It asks for every name a frame carries, a falsy one (null, "", 0, false, [], {}) included, since the arm keys on the flag key's presence; a frame with no flag key draws the terminal arm's unknownOp (the kernel's answer for a known op missing a field its arm requires), where POST /flag answers its 400, and neither writes. The saveFile socket op, under the file-editing consent, can still write session-flags.json whole, as it can any text file; it is not a flag door, and that consent already grants the write. No product surface sends a name outside the list (the lane gear's LANE_TOGGLES, the tab menu's typed union, the Obsidian panel's POST). Tests: the refusal executed through the real dispatcher and over a real socket to the served Handler, red before the fix (the store gained threadMail), the falsy names among the refused ones and the no-key frame a witness; the doors that write a session flag derived from the source of every module in the kernel's directory (which holds every module the kernel loads, pinned) and pinned as a set, an arm counting as a door when it mentions a setter at all (called by name, bound to a local, imported under an alias, picked from a table, named by a string), each asking the predicate, returning on its answer before any setter runs, handing `_set_session_flag` as its flag argument the expression it asked about, with nothing rebinding that expression's root name in between, and calling each setter with exactly its pinned parameters (`(sid, flag, value)`, `(sid, value)`); those source pins read only the names the source spells, so an alias of the frame, a name built from pieces, a star import and the setters' bodies are outside them, which the test module states, and the arm's behaviour is left to the executed tests; every road from a request to a setter (the route's POST arm, the socket's receive loop) derived upward from the setters and pinned, so a new way into either door function reds; the setters are found from every function in those modules that names the flags store in code or calls a helper returning its path, pinned by role (reader, writer, path helper), so a writer counts however its write is spelled, the path reaching it through an assignment, a parameter's default or such a helper, and whichever loaded module it lives in, while a function that stores the path in a module-level name is refused rather than traced. Porting the tests: SocketFlagWhitelist's end-to-end case needs `km.READY_GATE_CAP`, the fork's kernel ready hold, which no offer carries; and FlagWriterPopulation's LOADED set, with the NAMERS roles and the module figures, is derived from the fork's kernel/ and is derived again against upstream's tree (upstream's kernel/ also holds gc_freeze.py). The module imports no test helper upstream main lacks: its census parses the kernel's files itself and does not use tests/parse_cache.py, which upstream main lacks and only the parked-ops-liveness-boot-hold candidate carries.
