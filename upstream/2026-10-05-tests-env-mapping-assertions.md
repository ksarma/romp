A failing unittest assertion prints its operands. assertNotIn(name, env) prints the whole container, assertEqual(env, want) prints both mappings, and mock's assert_called* methods print every call the mock recorded, arguments included. A container that holds an environment under an env key prints it too: the SDK launch options, a session's launch shape, a host spawn spec, a registry entry. assertIsNone(env.get(name)) prints the variable's value whenever it is set. On a developer's machine those values include live API keys. Every such assertion now prints a bool, a field or a count: assertFalse(name in env, name), assertTrue(holder is None, msg), assertEqual(run.call_count, N, msg). An equality over a container is split into its key set and its fields, with the environment field compared as a bool. tests/test_env_mapping_assert_census.py holds the rule. It reads every tests/*.py by AST and fails on an assertion, message or bare assert that renders an environment mapping of a shape it reads (os.environ, an attribute or string key named env or environ, a copy or view of one, the result of a callee that returns one, or such a mapping formatted, sliced or joined into a message), a container the code shows holding one under an env key, or an absent-value check over one. It fails when it finds nothing to watch, keeps an exact-site exemption list (empty), and its docstring lists the shapes it cannot see, with green plants pinning the ones a reader would most expect it to see. Tests only.

The project's tree at upstream/main (f4a572008, 2026-09-24) carries the same assertions. This census, run over it, finds 138 sites (135 assertions) in 23 files: 84 environment mappings, 53 containers that hold one, and one absent-value check over os.environ. Ten more sites have five shapes the census cannot see: tests/test_credentials.py:514 tests a loop variable bound from the (cmd, env) pairs a stubbed spawn recorded; tests/test_judge_auth_billing.py:384, 404 and 449 call assert_not_called or assert_called_once on a mock of subprocess.run, which the judge calls with env=; tests/test_login_records.py:299, 300 and 302 test a child's dump of its environment, read back; tests/test_judge.py:6886 and 7020 call assertIsNone(env.get("MAX_THINKING_TOKENS")), where env is the judge child's environment, unpacked from the list of calls a stubbed spawn recorded; tests/test_env_value_redaction.py:1234 writes a test module as a string and runs it in a child pytest that inherits the test's environment, and that module's assert 'ROMP_TEST_PROBE_PD' not in os.environ prints the environment when it fails. That makes 148 sites, 145 assertions, in 24 files. Each prints a whole environment, or a present variable's value, when it fails: os.environ at 9 sites, and a child's environment, a session's stored environment or a container holding one at the rest. Three of the 23 files are not in the fork (tests/test_clear_batch_echo_retire.py, tests/test_judge_experiment.py, tests/test_worktree_transcript.py), and fork main fixed tests/test_judge.py's two census sites in 4ffc1585f. Upstream's tests/conftest.py masks, in pytest reports only, process-environment values of 16 characters or more (except names it exempts as paths or public) and credential-shaped tokens. It masks values inside the report text and leaves the mapping printed, with its names and every shorter value in the clear, and a plain unittest run has no hook at all.
