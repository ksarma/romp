Stage 0 of the reconnect design (client half). On the phone layout only the chat, the feed (exempt: the bell) and the stored tab load at boot; the Outline, the Sessions band, the Waiting pane and the Files pane load on their first tap, with the src set before the re-tell and a shell-owned loader until the iframe load event. The phone chat pane first dial declares skeleton=1, so a cold open is served one full plus statuses; the idle prefetch chain starts from the stored tab first full applied (or from the strip when it lists no such tab) instead of the strip first paint; an off-screen feed on the phone applies its first frame without painting the board. The desktop's panes and dial are unchanged; the prefetch start gate runs on every layout (it orders the chain behind the active tab's first full). The Files pane is lazy too: its markup line is the one upstream token this fork changes (src to data-src), taken on the coordinator's decision of 2026-09-18; the shell's viewFile and browseFiles relays wait for a just-promoted pane's page load (two inserted lines). Fails-before tests T1 to T6 per the stage-0 design. Offer waits on the user word.
