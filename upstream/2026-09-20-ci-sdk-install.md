CI's Python cells install pytest and cryptography and nothing else, so the 48 tests gated on claude_agent_sdk importing (43 in tests/test_sdk_backend.py, 5 in tests/test_host_transport.py) skip in every cell and read green having checked nothing, the two SDK-transport host tests in tests/test_session_host.py skip with them, every session host a test spawns takes the pipe transport, and the 100 tests whose fixtures install a fake SDK only when the real module is absent (27 spawned-host cases in tests/test_session_host.py, 73 in-process cases across eight other modules) run against the fake; upstream's workflow has the same shape and the same gated module. The change is one step, Install the Claude Agent SDK, between the cryptography step and pytest, reading the version from SDK_TESTED_VERSION in kernel/session_host.py with the sed bin/romp-sdk-setup runs over the same line, so the number has one declaration and the installer, the host's own version check and CI follow it; at this head that is 0.2.156, the version the box's full suite passed under (16875 passed, 566 skipped, 0 failed), while PyPI's latest was 0.2.157, released 2026-09-18 as the fifth version in four days and left alone on purpose. The step refuses an empty, malformed or duplicated constant and carries no continue-on-error: the SDK requires cryptography through mcp's pyjwt[crypto], and a lagging wheel must red the cell, not skip 48 tests. tests/test_ci_sdk_pin.py never skips: it executes the step's own read of the constant and, wherever the SDK imports, asserts the installed version equals it, so a box whose venv moved and a CI cell whose install disagreed both go red; on a venv without the SDK it checks the pin's presence and form and says the equality was not checked there. The bump is the constant's own act (install the new version, run the host tests, move the number); the residual is that nothing polls PyPI, a person notices a release. The 3.14t cell installs it too: on a free-threaded 3.14.6 with the GIL off the install used wheels only (cryptography, cffi, pydantic-core and rpds-py publish cp314t wheels), the import left the GIL off, and the gated pair passed (653 passed, 1 skipped, an unrelated runner-floor pin) and the host pair after the re-gates (101 passed); the SDK's classifiers stop at 3.13, so a release that breaks there shows as a red cell. Two re-gates: the two SDK-transport host tests gate on what the host's interpreter imports (a probe of sys.executable) or on the box venv, not on the venv directory, and the no-SDK control in tests/test_session_host_sdk_pin.py hides an installed SDK from its child with a sitecustomize.py blocker (under an interpreter that has the SDK it read CLINotFoundError where FileNotFoundError was expected, on 3.12 and 3.14t alike). Still skipping in CI: the four MachineVenv tests in tests/test_session_host_sdk_pin.py, which test the venv the installer builds; on a plain venv without the SDK the 48 and the two host tests skip as before. Cost per cell about 106.5 MB of download after the cryptography step (the SDK wheel is 102 MB, it bundles the Claude Code binary) and a few seconds of install on this box; the CI run's own step timings are the measurement. Travels with 2026-09-18-sdk-pin-for-private-imports (#777), which introduced SDK_TESTED_VERSION; upstream's installer installs the SDK unpinned and its tree has no such constant, so an offer there carries the step with a literal version until it does.
