Upstream's suite has the same lazy singleton (kernel.py's _sdk_locked caches SdkBackend over jd.STATE as it stands at the first km._sdk() call) and the same sandboxing tests, so the same leak can put a later module's backend over a removed directory: six classes in five modules did at the branch's original base (main on 2026-09-19), found by running every module alone with the fixture on, on the missing SDK road, which is CI's (the test venv's interpreter has no claude_agent_sdk, and a module run alone does not import tests/test_host_transport.py, the one module in the population that puts the box's SDK venv on sys.path itself); a full-suite census saw none of them, since an earlier first builder in every worker made their builds cache hits, and it ran on the SDK-importable road (a full run here collects tests/test_host_transport.py, whose import puts that venv on sys.path, and every xdist worker imports every collected module; CI never takes that road, since its install has no SDK, and a green CI run of the suite is the missing-road full-suite datum). SdkBackend constructs on either road (the probe at construction only sets _sdk_missing and prints the not-found notices), so the transition the fixtures judge is the same on both, and the fixtures' own tests force the road in each scratch head rather than inherit it. The offer depends on #798, which carries ViewBuilder's save of the backend (the sixth class, in tests/test_kernel.py; upstream's main lacks it, so ViewBuilder fails under the ratchet without it), and on #891, which carries tests/parse_cache.py, the shared parse the kernel-spawn census reads every module through. Autouse fixtures beside _shared_state_restored judge the singleton's transitions at three windows: the test (read before it and after its teardown; the test whose own transition left another object, or removed the directory under the object it found, fails), the class and module boundaries (a scoped read at the start and after tearDownClass or tearDownModule; the scope whose setup or teardown made the bad state fails, named as the boundary), and the setup before a test (a singleton found over a gone directory that no verdict named is reported once per worker, worded as inherited). The allowances are the kernel's own class over jd.STATE as the test found it, present, and the kernel's unavailable outcome; a kernel reload or first load inside a test is judged by what it left; the remedy is one per road. Tests only: the fixtures are tested by nested pytest runs over scratch modules that load the real kernel.

The residual that leaves, a stated limit: a green run under the ratchet proves no leak occurred in that run and not that no test would leak alone, because a first builder that leaves its build masks a later sandboxed test's reach as a cache hit (no build, no transition, the ratchet silent). Measured as a pair and module alone on the missing road, which is CI's (the test venv's interpreter has no claude_agent_sdk and neither run collects tests/test_host_transport.py), tests/test_kernel_fleet_cache.py then tests/test_token_usage.py with CostWeighting's fix reverted gave 77 passed and 0 verdicts, while the module alone gave 65 passed and 1 error. An arm keyed on the build event inherits the masking, since a cache hit is no build, so the order-independent instrument is the module-alone sweep; a reach-under-moved-root arm with two signals (a leak keyed on what is LEFT at teardown, and a wrong-root read keyed on the root the RETURNED backend was built over) is a follow-up item, its own PR after this one.

Beside the ratchet, the same PR moves the kernel-spawn census and the ratchet module's maps onto one name resolver (tests/ast_bindings.py, 2026-09-21): a name read at a call resolves to its declarations in the scope the call is in, by the language's rule, and the value is read from those. The kernel-spawn census (tests/test_hermetic_kernel_postal.py) keyed on a variable's spelling before, a regex over one line and a word search over each call's text, which named a module an offender for a local spelled like a pytest flag and would have passed a kernel spawn through a path bound across two lines (a plant showed the miss; the tree had no such spawn); the ratchet module's maps kept the last binding of a name bound in both arms of a version gate. The spawn census's residual is a rule: whatever it does not read is no path. It lists, by kind, a name in an argv that resolves to a declaration with no readable value (a parameter, an import, a loop or with target) or to none (an attribute of an imported module), a call of a function defined in the module or of a name no scope binds, a passthrough's splatted argv and a keywords splat a spawn is handed alone; it does not list, in the classes found so far, each held by a plant, an argv mutated by append, extend or insert, a spawn function reached through functools.partial or getattr, a function that starts a process other than the subprocess module's spawn functions (os.execv, subprocess.getoutput), a star import's spawn functions other than Popen, a program that starts a kernel other than romp-kernel and the CLI at bin/romp (bin/romp-serve, romp-manager up), the CLI composed from its directory other than by a path function, a comprehension flattening nested lists, a mapping a %-template reads whole, a class attribute bound outside the module's classes, a self-reference through a loop target, or a consumer call's arguments. A string the shell reads (a command string, a shell's -c program) is read at the words the shell splits it into, and a Python -c child's program as Python. The regex pair it replaced runs beside it, copied verbatim, in a comparison over the tree and every plant: a call the regex flags that the census neither finds, lists nor refuses fails that test unless the match is a word collision (never a name that reaches the one-line binding the regex read when the census cannot read its value), inside the program of a Python -c child that parses and starts no process, or the CLI with a verb that starts no kernel, handed to it as known text. The PR's ninth review round found that the rewrite had dropped shapes the regex read (a command string with the path after its first word, a placeholder template, an env-override default, Popen's executable=, a comprehension argv, a subclass's override of a base attribute, `romp up`) with every check green, since the tree held none of them; the comparison is what now shows a replacement reads at least what it replaced. `python tests/test_hermetic_kernel_postal.py --roads` lists each unread name and call and prints, per module, whether a kernel spawn is found by the argv road, the binding road, or neither.
