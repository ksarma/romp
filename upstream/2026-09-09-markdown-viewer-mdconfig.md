Upstream ships the same viewer and the same chat renderer, so the change applies there: a note with Obsidian syntax renders as Obsidian renders it, math renders on every surface instead of the chat page alone, and a remote picture in a viewed file no longer fires a request on open (a tracking pixel) unless its host is on the list or the person clicks. One consequence to weigh with it: the chat replies take the same grammar (wikilinks there are an unclickable styled span, a reply that opens with YAML folds), recorded in the plan as an open ruling.

Built as Slice 4 of plans/markdown-viewer.md on Slice 3's head (fb42df7d), so the offer stacks on the three slices before it, each with its own entry: Slice 1, fork PR #390 (2026-09-07-markdown-viewer-sanitizer; md-config.ts renders the math placeholders that slice introduced and registers KaTeX's fill through its `registerMdPostPass`, which upstream's math.ts and tree have only once #390 lands), Slice 2, fork PR #396 (2026-09-08-markdown-viewer-place; the front matter token re-tiles the block table its rendered index reads), and Slice 3, fork PR #407 (branch `mdviewer-s3`, 2026-09-08-markdown-viewer-typescale, merged 2026-09-09; its `.code-copy` skip in anchor-map.ts is the first name of the control list this slice widens). Four touched files are fork-only and travel with their own candidates or stay behind: the `resolveWikilink` stamp in file-view-links.ts's `viewerWalkTokens` (fork PR #347, 2026-09-07-file-viewer-links; upstream's mdBlock passes marked no walkTokens, so a port that wants `[[Note]]` to resolve in a file document calls the stamp from a walkTokens of its own for the file kind, and without one every wikilink renders as the dead span, the designed rendering everywhere but a file), and the token cases, holes and control list in anchor-map.ts with the `![[image.png]]` reader in file-comments.ts's and tools/file-comments-host.mjs's `imageEmbeds` (the file-comments candidate, 2026-09-07-file-comments-tracked-changes), together with anchor-map-obsidian.test.ts and its fixture, file-comments-panel.test.ts, the host's two tests, the two file-review-plan-focus tests under tools/ (fork-only pins of goTo's and scrollCard's opening statements, which the merge of main re-aimed once Slice 4's revealMarks stood before fork PR #413's focusOn) and the re-pinned anchor-map and file-comments suites. The rest ports as it is. Three files are new, and a port copies all three: md-config.ts, figure-gate.ts and md-block-start.ts (the per-frame memo of the block extensions' `start` hints, which math.ts's math hint imports; md-config.ts's callout registers no hint since review round 3, and without the module math.ts fails to build at that import). Beyond Slice 1's md-sanitize.ts they import only upstream's own modules: marked and math.ts (md-config.ts), md-links.ts and settings.ts (figure-gate.ts, which reads `onExternalSettingsChange` and `window.__rompKernelBase`). The upstream files the slice changes are math.ts (the hint memoised through md-block-start.ts, the block tokenizer's closer search shared with the hint and remembered per frame, and `MATH_ERROR_COLOR`, the `--math-err` token KaTeX's error ink takes), render.ts, chat-md.ts, file-view.ts, settings.ts, gear.js, styles.css and feed.css. Two files of the earlier slices change too and port with them: md-sanitize.ts (Slice 1, #390: `sanitizeMd`'s `own` pass, in which the viewer mints its heading ids before the math fill, and `revealFragmentTarget`, which file-view.ts's `#` landing and file-comments.ts's revealMarks run) and reader-place.ts (Slice 2, #396: `noteText`, which reads an html block's paired elements with the viewer's controls skipped).
