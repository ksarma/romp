Upstream's file viewer keeps the view controls in one span, `.fileview-group-view` (T367's grouping: the format choices, the text-size control and the SVG Source button), hidden as a whole when every control in it is hidden so an all-hidden group takes no gap. renderBody in ui/webview/file-view.ts computes that group's hidden state from the controls' hidden states before its media branch, and the media branch is where the Source button is decided (srcBtn.hidden = !(isSvgImage && objUrl !== null)): on an SVG open the sync reads the Source button as still hidden (its initial state, kept by the loader paint while the bytes are in flight), hides the group, and the media branch then shows the button inside the hidden group with nothing re-reading the group after it, so after an SVG's first paint the view group stays hidden and the Source button with it: the one media control in the group is behind a hidden element. Verified at the tip 14f1548a9: renderBody syncs viewGroup.hidden at line 928, the media branch sets srcBtn.hidden at line 939, and no re-read follows; the pull-in review's ruling (2026-09-16) states that upstream's live main still carries that order. The fork fixed it in the stage 1 pull-in of 14f1548a9 (commit c260d885f, the pull-in's fixer round 2): one line after the media branch's three Source-button writes re-reads viewGroup.hidden with the sync's own expression (on the fork the expression also reads the Outline button, a fork-only control), so the group's state follows the Source button's decision; a fork-made fix to code upstream ships with the defect, kept beside upstream's text (no landed twin). Pinned in ui/webview/file-view-place-svg-source.test.ts (the executed node-only case: the group is shown after an SVG's first paint and stays shown after Source on and after Source off; the pin where CI runs, since CI runs npm test before any browser is installed) and in ui/webview/file-view-place-svg-source-browser.test.ts (headless Chromium, the reload and the panel toggle; it fails without the re-read). The offer is the same one-line re-read after upstream's media branch, with the node-only case as the test that fails before it (upstream's expression carries no Outline term); it waits on the no-new-upstreaming hold like the other 2026-09-16 entries, the ledger being the queue.
