Upstream carries the same two bindings (the judge's STATE is the romp root, the bus's is the root plus postal) and the same read in _presumed_closed, so rule 5 of its dead-session ladder is dead there too: every sid reaching it answers cannot-determine, and a dead sender's card settles only by rules 1 to 3. Re-checked at upstream/main for this round: its _write_remote_sids still writes the whitespace list, pruned by HEARTBEAT_TTL at every write and folded from every PEER_STATE row, from memory alone, and its judge still reads STATE/remote-sids. Found as a side finding of the fork's postal-bus tests PR (fork PR #894), where the reviewer's ruling asked for both STATE bindings to be read and the read to be run; the probe there confirmed it by execution and filed it for its own fix-tier PR.

Moving the reader to the writer's path alone would arm a rule that settles falsely, which the round-1 review of the fork's PR showed by two roads: a bus restarted from empty memory rewrote the mirror at its first poll naming nobody, so until its first exchange every sid live on another host was absent from the file and its local mirror store settled; and, under the legacy singleton scheme, the bus pruned an expired heartbeat's sid at every write, so a tunnel drop or a stalled peer longer than the 90 s TTL settled a live session on no new information. The mirror therefore changed shape: a JSON document with one row per presence source, the roster it last reported, whether the bus heard it in its current process, and whether its presence expired. The writer carries every host the previous file named and this process has not heard forward, unreachable, until its heartbeat or exchange arrives; an expired beat's row stays, marked. The reader presumes a sid closed only when a host vouches for absence and none names it; a sid only an unreachable host names, a mirror in which no host vouches for absence, or a mirror of another shape (the old whitespace list, said once in the judge's log) answers cannot-determine, as the dead rule did. The kernel's link state gates reachability too (round 2's ruling by the reviewer): a host is reachable only when heard and the kernel does not hold its link down, so the down notify makes it unreachable at once with its roster kept (a host that is down cannot vouch for absence, and a session started there since its last roster is in no roster) and its next heartbeat or exchange heard with the link up makes it reachable again; the writer computes the flags per row and the reader reads them, and the two cannot-determine reasons that turn on a source's state name the sources and why each cannot vouch. The rule is two-sided (the reviewer's ruling, the round's fifth commit): a heard host that is not held down vouches for the PRESENCE of the sids it names (`reachable`, rule 4), and a host vouches for the ABSENCE of a sid it does not name (`vouchesAbsence`, rule 5's precondition) only when its link is known up, a dialable PEERS row the kernel holds up and the host heard since the link last dropped (a legacy heartbeat within its TTL vouches as before, having no link), so a heard host with no link state (a host the kernel never notified, or a far bus filed under the hostname it declares before this bus's own dial has folded it under the alias the kernel dials) answers cannot-determine for a sid it does not name, as a down host does. The events: the up notify plus the host heard since make a host vouch for absence, the down notify ends it at once, and for a far bus under its declared name the fold files its row where the alias's link reaches it. Event-keyed, no grace period. One test runs the real writer and the real reader over one root under both root shapes through the first write, a restart, an expiry and the legacy shape. Fix tier: product code with tests red before it.

Round 3 (the reviewer's ruling, the seventh commit): a hub's word about a host this bus also holds directly is never discarded. Until this round the writer folded a hub's gossip about a far host away whenever that host had a dialable PEERS row or a heard row, whatever that row's state (the display fold, _via_duplicate), so with the direct row carried after a restart, or held down by the kernel, a session the hub freshly named on that host was in no row, and the hub, vouching for absence, let rule 5 presume it closed: a false settle, and a regression from round 1's head, which named every gossiped sid. Now the gossip folds into the far host's own row only when that row is heard in this process and the kernel does not hold its link down, matched by the bus id the hub stamps on the gossip (the row may sit under the alias the kernel dials) or by the name the hub uses for the host when the row carries no different known bus id (the eighth commit, the reviewer's verifier's finding by execution: a row under that name whose bus id is not the gossip's is another bus, another machine the hub calls by the name or this one restarted under a new id, and a name match that folded whatever the ids left a session on the other machine in no row while two sources vouched for absence, rule 5 for as long as the direct row was heard and up); otherwise the hub's word stands as a via row under via:<hub>/<far>, a key no host name can collide with, beside the direct row, whose last roster still protects the sids it named; a via row whose hub is not heard is carried like any key, and it is dropped by the carry once the direct host speaks again (its exchange arriving with its link not held down, the event), since its own row then names what runs there, or once the hub's current word about that host folds at a write (a hub knows one machine by a name, so its earlier word under the key is superseded; without this a far bus restarted under a new id and heard here before the hub heard it left a via row stamped with the old id for the file's life, and a session that then ended there was cannot-determine by that stale row where rule 5 was due). A via key carries two names, the hub's and the hub's name for the far host, and either changes with no restart on either side (the ninth commit, the reviewer's verifier's finding by execution through the real handler and the real fold): this bus's own dial folds a hub heard first through its dial to us from the hostname it declared under the alias the kernel dials, and a hub's own fold of the far host under the alias it dials changes the name it stamps; the hub's word is then written under the new key, and the row under the old key, carried by key alone, named a session that had since ended for the file's life, cannot-determine where rule 5 was due. So the carry drops a carried via row by identity as well: when the hub's bus is heard in this process under another name (the same test that drops the hub's own stale row, so the two leave together), and when a hub's current gossip names the far host's bus, by its stamped bus id, under any name. A heard hub gossiping nothing about a far host under the same name still leaves its via row carried (a restarted hub has not heard it yet). What no identity in the file reaches stays disclosed: a hub restarted under a new bus id and heard under another name leaves its old row and that row's via rows carried for the file's life (a departed host's rows), as does a hub that stamps no bus id renaming a far host. The drop once the direct host speaks again is pinned on its own, with the hub not heard, since every earlier pin of it had the hub heard and the hub's gossip folding first. The two identity drops are pinned with hubs that carry a bus id, as every real bus does (the reviewer's verifier: every carried-hub fixture until then had none, so a carry reading a carried row's bus id alone as the hub heard under another name, and one dropping a carried via row on any hub's current word about the far bus, passed every pin): a carried hub's word about a host nobody holds stands while its bus is heard under no other name, whatever another host vouches, and a second hub's current word about the far bus drops no other hub's carried row. The gossip is never added to the direct row as a naming source: that would credit a source that did not vouch. The display and routing consumers keep their own fold. The one residual is disclosed as a bound, not closed by a timer: a direct row heard and not held down whose roster is older than the hub's gossip folds it, so a session started on that host since its last exchange is in no row for a window of one exchange interval of that host, closed by its next exchange; the population includes a heard row with no link state, a far bus under the hostname it declares before this bus's own dial has folded it, closed by that bus's next dial. The reader needed no new arm: the via key is a key, and the cannot-determine reasons name it like any source.

Round 3, the eleventh commit (the reviewer's ruling; the road found by its refuters through the real handler and writer): a heard host whose exchange served a cached roster vouches for presence alone. While a host's kernel listing does not answer (mid-restart), its presence producer serves the last answered rows into the exchange (the blink honesty of 2026-08-31, which upstream carries too), and until this commit that cache rode the exchange with no sign of it, so a session started on the host after that listing was in no roster while its mail rode the same exchange, and the host, heard with its link known up, vouched for absence: rule 5 presumed a live session closed.
