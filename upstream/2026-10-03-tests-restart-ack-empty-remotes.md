tests/test_kernel.py's ServeSecurity.test_restart_endpoint_acks_post sends a bodiless POST /restart with the real restart legs in place, and it assumed that the kernel module's remotes registry was empty. Every test module that loads the kernel as romp_kernel shares one module object, and some leave rows in that registry: tests/test_kernel_trust.py's pair-route round-trip test leaves an 'up' row. With a row there, the bodiless POST takes the broad leg: the handler acks and starts a real `_fleet_restart_run` thread, which runs ssh against an 'up' row's host (a synthetic name here, so it fails at name resolution), writes its report and then calls the module's `_restart_this_kernel` as it finds it at that moment. That moment falls inside a later ServeSecurity test that has replaced the local leg with a recorder, so test_restart_refuses_a_malformed_body_instead_of_restarting_everything recorded two local restarts where it expects one (test_restart_refuses_a_body_that_did_not_arrive_whole can catch the call instead). The fix is tests only. The ack test empties the registry for its run and puts back what it found through addCleanup. A new test, test_the_ack_test_owns_its_empty_remotes_premise, runs the ack test under a leftover 'up' row with both legs as recorders, and requires that the local leg ran, that no broad restart started and that the row is back afterwards. Tests only, so docs tier.

On the fork's main at 591436b2e, a serial run of 15 kernel modules in the order an earlier review recorded failed the malformed-body test in 3 of 3 runs, each time with the stray run's local restart recorded ahead of the test's own. tests/test_kernel_trust.py's pair-route test followed by the ack test and the three restart tests after it failed in 4 of 5 runs. The new test fails without the fix (the local leg never runs and the broad recorder fires), and it fails with a fix that empties the registry but does not restore it (the row is gone afterwards).

The population was measured at 591436b2e with two pytest plugins that stay out of the repo.
- Readers. Across the 110 modules that load the kernel as romp_kernel or mention /restart, one request reached the restart scope decision as broad on a handler thread with the real `_fleet_restart_run` in place, and it came from the ack test. The other in-process POST /restart tests (tests/test_manager_write_token.py, tests/test_restart_audit.py, tests/test_restart_port_at_ack.py) send a body that asks for this kernel only, so they never reach the broad leg, and the kernel starts `_fleet_restart_run` from that one handler branch only. With one sentinel row added to the shared module before every test of the 94 modules that load it under that name, the run's one failure was a restart test that ran after the ack test (test_restart_refuses_a_body_that_did_not_arrive_whole).
- Writers. In that run, 9 tests in three modules (tests/test_kernel_trust.py, tests/test_kernel_known_hosts.py, tests/test_kernel_remote_update.py) left rows they had added, and 38 more cleared the registry without restoring it. No other test reads an empty registry as a premise, so the writers are left as they are.

upstream/main (f4a572008) carries the same ack test, the same restart tests with recorder legs, the same pair-route test in tests/test_kernel_trust.py loading the kernel as romp_kernel, and the same handler branch. The leak reproduces there: tests/test_kernel_trust.py followed by tests/test_kernel.py::ServeSecurity failed the malformed-body test in 5 of 13 serial runs, with the same extra local restart. With this change applied to upstream/main, the same pair passed 10 of 10 runs, and the new test failed without the ack test's fix. upstream/main's local leg runs after the ack rather than before it; the new test waits on the local leg's event instead of reading it at the ack, so it holds there too. The diff applies to upstream/main as it stands.
