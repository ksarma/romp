The Bash-side track guard (a PreToolUse hook on the Bash tool) blocked a shell write to a tracked file only when the target path was literal in the command: a cp whose destination was a shell variable, a command substitution, a backtick, a ~user, a brace list past the cap, or a glob it could not expand went through and overwrote the tracked file with no change recorded, while the same command spelled out was refused (a research session reported it through the box admin, 2026-09-17). The hook now refuses such a target while a project that tracks anything is in play (the session cwd, the directory a cd moved to, or the folder a copy lands in has a .trackchanges/config.json whose tracked list holds an entry the literal rule could refuse), with a message that says the target is not literal, that a tracked file takes its change through track-edit, and to spell the path out or write outside the project; it reads no variable the command names to resolve the word (of the environment it reads HOME, for `~` and a leading `$HOME`, and the CLIs' root override, for a directory under it; only HOME's value can appear in a refusal, as a path resolved through it, and the override is named by its variable). The round-1 review (2026-09-18) bounded the rule: a target whose only expansions the running shell keeps unassignable (`$$` everywhere; `$RANDOM` and `$SECONDS` in bash and zsh, not inside a script handed to `sh`, where dash lets a script assign them; `$BASHPID` nowhere, since zsh lets a command assign it, both corrections from round 2 the same day, by execution) at an absolute path outside every project in play is allowed, the project the target's own prefix sits in asked first and a `..` that folds every expansion away still resolving the literal directory part (round 2 overwrote a tracked file through both gaps), a copy's landing folder counts only when a tracked file could land there or holds more than 2000 entries (a deliberate false refusal, escalated), a directory is judged under its real path and its name, and `install -d` writes no file; a `$(date)` in a log's name is still refused, a stated cost. Found on the way: a redirection onto several glob matches or brace alternatives was read as the ambiguous redirect bash refuses, but zsh (multios) writes each, so the hook now names each. Literal targets keep their verdicts; commands with no tracked project in play are untouched. Tests in tools/romp-track-bash-guard.test.mjs, the shapes module, the plan pins and the vendored skill patch 0009.
