The Bash-side track guard (a PreToolUse hook on the Bash tool) blocked a shell write to a tracked file only when the target path was literal in the command: a cp whose destination was a shell variable, a command substitution, a backtick, a ~user, a brace list past the cap, or a glob it could not expand went through and overwrote the tracked file with no change recorded, while the same command spelled out was refused (a research session reported it through the box admin, 2026-09-17). The hook now refuses such a target while a project that tracks anything is in play (the session cwd, the directory a cd moved to, or the folder a copy lands in has a .trackchanges/config.json whose tracked list holds an entry the literal rule could refuse), with a message that says the target is not literal, that a tracked file takes its change through track-edit, and to spell the path out or write outside the project; it reads no variable the command names to resolve the word (of the environment it reads HOME, for `~` and a leading `$HOME`, and the CLIs' root override, for a directory under it; only HOME's value can appear in a refusal, as a path resolved through it, and the override is named by its variable). The round-1 review (2026-09-18) bounded the rule and rounds 2 and 3 (2026-09-19) corrected it by execution: a target whose only expansions are `$$` or `${$}`, the shell's process id, at an absolute path outside every project in play is allowed, and nothing else is (round 1 listed `$RANDOM`, `$SECONDS` and `$BASHPID` as read-only; round 2 dropped BASHPID, which zsh leaves assignable; round 3 measured `unset RANDOM`, `local RANDOM=` and zsh's `typeset -h` carrying a path onto a tracked file, so a `log.$RANDOM` inside a tracked project is refused in every shell, a deliberate false refusal recoverable in one step); the project the target's own literal prefix sits in is asked first, from any cwd, for every target the hook cannot read that it can place, absolute or relative (round 3: a variable's spelling and a relative numeric one reached another project's tracked folder from a cwd in no project); a numeric target's literal directory part is resolved through the filesystem, an existing entry its number could spell is followed, a fold that leaves no expansion is judged by the literal rule, and a `..` after an existing directory climbs from that directory's real path for a literal path too (round 3 overwrote a tracked file through each of those); a copy's landing folder counts only when a tracked file could land there or holds more than 2000 entries (a deliberate false refusal, escalated; the same cap now covers a numeric name in such a folder), and a landing folder no project claims counts when an entry of it is or leads to a tracked file; a numeric name in any folder where a tracked file could land (`<root>/x-$$/y.md`, `<root>/docs/build-$$.log`) is refused from any cwd while its literal spelling may pass, the refusal naming the unknown folder when the expansion names one and offering a literal folder name or a write outside the project (round 2's addendum ruled the first-segment case; round 3 restated the class as the landing gate on the literal directory part, at any depth, and replaced a remedy that asked for the name the shell would give); a literal relative target after a `cd` the hook cannot follow (a name the shell fills in, `cd -`, `popd`, a cd inside an if or loop body, or one to a directory the command cannot enter at check time) is refused with that reason while the session's project is in play, where before it was dropped; `$'...'` is ANSI-C quoting in bash and zsh and a literal dollar is literal, so a folder or project whose name holds a dollar is judged by that name; `bash -O` and option clusters holding `o` or `O` take their word; a command nested past 64 substitutions or brace lists is marked opaque rather than overflowing the stack (evaluate read the overflow as allow); a directory is judged under its real path and its name, and `install -d` writes no file; a `$(date)` in a log's name is still refused, a stated cost, and so are a relative `$$` name from a cwd in a project and a `mkdir -p x && cd x && cmd > log` from a tracked cwd. Found on the way: a redirection onto several glob matches or brace alternatives was read as the ambiguous redirect bash refuses, but zsh (multios) writes each, so the hook now names each. Round 4 (2026-09-19, a walk-around lens run ahead) closed eight more in-model roads: cp/mv/install/ln read a per-writer option table taken from coreutils, so a flag that takes no argument (`-Z`, a bare `--context`) no longer eats an operand and an option the table does not know refuses the command naming it; `env -C DIR`, `env --chdir=DIR` and `sudo -D DIR` run the inner command in DIR (its relative operands judged there, the redirection in the shell's cwd), where before commandOf returned null and the whole segment was dropped; the wrapper set gained setsid, flock (its lockfile peeled, `-c 'cmd'` read like `sh -c`), taskset, chrt and numactl, each with operand-aware peeling; a same-command assignment to HOME (`HOME=…`, `export HOME=…`, `env HOME=… cmd`) makes `$HOME` and `~` unreadable for the rest of the command; a word whose literal head is a parent of one or more tracked roots is refused naming the projects beneath (the expansion could spell a root), and one whose literal head sits under a tracked root is refused unless every expansion is numeric (a `../` in the value can climb back into tracked files); a directory the hook cannot search or stat before a `..` (mode 000 at check time) is refused as unresolvable rather than folded lexically and read as allow; and a symlink an `ln -s` makes earlier in the same command redirects a later literal target to what it points at. The guard also states its contract on the hook header, the vendored skill, hooks/README.md and docs/install.md: it is best-effort against known write forms, its default on an unrecognised form is allow, and the unmodelled writers that still reach a tracked file are listed (rsync, awk with a redirect in its program, ed, ex, make, find -delete/-exec, a git tree write, a computed interpreter path, a leading opaque expansion from a cwd outside every project). The walk-around lens second pass (2026-09-19) then closed six families of in-model write, each as one rule: the option tables and sort's -o accept a glued short form (`sort -oFILE`), and env -S/--split-string is read as a shell string like flock -c; HOME as an lvalue in any form the shells offer (`HOME+=`, read HOME, printf -v HOME, export/declare/typeset/local/readonly HOME, mapfile HOME, getopts HOME, for HOME in) makes $HOME and ~ unreadable for the whole command; an earlier rm/rmdir/mv/hard ln/cp -l/cp -s that removes, renames or aliases a path makes a later word under that prefix unreadable, and the ln -s class-H rewrite is kept only when nothing else touched the link name or its source (a relative link source now resolves against the link's own directory); a stat, realpath, readdir or config-read error other than ENOENT anywhere on a judged path (a mode-000 folder, .trackchanges or project) refuses from any cwd, the class-G flip applied to the class, its false-refusal cost recoverable in one step; a .git, .obsidian or .trackchanges nested between a tracked root and the file refuses naming both markers, the nearest-marker rule kept for the untracked case; and a cd the guard cannot know ran in this shell (after &&/||, in a pipeline, backgrounded, under a wrapper, pushd -n or a rotate, a physical cd -P or set -P, or a call of a function whose body cd'd) leaves the directory unknown, so a later literal relative target refuses with the construct named, while env -C resolves its operand physically. The single true statement on same-command symlinks is now everywhere: an ln -s with literal operands the hook can place, and an untouched name, is resolved; every other same-command link or mutation refuses. The walk-around lens third pass (2026-09-19) re-keyed six of those rules on what the guard can see, after a third attack walked around each enumeration with the next spelling (a nameref and `select HOME in`; a glued `env -Cdocs`, an abbreviated `env --chd=`, a nested `env -C`, an `env -S` string beginning with env's own option; a non-literal `ln -s` source; zsh's `set -o chaselinks`; a two-segment expansion under a grandparent; `cp --targ` from a cwd in no project): (a) the bare identifier HOME anywhere in the command outside a `$`-expansion makes `~` and `$HOME` unreadable and a bare `cd` or `cd ~` unknown (bareExpandedNames), no list of assignment forms; (b) every wrapper in PREFIXES is parsed in full against its own option table (WRAPPER_OPT) or the command refuses naming the option, a nested chdir composes, `env -S`/`--split-string` and sudo's -e/-i/-s/-R/-h are refused outright as opaque, and `time -o FILE` is a write; (c) a symbolic link whose source the guard cannot read or place marks the link name as mutated, so a later write through it refuses (recordSymlink); (d) a `set`, `shopt`, `setopt` or `unsetopt` option not on the inert allowlist (built from the shells' own option lists: exit status, tracing, history, completion, prompts, job control; nothing about cd, physical paths, links, globbing, brace expansion, aliases, quoting or POSIX mode) leaves the directory unknown (shellOptionChange); (e) the parent-prefix rule finds every tracked root under the literal head at any depth, breadth-first within a budget (parentTrackedRoots); (f) an option a writer's table does not know refuses on every path the writer is reached through, its candidate operands judged by their own project from any cwd and marked by the mutation recorders (optionCandidates); also `chdir` leaves the directory unknown and coreutils `link` is a hard-link maker. Every list left in the hook is audited in its header for the side its gap falls on (a missing wrapper in PREFIXES is a write, stated on the four surfaces; every option and inert table a false refusal). The cost is measured against tools/romp-track-bash-guard-corpus.json, 164 ordinary developer commands and the 22 recorded false refusals run at the head before the pass and at this one: no ordinary command newly refuses; the refusals added are a `~/` write beside a mention of HOME, an `env -S` line, a relative write after `shopt -s globstar`, a write through a link whose source is a variable, and a variable-named file in a folder with a tracked project anywhere beneath it, each pinned with its remedy. The contract paragraph is identical on the hook header, the vendored skill, hooks/README.md and docs/install.md, its allow-by-default sentence and its refused-class sentence included, and its writer list names the out-of-model roads the passes found (a sourced or eval'd script, a wrapper outside the set, shuf -o, a cd through CDPATH). Literal targets keep their verdicts; commands with no tracked project in play are untouched. Tests in tools/romp-track-bash-guard.test.mjs (with the corpus), the shapes module, the plan pins, the drift test's title rule and the vendored skill patch 0009.
