Upstream c017b510 changed the kernel pane shim to hand frames to the bundle from a MessageChannel flush task (one FIFO per socket, FLUSH_MS=8 slices, a newer whole-state frame replacing an older queued one) instead of inside `ws.onmessage`, so on that shim the bench's onmessage window held only the shim's parse (measured 2.3 ms inside the window and 333 ms outside; the per-window profile tables empty) and its replay test failed at `wrapperSamplesInHandlers >= 0.9`. The bench now wraps `window.__rompFed.inbound` with a timed dispatch hook (start, duration, type, whether a socket handler was on the stack, the handler ordinal `n`, and on the deferred shim a settle stamp two animation frames after the handoff), counts and times the flush tasks through `MessagePort.prototype`'s onmessage setter, matches each inbound call to its frame in node by handler order (candidates are the unmatched frames of the dispatch's type with index below `n`; a whole-state type takes the latest and marks the rest coalesced, a chained type the earliest; the clock is the fallback for records without `n`, because `performance.now()` is coarsened to 0.1 ms in a page that is not cross-origin isolated and two consecutive reads can be equal), reports dispatch beside handler per type with an inline/deferred/coalesced/unmatched/flush-task block, takes a frame's settle as the later of its handler's and its handoff's stamp, and sizes each profile window to the union of the frame's handler and dispatch spans, preferring per type the largest frame that reached the bundle. Rides the same offer as the `ui-bench-tool` entry (romp-on/romp#1057, dev-bench); the hunks apply whether or not c017b510 is in the target tree.

Verified on both trees with the synthesized 40-card streams replayed back-to-back (`--fast`, one iteration, headless Chromium): on the inline shim (fork main 56f58d92) the feed stream reports 25 handoffs inside the socket handler, 0 deferred, 0 coalesced, 0 unmatched, 0 flush tasks, `wrapperSamplesInHandlers` 0.99, the first content frame window handler 50.1 ms / dispatch 49.7 ms / 50.1 ms of window / 87 samples; the timeline stream 29 inline, 0 coalesced, 0.986. On the deferred shim (upstream c017b510, tree 7adbdae1) the feed stream reports 0 inline, 25 from flush tasks, 0 coalesced, 0 unmatched, 9 flush tasks (118.9 ms), 0.99, first content frame handler 0.4 ms / dispatch 50.3 ms / 50.7 ms of window / 89 samples; the timeline stream 0 inline, 3 deferred, 26 coalesced (the full `bars` frame and 23 of the 24 deltas replaced in the queue before a flush), 3 flush tasks, 0.983, and the `largest delta:bars` window holds the 23.4 ms bars render (40 samples). On every run no frame's settle stamp precedes its own handoff. The replay tests pass on both trees on all cores and pinned to one core.
