Every served driver (a node program that a module in CI's served-pages job runs) now hands its record to pytest through one shared helper, tests/lab_result.cjs, and one shared reader, tests/lab_result.py, and a source census refuses any other write to a driver's stdout. Before this change each driver printed its record whole on stdout and each module parsed that line its own way, so the record reached pytest through one write to a pipe. Loading playwright leaves the driver's stdout non-blocking, and one fs.writeSync to a pipe puts in what the pipe has room for and loses the rest without a throw: up to 64 KiB, and 8 KiB on a loaded machine (a user past fs.pipe-user-pages-soft gets minimum-size pipes, pipe(7)). On the fork's main as it stood before this change (measured 2026-10-05), with every node's stdout an 8 KiB pipe, records cut at 8 KiB failed tests in tests/test_tab_groups_rows_served.py, tests/test_files_pane_toggle_served.py, tests/test_day_divider_served.py, tests/test_feed_focus_served.py and tests/test_reply_sheet_served.py, and in tests/test_scroll_marks_click_served.py in one of two runs. How big a record grows depends on the tree, so the fix is a rule over every writer, which also covers the drivers whose records are small today.

writeResult(cfg, record) writes the record and the drive's nonce to the file the Python side names (a temp file renamed onto the path, so the path holds a whole file or none), then prints one short RESULT: line naming the file and the nonce, with the died reason or a write error when there is one. The line goes out through a writer that resumes partial writes and waits out EAGAIN, so a full or non-blocking pipe delays the line and never cuts it. writeLine prints a progress line such as KPID:<pid> and refuses the RESULT tag; targetFromEnv serves drivers that take no cfg. On the Python side, target(lab, name) mints a drive's target (the file, a fresh nonce, the helper's path), and read(p, target) returns the record or raises an AssertionError that carries both streams' tails. read refuses no line or two, a line or a file that is not JSON, a reported write error, a line naming another file, a missing file, and a nonce on the line or in the file that differs from the one it minted. The nonce keeps a file an earlier drive left at the same path from passing; the two modules that delete their result file before a drive keep the delete.

Every served driver moved onto the helper, whatever its record's size and whether it printed the record with fs.writeSync, process.stdout.write or console.log or wrote a file of its own with no nonce: 140 browser drivers in 110 modules, the 7 driver files under tests/, and the drivers that print a record without a browser (the update banner's harness, the linkdrop parse helper). Each module reads its record with lab_result.read. The companion tests that stub a driver (tests/test_federated_linkdrop_driver_bound.py, tests/test_tool_rows_vocab_shots_root.py) write the helper's file and RESULT line, tests/test_federated_linkdrop_mint.py admits secrets (the reader mints the nonce with it), and tests/test_hermetic_kernel_postal.py's direct-import allowlist holds lab_result.

tests/test_lab_result_census.py enforces the rule over every module CI's served step runs and every driver file those modules name. It refuses a direct write to stdout in any of nine spellings (its docstring lists them, with the cases it cannot see), requires every browser driver and driver file to call writeResult and every module that runs node to hand a record through the helper, and refuses a module that parses a driver's stream itself. Its exceptions carry structural reasons, never sizes: the browser-install probe, which prints one executable path and no record; the helper's own pipe pins; a parse sample that node never runs; and one module whose own node runs hand no record. tests/test_lab_result_pipe_served.py shows the failure in CI's served job: through an 8 KiB non-blocking pipe, a 96 KiB record written by the helper comes back whole, and the old single fs.writeSync leaves exactly 8192 bytes.

upstream/main (read 2026-10-06; its last commit is of 2026-09-24) has neither tests/lab_result.cjs nor tests/lab_result.py. Its CI's served step names 132 modules, and the census run over that tree refuses 162 direct stdout writes in 116 of them and in its 3 driver files. 113 of the 140 tests/ files this change edits exist there, and 21 of upstream's served modules do not exist on the fork, so an offer would convert those 21 too. Record sizes on upstream were not measured.
