Fourteen drivers that served-page tests run printed their whole record on one RESULT: line with a single fs.writeSync to stdout. Loading playwright leaves that stdout non-blocking, so the write puts into the pipe what it has room for and the rest is lost: up to 64 KiB, and 8 KiB on a loaded machine (a user past fs.pipe-user-pages-soft gets minimum-size pipes). Each of these records ran past 8 KiB in a measured run, from 8724 bytes (tests/test_unfocused_pane_browser.py) to 46528 (tests/keyboard_gap_browser.mjs), and with each node's stdout pipe set to 8 KiB their tests failed (tests/test_scroll_marks_click_served.py in one of two runs) on a JSONDecodeError of a line cut at its 8192nd byte. Each driver now writes its full record to cfg.resultPath and prints a short RESULT: line naming the file, with the died reason where the driver has one; the Python side passes resultPath in the driver's cfg, reads the file, and fails loudly when the line names another file, reports a write error, or the file is missing. Where a module can drive twice into one result file (tests/test_tab_groups_rows_served.py drives "inline" in two tests; tests/test_tag_chips_everywhere_browser.py drives again for the next test after a failed drive), _drive deletes the file first, so a drive that writes none fails instead of passing on the earlier drive's record. On upstream/main the tag chips module drives again after a failed drive the same way, and the tab groups module drives "inline" once.

The population was measured on the fork's main on 2026-10-05: every module CI's served-pages job runs, with a node preload outside the repo recording the size of each write a node process made to its stdout. These 14 are every single-writeSync record past 8 KiB there; the largest left are 7954 and 7790 bytes. Records printed through process.stdout.write or console.log were left, since no process exited with stream bytes still pending.

upstream/main (read 2026-10-05) carries 12 of these modules with the same single fs.writeSync of the whole record: tests/test_api_health_hover_browser.py, tests/test_chat_split_served.py, tests/test_day_divider_served.py, tests/test_feed_focus_served.py, tests/test_file_preview_browser.py, tests/test_files_pane_toggle_served.py, tests/test_rail_relative_served.py, tests/test_scroll_marks_click_served.py, tests/test_tab_groups_rows_served.py, tests/test_tab_overview_mode_served.py, tests/test_tag_chips_everywhere_browser.py and tests/test_unfocused_pane_browser.py. The two driver files, tests/keyboard_gap_browser.mjs and tests/reply_sheet_browser.mjs, and their modules are not there. Those twelve files differ from the fork's in other places, and their record sizes on upstream were not measured.
