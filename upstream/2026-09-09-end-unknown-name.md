`_sid_of` hands back its input unchanged when nothing matches, so a typo reached the backends as a phantom sid: /end killed it and `_confirmed_ended`, finding nothing listed, certified the death, so `romp end <typo>` printed a bare ok while the real session ran on; /send handed the phantom to the tmux backend and folded its refusal into ok:true. A peer handoff flow that trusted the ok had to re-check the roster. The gate admits a sid through three doors, each a record the kernel wrote for a session it registered: the names registry, the live map, and the SDK registry's threadOf entry (a comment thread, which the fork-comment door's registered-or-live check refuses); it is asked after the remote forward, and a far kernel's non-200 is relayed with its status: its JSON error with the far host named, else the status and the body's first line. A thread's deferred end (`romp end self` from inside one) is served by the end-on-idle sweep, which reads the thread's reg as the owner's answer and its own transcript for the settle. The CLI used to swallow every 4xx into "kernel not reachable", and `romp end --help` POSTed a session named --help.
