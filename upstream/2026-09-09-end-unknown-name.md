`_sid_of` hands back its input unchanged when nothing matches, so a typo reached the backends as a phantom sid: /end killed it and `_confirmed_ended`, finding nothing listed, certified the death, so `romp end <typo>` printed a bare ok while the real session ran on; /send handed the phantom to the tmux backend and folded its refusal into ok:true. A peer handoff flow that trusted the ok had to re-check the roster. One gate answers for both client doors, the WS drive gate and the HTTP control routes (`_session_gate`, asked through `_unknown_session_refusal` by `_control_target`, the routes' one resolution): a session the SDK backend reports running is admitted whatever its record reads; a session whose SDK registry entry exists but will not read and that backend is not running is a 503 naming the file and the way out, in every tmux state and whatever the registry cache holds, never a 404 and never a promise to try again, at the HTTP door and as the dashboard's modal alike (a comment threads' store that will not read is a 503 too, and so is a live scan the tmux probe did not answer, ahead of any forward); else the kernel knows the sid (`_kernel_knows`: the names registry, the SDK registry via `owns()`, which admits a comment thread since a thread has no names entry and the live map hides it, and the live map) or answers 404. The roster is consulted by sid before the gate and by name after a would-be 404 (`_remote_session_named`: the composed host:name match, so hosts may carry colons; only a host's live sids, so an away host's stale names route nowhere; same-named sessions on one host refused by id), and a far kernel's non-200 is relayed with its status: its JSON error with the far host named, else the status and the body's first line. A send to a tmux-backed session no pane runs is refused before the paste, as the SDK refusal is. A thread's deferred end (`romp end self` from inside one) is served by the end-on-idle sweep, which reads the thread's reg as the owner's answer and its own transcript for the settle, and ends a thread whose turn a restart cut when nothing runs or resumes it. The CLI used to swallow every 4xx into "kernel not reachable", and `romp end --help` POSTed a session named --help.
