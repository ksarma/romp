Upstream ships the same unit, the same manager `startTmuxServer` and the same SDK spawn, so it ports as-is. Linux/systemd only by construction; macOS/launchd is unchanged (the kernel answers "not Linux" before looking for systemd-run), and a terminal-run manager (`romp up`, no `ROMP_SUPERVISED`) scopes nothing — neither session CLIs nor the tmux server — unless `ROMP_CLI_SCOPE=1`. Found when a service restart on 2026-09-05 killed sessions' tmux servers and setsid jobs along with the kernel; only kernel-only restarts (`romp refresh`) had left them running. Offer WITH the reaper row below (or after it): the scopes remove the cgroup kill that had been killing what the ppid-1 reaper missed. The wrapper runs probes (no `ROMP_SID` — the SDK's per-connect `claude -v` check, which inherits the kernel's environment) unscoped, and falls back to a direct exec with one stderr line when a pre-flight scope fails; unit names carry pid and start time. Known follow-up, not built: a postal bus autostarted from a session's MCP server (`postal/postal_service.py`, `ensure()` from `mcp()`) now starts inside that session's scope. It outlives a service restart, and it keeps the scope loaded after the session ends: a scope stays loaded while any process in it lives, and nothing stops a scope, so the dead session's `romp-session-*` unit stays listed until the bus itself exits.
