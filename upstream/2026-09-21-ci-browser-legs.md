Upstream's vscode-extension job has the same ordering (npm test before the Chromium install), so its browser legs skip in its gating job too. An offer carries the step, the script, the reporter, the tree test and the CONTRIBUTING paragraphs; the roster is re-derived against upstream's own browser legs (13 test sources import playwright there; upstream has no ui/webview/real-viewer-leg.ts and no vscode-extension/scripts/ directory), and the launcher rule needs the shared helper (PR #860's entry) landed there first. The roster rule is checked by the PR's reviewer, not by CI, and the step reads four cases green: a rostered leg that launches its own browser and swallows a failed launch without skipping, a rostered module that launches nothing, a leg that drives a browser from a child process and tolerates the child's failure, and a todo test that passes beside a real pass. The PR no longer claims that every browser leg in the tree is rostered or excluded, and main has no such check. The census that made that claim (a parse of every test module with the TypeScript compiler, an exclusions file with a reason per line, and planted forms with their tests) left the PR by the review's round 7 ruling and is kept on the fork's branch ci-browser-legs-census, the corpus for a follow-up that starts with a design note.
