Split out of the follower fix (fork PR #787) by the reviewer's round 2 ruling (fresh-5, 2026-09-19), stacked on it and landing after it. A per-session Billing pick writes sdk-defaults.json's auth with no authExplicit; the launch (_explicit_default) and the per-init check (_declared_auth) read that file's auth only beside the flag, but the spawn's seed (SdkBackend.spawn) and the new-session picker's preselection (_auth_avail) read the flag-less value as the remembered default, so one pick on one session preselected the picker and seeded every later pick-less spawn with a pick of its own; changing one reader alone would have left the picker and the spawn disagreeing. Both readers now follow the file's auth only beside authExplicit, the launch's rule: a session created with no pick of its own follows the machine default (the explicit one, else the helper rule: the key when an apiKeyHelper is configured, else the login) wherever it moves, the picker preselects that same default, and a session created while an explicit default stands is seeded with it as a pick of its own. The set-aside problem rows (_note_seed_skipped) name the machine's default billing and the Set default billing submenu as the remedy, no longer a pick on a session, which seeds nothing now; the reference states the new semantics and no longer promises that the last per-session pick seeds the default. The two hunks move together: a split carrying one would leave the seed and the preselection disagreeing. Blast radius, by execution at 934aa3cbf and 04b7b0590 (the reviewer's executors over three harnesses and the fork's own, 2026-09-19), every billed account read from the launch payload (which token rides, whether the helper is suppressed, reg.auth), never from the status side word alone: a flag-less LOGIN pick, the machine's own (auth login) or a stored one (auth login with authLogin, what set_auth writes for "login:<id>"), flips what a new session bills, to the key when an apiKeyHelper is configured and, for a stored login, to the machine's own login when none is, or to no credential of romp's at all when no login is signed in either; a flag-less KEY pick keeps the bill and makes the new session a follower of the machine default, so a later move of the default reaches it; the discriminator is the helper, read through key_available after effective_auth falls through the empty explicit default. The picker's preselection (_auth_avail's default) moves in the same cells (a plain login pick with a helper; a stored-login pick with or without one), and a picker-created session carries the preselection as a pick of its own (render.ts sends the Billing row's selection as the create's auth). Where the account moves, or the remembered pick names a side the box cannot bill, the spawn now says so (round 1 of the review, 2026-09-19): a problem row on the new session (kind auth.pick-not-seeded), the kernel-log line and the ring entry keyed by the pick, naming the pick, what the session bills and the Set default billing submenu; before this round the seed skipped the pick with no word, and the retired seed's once-per-process row for an unbillable remembered pick had left with it. Every billed-account label above is the (settings file, environment) pair mapped through the CLI's credential precedence as last verified against CLI 2.1.257; the boxes run 2.1.278, where that mapping is being re-verified.

Tier: feature is the reviewer's recommendation (2026-09-19; the round-1 rulings set aside the earlier fix framing, whose premise the round found false: an explicit machine default has always been respected by new sessions, so this changes behaviour rather than restoring documented behaviour), because a change that can move the account new sessions bill without a gesture of the user's must not merge on green unseen; the ruling is the user's. Neither of the user's machines is in a moving cell as read on 2026-09-19: one carries an explicit login default, which the seed's new conjunct reads, so nothing moves there; the other remembers no pick, and with a helper configured and no machine login can reach only a key pick, which moves no bill. The exposure is the project's users, for whom a flag-less login pick with a helper is the ordinary path. Kernel-side, live at the next kernel restart of the box that serves the sessions. An offer waits on the user's word.
