Split out of the follower fix (fork PR #787) by the reviewer's round 2 ruling (fresh-5, 2026-09-19), stacked on it and landing after it. A per-session Billing pick writes sdk-defaults.json's auth with no authExplicit; the launch (_explicit_default) and the per-init check (_declared_auth) read that file's auth only beside the flag, but the spawn's seed (SdkBackend.spawn) and the new-session picker's preselection (_auth_avail) read the flag-less value as the remembered default, so one pick on one session made every later pick-less spawn carry that pick as its own and preselected it in the picker, and a session created from the picker billed a different side from one created any other way. Both readers now follow the file's auth only beside authExplicit, the launch's rule: a session created with no pick of its own follows the machine default (the explicit one, else the helper rule: the key when an apiKeyHelper is configured, else the login) wherever it moves, the picker preselects that same default, and a session created while an explicit default stands is seeded with it as a pick of its own. The set-aside problem rows (_note_seed_skipped) name the machine's default billing and the Set default billing submenu as the remedy, no longer a pick on a session, which seeds nothing now; the reference states the new semantics and no longer promises that the last per-session pick seeds the default. The two hunks move together: a split carrying one would leave the seed and the preselection disagreeing. Blast radius, as the refuter scoped it by execution: only a remembered flag-less login pick on a box whose settings carry an apiKeyHelper flips the account a new session bills (from the login to the key, until an explicit default is set); a remembered flag-less key pick, or a remembered login pick on a box with no helper, changes only followership and the badge, not the bill.

The tier is the user's call between feature and major-feature, filed as feature until he rules: the change removes documented behaviour (the reference's sentence that the last per-session pick seeds the default until one is set) and changes which account new sessions bill on a box in the flipping state, which reads closer to major-feature; the reviewer would not pick feature by default. Neither of the user's machines was in the flipping state when the change was made (2026-09-18: one default explicit, the other remembering no pick). Kernel-side, live at the next kernel restart of the box that serves the sessions. An offer waits on the user's word.
