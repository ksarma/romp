Upstream's two markdown sanitizers (render.ts `md()` / `userMd()` and file-view.ts `mdBlock`) run DOMPurify's default html+svg profile, which keeps `<style>`, the `style` attribute, `id` and `name`, forms and image maps: a note's `<style>` block blanked the Files page, a `position: fixed` div in a note covered the viewer's close button, a `<form action>` with a button navigated the pane's document away, an author's id could collide with the viewer's own, and a `<td background=URL>` fetched the URL on open. Both callers now go through one `sanitizeMd` (md-sanitize.ts, the dashboard's only `DOMPurify.sanitize` call): the form-associated elements, `dialog`, `style`, `map` and `area` are forbidden and `background` and `usemap` dropped; an `input` survives only as a disabled checkbox; ids and names are kept under GitHub's `user-content-` prefix; an `uponSanitizeAttribute` hook keeps only literal-colour `color` and `background-color` declarations in `style` (plan decision 6, so coloured spans in existing notes survive); `.fileview-md` takes `contain: layout` and caps a note's own svg, canvas and video at the column; each viewer installs one `submit` preventDefault. Three fixes rode along. KaTeX renders after the sanitizer into inert placeholders (its layout lives in inline `style`, which the colour rule would strip) and under bounds upstream's tree lacks, since `katex.render` is synchronous on the main thread: one formula's length and one message's total in characters of TeX, KaTeX's `maxSize` (a `\rule{5000em}{5000em}` laid a 78,650 px square in the transcript) and a `maxExpand` computed from the formula's macro bodies (a 1,409-character `\def` bomb was 20 s of render), with a macro that repeats an argument or is defined with `\edef` or `\xdef` (KaTeX stores those expanded, so no count over the bodies as written bounds them: 1,635 characters of TeX was 31 s) shown as source before KaTeX sees it; a formula over a bound is shown as its source, dressed as unrendered source, in the user's bubble too. The chat delegate and `mdBlock` key on every link element (`LINK_SEL` is `a[*|href], area[href]`; `linkHref` reads `xlink:href` too, and `mdBlock` moves an SVG anchor's `xlink:href` to `href` so a stamp that removes `href` leaves the browser nothing to follow), because an SVG anchor or an area navigated the document in the same frame. The chat delegate resolves a message's scheme-less href (`//host`, `/\host`, a control character before `https:`; all pass upstream's DOMPurify and fail its scheme test) the way the default action would and opens it as it opens an absolute one, instead of letting it navigate the chat document, while the page's own `<a download>` controls and a message's same-origin download link keep the browser's download; a reply's own `#fn1` links land on their prefixed target through `userContentTarget`; both arms read a message body's link only, the comment popover's agent reply (`div.cmt-msg.agent`, the one `md()` body without `.md`) included.

Not yet offered. The offer stacks on fork PR #347 (2026-09-07-file-viewer-links, a candidate) or ports around it. Three pieces are #347's: `fragmentTarget` in file-view-links.ts, a file upstream does not ship (its `userContentTarget` arm lets `[go](#top)` land on the author's prefixed element); `mdBlock`'s post-sanitize split, where a URL document's links get the `LINK_SEL` passes and a file document's go through #347's `linkMarkdownAnchors`; and the chat delegate's `draggable` and `selectionOpenIn` guard on the same anchor. A port without #347 applies `LINK_SEL`, `linkHref` and the `setAttribute` stamps to upstream's own two `a[href]` passes in `mdBlock` and drops the `fragmentTarget` arm, which regresses nothing there: upstream's `scrollToFragment` reads only the viewer's `md-<slug>` heading ids, minted after the sanitize and never prefixed, so an author's id was never a link target on that tree. The fork-only pins (file-view-links, file-view-links-browser, file-view-seam, file-view-text-size, pr-links) stay behind; the eight upstream test files named above carry the source pins and travel with the change.
