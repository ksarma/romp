The kernel writes each hosted session's launch spec to hosts/<sid>/spawn.json, env overlay included, and the pull-in's writer moved only the three login names (AUTH_ENV_NAMES) out of it to the host's process environment; a credential-shaped variable of any other name a compose put in options.env reached the file (the box admin's hazard review of the pull-in, 2026-09-16), against the fork's rule that no credential is ever written to a file. split_spawn_secrets now moves every name of spawn_env_secret_names' shape: the three login names whatever their value, and every name env_credential_names flags over the overlay itself, a non-empty value under a name ending _API_KEY or _TOKEN, in any letter case, or one of 1Password's names. The helper sits beside the rule the boot notice already used, so the file and the notice agree on what a credential looks like; the case fold went into that shared rule in review round 1 (the suffixes were compared exactly, so notes_api_token was neither moved nor named), so the boot line names lowercase and mixed-case spellings too and its printed copy says so. A non-string value in the overlay is coerced to text for the name decision only (_overlay_text), so the split neither raises on one nor leaves a credential-shaped name in the file over its value's type; a non-string value under a plain name stays in the file as before, a pre-existing state named in split_spawn_secrets' docstring and not changed here. The moved names take the login token's road, the host's environment, with the overlay's precedence kept, so the session launches with them and only the file is clean; the spawn logs the names moved beyond the three, never a value. Tests: the unit split and the case fold (tests/test_session_host.py and tests/test_env_credential_names.py, where the boot line's copy is pinned too), the real _host_transport_for spawn road over a stub kernel (the value is in no file under hosts/), and a real host launched from the kernel's own split, red on the base tree on the spec's contents and the absence of the value under hosts/ (the CLI probe seeing the name is true on both trees, so it is not the discriminating leg). The kernel side goes live at the next kernel restart; an offer waits on the user's word.
