A feature in code upstream ships too (the kernel's shell page, the retry-pause file, the api_retry storm state). It builds on the API-health signal candidate (2026-09-02-api-health-signal, approved, not yet merged upstream): tests/test_api_health_rail.py pins _apih_class against sdk_backend.api_health_status_class, docs/reference.md files the indicator's subsection under 'The API-health signal', and the kernel comments name that machinery. Offer it after that entry or stacked on it; a port on its own would have to drop the twin test and re-anchor the subsection. Every field of the frame moves on one named event (a retry frame, an isApiErrorMessage record, fresh assistant output, a pause set or lifted, a session leaving the roster) and never on a clock; two computes over the same world at different times serialize identically and send once. Behavior changes outside the cell, each a lift rule keyed on the event that engaged its pause (review round 2): _auto_pause_on_limit records reason limit at the pause event, and a limit pause lifts when the usage report stops naming an account-wide window (_account_limited, the same filter the engage reads; the mtime rule let a key-billed session's output, or a prompt, flip the pause file every cycle, and a lift keyed on a login session's output could never fire after the reset, since the blocked login sessions are the ones the pause gates); a spend pause records the capped session's billing and lifts on fresh assistant output from that billing only (the mtime rule let a session on the other account flip it every cycle); the shell socket carries the dashboard's wid, so a session opened from the detail moves that dashboard's chat alone. The frame carries seq, the pause file's write count, so the frame that answers a pause press differs from every frame before it. Review round 3: a spend cap is on-you, so the capped session's record outlives the lift (romp sends it no retry; only a human prompt clears it), and the engage re-engaged on it the cycle after every lift, alternating at the streaming session's output cadence and settling on once it idled. Un-pausing a spend pause now records liftedAt and the floor it superseded in the pause file, the memory rides every later write, and the spend engage skips records older than liftedAt; a new record engages again. The detail clears a pause acknowledgment when the shell socket closes (the redial's ready re-sends the last frame verbatim, so nothing else would), and moves focus to the card before disabling the pressed button (a disabled element cannot hold focus, and from the body a Shift+Tab left the aria-modal dialog). Deferred: the VS Code strip twin and the phone's Usage-modal section.
