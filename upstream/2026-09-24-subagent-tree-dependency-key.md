romp-on/romp PR #1822 holds each subagents tree once per pusher cycle: the first reader of a root samples it, and when the sample lists a tree, every later reader in the cycle is served that sample, the (directories, stats) pair. The agent-file walk's miss path (_subagent_file_walk) notes each sibling session's root for the running chat build under a fresh stat, then looks the tree up through that held pair; when an earlier reader in the cycle took the sample, that stat is taken after the sample's read: upstream main 45b0720b0, kernel/kernel.py:32708, `_chat_dep_note_taskout(str(sd), _chat_stat_key(str(sd)))`. When an agent file lands under a sibling tree after the cycle's sample, the lookup answers None from the held listing, and the key recorded for the root is the stat taken after the landing, which every later re-stat equals. The tab that shows the file missing is then not rebuilt until something else rebuilds it. The note also records the root alone, which a file landing under a listed child such as workflows/ does not move.

The fix, in _subagent_file_walk: each tree the walk looks through, its own and each sibling's, is read once; that read answers the lookup (_find_agent_file takes the pair through a new `tree` argument), and the walk's dependency note, when it takes one, comes from the same read. The note records every directory of the tree under the (st_mtime, st_size) of the stat the read took, never a stat taken after it (_subagent_tree_dep_note; _subagent_meta_map now calls it too, and its notes are unchanged). A path that holds no tree (a live link, a file or a dangling link) is never listed, and the walk still notes it under the path's stat key as before, or None when an lstat taken after that stat shows the path changed since the read (_subagent_walk_dep_note). On a miss the walk notes each tree its project listing reaches, the own tree only when the listing reaches the session's directory; in a chat build _stamp_agents calls _subagent_meta_map on the same path before the lookup, and that call notes the own tree from the pair its own _subagent_tree call answered (every directory of a tree; None when nothing or a dangling link is there).

The pins, in tests/test_subagent_tree_cycle_scope.py; the module docstring's numbered rules and each class's docstring state the rules in full. DependencyKeyFromTheHeldRead's cases, among them: a held sibling root, whose recorded key must be the held stat's pair and not the re-stat after the landing; a held sibling tree's workflows/, whose recorded key must be its held pair; the same on the walk's own tree; and a control, the same sequence with no scope open, which finds the file. The held-tree cases are red at the fork's merge of romp-on/romp PR #1822 before the fix and green with it. WalkNoteForAPathThatHoldsNoTree pins the walk's note for a subagents path that holds no tree; its cases, among them: a live link and a file one at a time, on a sibling's path and on the own path, each noted under the path's stat key and each then swapped for a tree, which moves the key; a dangling link, noted None; the one-path sequence of a live link, a file and a dangling link, on a sibling's path and on the own path, each swapped for a tree before the next cycle, after which the tab must rebuild; an absent path whose fsid directory exists, on both paths, noted None from the read, after which a tree appearing must rebuild the tab; and a tree placed at the path right after the note's identity lstat, on both paths, whose recorded key must differ from the re-stat. The read-then-replace cases, a link replaced by a tree between the read and the note at a sibling's path and at the own path, pin the None noted when the path changed after the read: each is red with the identity check removed, on the recorded key equal to the re-stat.

Upstream: _subagent_file_walk, _find_agent_file, _subagent_meta_map, _subagent_tree and _subagent_tree_sample are byte-identical between upstream main 45b0720b0 and the fork's merge of romp-on/romp PR #1822, and the helpers the fix calls (_chat_stat_key, _chat_dep_note_taskout, _stat_ident, _lstat_or_none) exist there. _subagent_file differs between the two trees, and the fix changes only its docstring. The fix was not run on upstream's tree.
