romp-on/romp PR #1822 holds each subagents tree once per pusher cycle: the first reader of a root samples it, and when the sample lists a tree, every later reader in the cycle is served that sample, the (directories, stats) pair. The agent-file walk's miss path (_subagent_file_walk) looks up each sibling session's tree through that held pair, then notes the sibling root for the running chat build under a fresh stat taken after it: upstream main 45b0720b0, kernel/kernel.py:32708, `_chat_dep_note_taskout(str(sd), _chat_stat_key(str(sd)))`. When an agent file lands under a sibling tree after the cycle's sample, the lookup answers None from the held listing, and the key recorded for the root is the stat taken after the landing, which every later re-stat equals. The tab that shows the file missing is then not rebuilt until something else rebuilds it. The note also records the root alone, which a file landing under a listed child such as workflows/ does not move.

The fix, in _subagent_file_walk: each tree the walk looks through, its own and each sibling's, is read once, and that one read answers both the lookup (_find_agent_file takes the pair through a new `tree` argument) and the dependency note. The note records every directory of the tree under the (st_mtime, st_size) of the stat the read took, never a stat taken after it (_subagent_tree_dep_note; _subagent_meta_map now calls it too, and its notes are unchanged). A path that holds no tree (a live link, a file or a dangling link) is never listed, and the walk still notes it under the path's stat key as before, or None when an lstat taken after that stat shows the path changed since the read (_subagent_walk_dep_note).

The pins, in tests/test_subagent_tree_cycle_scope.py. DependencyKeyFromTheHeldRead has four cases: a held sibling root, whose recorded key must be the held stat's pair and not the re-stat after the landing; a held sibling tree's workflows/, whose recorded key must be its held pair; the same on the walk's own tree; and a control, the same sequence with no scope open, which finds the file. The first three are red at the fork's merge of romp-on/romp PR #1822 before the fix and green with it. WalkNoteForAPathThatHoldsNoTree has six: a live link or a file at a sibling's or the own subagents path, each noted under the path's stat key, which a tree replacing it moves; a dangling link, noted None; and a link replaced by a tree between the read and the note. These six are green before the fix and with it; they hold the walk's earlier notes for paths that hold no tree, which a first version of the fix dropped.

Upstream: _subagent_file_walk, _find_agent_file, _subagent_meta_map, _subagent_tree and _subagent_tree_sample are byte-identical between upstream main 45b0720b0 and the fork's merge of romp-on/romp PR #1822, and the helpers the fix calls (_chat_stat_key, _chat_dep_note_taskout, _stat_ident, _lstat_or_none) exist there. _subagent_file differs between the two trees, and the fix changes only its docstring. The fix was not run on upstream's tree.

Tier fix: a bug fix with tests that fail before it. In the fork the branch carries romp-on/romp PR #1822 merged with fork PR #875's resolution and lands right after fork PR #875, never before it.
