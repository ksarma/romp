Stage two of the usage-data plan (2026-09-18), stacked on the export (fork PR 764): one verb sends one file written by romp perf export --public to a receiver and nothing else. The receiver address is configuration and is EMPTY upstream: --receiver URL, else ROMP_PERF_RECEIVER, else ~/.config/romp/perf-receiver (the default-dir pattern; a regular file, else refused as an address naming the file, so a fifo there does not hang the verb); with none set the verb refuses and names the three settings, so an installation nobody configured sends nowhere, and no code carries an address. The receiver is unauthenticated, so the verb reads no token and sends none. The file is checked again as it stands (at most 1 MiB, strict JSON with no repeated key and the romp-perf-export/1 schema line, nested at most 32 levels, about four times a fresh export's depth, refused naming the bound before any check walks it, since the checks recurse one frame per level and this is the one road that reads a file a person names, the export's own scan, walk and denylist check through check_document, a finding reported by kind and key path only; the scan reads the hostname, login, home, the registry's ids and directories and the machine-local private-strings list when one exists (~/.config/romp/private-strings.txt, the list the pre-push hook reads, ROMP_PRIVATE_STRINGS and XDG_CONFIG_HOME honoured, absent on a clone that never set one up, and no list when the path is not a regular file, so a fifo there does not hang any caller; read as far as 64 KiB with a partial last line dropped so a fragment never becomes a probe; every entry a probe whatever its length, matched as a run of whole tokens or as a substring, whichever finds it, where the hostname and the login stay whole-token matches; one stderr line says when the bound was hit and the entries past it are not checked, or when listed entries did not become probes; the hook matches each entry as a plain substring, a known divergence a comment at the read names, one shared matcher being a later change), so romp perf export --public and romp restart-metrics --json --public refuse such a string too; the denylist walk is the fold's fixed point, holding the file to the export's own fold, paste-safe, not unlinkable, with six findings: a key the export drops, a string value the fold would have folded to other, a key the grammar's anchored match admits but the fold would have replaced (a trailing newline among them), an uptime off whole minutes, a bound off a power of two or a float inside a clock stamp's epoch window (1.5e9 to 2.0e9 seconds, 1.5e12 to 2.0e12 milliseconds) under any key but a duration key is refused, and, whatever those find, the document's top-level keys are held to the ones the export writes (schema, exported_at and perf, with kernel_commit and usage optional), any other refused naming the key alone, exported_at and kernel_commit to the export's own shapes, and perf and usage each to its own fold, the verb refusing naming the block, the whole root never folded because the fold's rules are anchored at the block root; and the measurements the export keeps pass, an integer of any size among them, a byte total or a count, a float outside both windows, the allocator's figures on a long-lived kernel among them, and a float inside a window under a duration key, a name carrying the token ms, a millisecond total, all of which a long-lived kernel's figures reach); what is sent is what was checked: the body is the parsed document re-serialised by the export's own writer (perf_export.document_text), never the file's raw bytes, so a spelling no check read never travels and a file as the export wrote it goes out byte for byte (the fourth review round closed the divergence between the parsed document the checks read and the raw bytes the verb sent); the verb prints the path, the byte size of the body and the URL it will dial (a path in the address included) and asks for a yes on a terminal, refusing off a terminal unless --yes is passed (the agent's form; no setting or variable stands in for it, so nothing uploads from a cron). One POST to <receiver>/v1/upload (stdlib urllib, redirects refused with the Location never parsed, no proxy variable read, no cookies, six headers: Content-Type, Content-Length and User-Agent romp-perf-upload/1 from the verb, Host, Accept-Encoding: identity and Connection: close from the client; 30 s as one deadline over the whole exchange, connect, send, status line, headers and body, held by a timer armed on the connection's socket that shuts it down when the budget runs out, the connect and handshake bounded by the connection's own timeout cut to the time left, not a per-read timeout, so a receiver answering in pieces cannot hold an unattended --yes run open, and the refusal is the same fixed line naming TimeoutError); the only answer accepted is 201 with exactly {receipt: uuid4, retention_days: int, av: ok|skipped}; every other status, body or error is refused with a fixed line carrying only the status code or the error class. docs/reference.md states the request and response contract so any operator can write a receiver, the 180-day retention, the screening (vocabulary, antivirus) and deletion by receipt id; docs/guide.md says what the upload sends and to whom: a paste-safe copy of the counters, to a receiver the user configures, none shipping, and only after a yes; it ranks the upload against no other traffic, and the guide's pre-existing local-only clause is untouched, its rewrite a separate change for the owner. The tests include an executed enumeration of the request a recording receiver saw (line, six headers, body bytes equal to the file for a fresh export and to the parsed document's re-serialisation for an edited one). The stage-three trigger (an unattended sender) is the owner's later word and is not built. Before landing, the branch's history was rewritten so the accepted-address fixture in tests/test_perf_upload.py carries the reserved example domain from the commit that introduced it (the tip had already been redacted; the introducing commit and the ones after it had carried a real service hostname and were published on the fork); the rewrite keeps the string out of main's history, which the fork's merge-commit-only landing would otherwise have carried it into, and it does not unpublish the earlier shas, which stay reachable through the PR's timeline.
