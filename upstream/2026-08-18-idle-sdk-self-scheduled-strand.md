Upstream ships the same SDK turn loop (turns start only from the input generator's fed messages) and no queue watcher. Live-transcript evidence, TWO regimes: in most sessions the CLI delivers this class itself straight from idle (602 of 1311 enqueues across 25 sessions, median 46ms, p90 126ms; the delivery writes NO dequeue record — the user record carrying the text is the evidence), but a session can fall into a stuck regime where nothing ever starts the turn: an overnight 15-min Monitor stacked 33 undelivered enqueues while the session ran zero turns for 8+ hours (that transcript: 123 enqueues, 0 delivered, 66 removes = discards). Background-agent completion notices are delivered in EVERY regime, the stuck one included, and are excluded by id class. Fix = a pusher-cycle tick (`_idle_queue_drive_tick`) reading the transcript's still-pending enqueues PER ENTRY (a content-addressed remove resolves its own entry; a user record carrying the text is the delivery evidence, one entry per carried occurrence, so a varianceless monitor's identical firings resolve one at a time; the same queue-operation records `_pending_queued` folds, no new polling), with a ~60s age floor PER ENTRY — only the aged subset drives, so the delivering regime is never raced and a sub-floor-cadence stream cannot starve candidacy (the CLI's decision NOT to deliver writes no record, so only its window passing proves the stuck regime — the documented exception to the no-time-windows rule), + `SdkBackend.drive_idle_queue`: per-watermark latch (in memory at acceptance; persisted to the reg only after the enqueue lands, so a kernel death in between re-drives instead of discarding), one worker per sid (overlapping drives let a stand-down's mark restore clobber the newer worker's watermark and double-deliver), gates re-checked at the send moment against a re-resolved session, dormant spawns drawing on boot-reconcile's own stagger budget (one shared semaphore), delivery via enqueue() of the queued texts verbatim (no synthetic prompt), problem-ring-loud failures, and the queued-bubble/_backend_queued genuine-filter so a parked wrapper never renders as the user's input. Red-first tests: both regimes, the floor, per-entry resolution, every gate at acceptance and delivery, boot parity. Pure bug fix, no fork-specific content.
