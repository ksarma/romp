Part 1 changes nothing on the wire today: every kernel-served page's caps are feedDelta and/or readyGate, so every relay dial's joined term is still feedDelta; the plumbing lets a page cap a later change grows (a face projection, say) reach a remote kernel without a federation change, and readyGate never travels because the hold it names is the shim's on its own socket and the federation manager posts its own ready. Part 2 is the field the fork's owner approved on 2026-09-19 by name (the bytes each attached host sent, one number per host, no content): counted in the conn's ws.onmessage before the parse in the shim's unit (String.length, keepalives and undecodable frames included), kept per page-lifetime host position (h1 the first remote host the page saw, never pruned on detach so a re-attached host keeps its position and the collector's per-minute difference stays right), at most four positions named and the rest under hmore. The row carries positions, never names; the file's federation and shell surfaces carry host names already, so a reader holding both surfaces can map a position to a name within one page life. No /perf aggregate, export or public projection reads client-diag, and romp perf client folds by explicit .get() and never reads wsBytes. The __rompDialTerms line in kernel.py is byte-identical to the project's, so the caps field is added by a wrapper line inserted after it rather than an edit of it.
