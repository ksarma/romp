Upstream shipped their OWN fast-mode toggle on 2026-08-07 (`258d9719`, their PR #222) hours after ours, and **it does not work**: they send the literal `/fast on` without ever supplying the flag-settings key, so the CLI refuses every SDK session (`fast_mode_state=off reason=sdk_opt_in_required`). The re-check ran 2026-08-09 against their v0.6.0 tip: nothing changed — `git log -S` for `fastMode`/`fast_mode`/`fastReason` over their 42 new commits is empty. CORRECTION to this row's earlier text: their badge is NOT dead-clickable — their kernel blanks it server-side whenever `fastReason` is set (their `kernel.py`, the `"fast": "" if tm.get("fastReason")` gate), so their real failure mode is an **inert feature**: no control ever appears on an SDK session and fast mode can never be enabled; any offer must say that, not "your badge is dead". Verified in CLI 2.1.224: the flag is both the unlock and the starting state, and once a session is CONNECTED with it, literal `/fast on|off` works live in both directions — so the minimal offer hews to their implementation: persist the ask as a reg bool, mirror it into a per-session settings file at every connect (per-session because `options.settings` is one path and ultracode shares it), keep their literal-send body when the connection carried the flag, reconnect only for the first opt-in. That fix is `sdk_backend.py`-only (~+70/−30); their kernel, UI, badge, parking, and `fast-toggle.test.ts` survive as-is, and it also cures their second latent bug (fast state silently lost on any reconnect). Adopted on the fork 2026-08-09 (PRs #35/#37/#38: option A, full convergence — the fork and the offer are the same implementation) and live-tested on the fork's own kernel: first opt-in reconnects once, later toggles are live, state persists across restarts. Offered upstream as their PR #255 (branch `fast-opt-in-offer`) and MERGED 2026-08-10 into v0.7.0. Upstream then built PAST it — persisted `liveFast`/`liveFastReason` seeding across kernel restarts, a shared `_adopt_fast_state` connect+init path, the curable `sdk_opt_in_required` handling, humanized refusal toasts, and the one-word Fast/Slow badge — all adopted back on the fork in the v0.7.0 merge (2026-08-11), which took their newer generation wholesale. The offer branch can be cleaned up.
