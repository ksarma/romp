A pane title is free text (only length and non-empty were checked), so a title holding a quote, a backslash or a newline reached the shim served at /pane/<id>/shim.js, baked into a double-quoted JavaScript string literal (var LABEL="%s"): a quote, a newline, a trailing backslash or a malformed \x or \u escape made the shim a SyntaxError that never loaded; any other backslash was read as an escape (C:\docs became C:docs), so LABEL silently differed from the title; and a crafted quote such as "a"+"b" parsed and changed LABEL. The fix bakes LABEL and APP with json.dumps(ensure_ascii=True) into bare template slots (as LOADEDPV bakes pvv), so the shim parses and LABEL equals the title for any title. A title or source is also refused at _pane_check when it is not one line of text (a control character, U+2028/U+2029 or an unpaired surrogate), the field, the cause and the offending position named (an id with such a character is refused by the id rule, which already excludes it, with no position given): an unpaired surrogate in such a title or source otherwise broke _send's strict body.encode('utf-8') and served a 500 for the whole landing, while a control character or a separator encoded and served normally (a newline in a title folded the bell row). Separately, _PANE_ID_RE was applied with re.match and a $ anchor, which matches before a terminal newline, so an id ending in a newline passed the rule and reached the landing's unquoted markup and CSS; it is now matched whole with fullmatch, and the pattern keeps $ (not \Z) so it stays portable to a JavaScript RegExp. An id equal to an Object.prototype own-property name that matches the id rule (today "constructor") is refused too, since the landing reads a pane id as an object key. The other title sinks (the rail, the phone tab, the body attribute) already escape through _html_esc, and the WS-drop bell row renders client-side through textContent; the id is inert in its remaining sinks once it is confined to the whole-string rule. A record the base accepted but the stricter schema now skips (an id that is an Object.prototype name or ends in a newline, a title or source that is not one line of text) is named on stderr with its file path at each listing, and remove_pane clears such a skipped record by its file name, so no file is stranded and unremovable. Defence in depth, offered as a correctness fix.
