Upstream runs `_lift_spent_awaiting` every pusher cycle and loads every alive session's store: 5.4% of the pusher thread in the 2026-09-06 profile, 3.1% of it in `load_goals`, and in the common case the job writes nothing after the load. Both lists it computes (stamped and rolled) are functions of the loaded store alone, so the store's identity decides whether a load can produce a different answer; a session with candidates is never gated, so the clock, registry and transcript inputs run every cycle as before, and entries for sids that left the alive set are dropped each tick. The skip is safe because every writer moves an identity (a publish by rename, a journal append, an archive publish), the stat is taken before the read so a writer racing the load costs one redundant load on the next cycle and never a wrong skip, a load that raises records nothing, and a load that fell back to an empty store after a swallowed read failure records nothing. Without the `_unread` mark the gate recorded a skip for an identity whose stat had succeeded and then skipped an idle stamped session until one of its three files was republished, which for an idle session could be never; an absent file is not marked, because empty is its content. Loads per cycle fall from one per alive session (about 30) to one per session carrying a stamped node (about 5).

Base of the round-2 kernel stack: J4 (`propagate-load-once`, #266) and P9 (`shared-goal-store-cache`, #267) consume the `_unread` mark and follow this. Depends on `romp-perf` (fork #199) for the `memos.lift_gate` block only. The race test wraps `jd.load_goals` so the first call publishes a stamped store after the real read returns; re-stat-ing the key after the load fails that test and no other. The same-size pins fail with either key component dropped.

2026-09-07: resolved upstream, in the upmerge0907 fold. Upstream built its own gate (`_sid_inputs_fp` / `_lift_seen`: a fingerprint of the store, the override journal, the goals archive, the transcript, the postal log and the SDK reg, which also skips a stamped session whose inputs are unchanged) and the fold adopted it; `_LIFT_GATE` and `_lift_gate_key` are gone from the fork, and `tests/test_kernel_awaiting_lift.py::LiftGate` now pins the adopted gate. Fork-only on top of it, and not covered by this entry: the goals archive in the fingerprint, the transient `_unread` mark (`kernel/judge.py` `load_goals` / `_replay_overrides`) and its forgetting at the gate, `_lift_gate_stats` / `_lift_gate_report` for `/perf`, and the alive-set cleanup. A new candidate entry for that layer is the owner's call.
