kernel/judge.py makes the state root 0700 at import, best-effort, swallowing the OSError, and since 2026-09-19 reads the mode back and says one stderr sentence when it is not 0700, refusing nothing. So a root this uid does not own stays loose with one line nobody reads, a root loosened after boot is never read again, and the premise of _atomic_write's interim-mode argument (a file written at a looser mode is not exposed because the root is owner-only) rested on a diagnostic. Now the check has four arms and a consequence. One: a root with a group or other write bit (mode & 0o022) refuses to serve, since write access by another local user is the cross-session code-execution road: at boot the kernel says one line naming the root, the mode read back and the remedy and exits 2 before any thread starts (the manager restarts it and it refuses again); found by the re-check after boot, a latch answers every request but /healthz and /version with a 503 JSON body (the error, the mode, a path-free remedy) and runs no route, /ws upgrades included, until the root reads tight again, when serving resumes with a row that says so. Two: a root not 0700 but not writable by others (0750, 0755, 0711) is a privacy fault, not a code-execution one: one error-centre row (_sdk_problem) and one stderr line per transition, no refusal, the reason mirrored into /version's stateRootMode the way the model catalog mirrors its failures. Three: the check re-runs on the jobs pass's cadence, before every request and before every WebSocket client frame, each at most every 15 s (ROMP_STATE_ROOT_CHECK_S overrides it), and the same two-way rule applies at every check; a verdict the check could not read (unknown: the stat failed, or the check raised, which is cached as an unknown check with the exception's type name and its traceback said once) lifts no latch, only a mode read back with no group or other write bit does, and the resumed row names that mode. Four: a failed mkdir or chmod is recorded as "ENAME: strerror" (errno.errorcode and os.strerror, never the exception's text, which carries the path) and reaches the same line, row and /version field, a root that reads 0700 but whose chmod this uid cannot run included (verdict ok with a line, one row per transition). /version and the 503 body carry no filesystem path (the route answers with no token, and the root's default sits under $HOME); the stderr line and the error-centre row name the root. Existing WebSocket clients are not force-closed by the latch (out of scope), but a frame one sends under it runs no op: the socket is answered one stateRootRefused frame (the 503 body) per latch episode and the frame is dropped; pushes keep flowing and the background loops keep running (the latch stops serving, not the process). The check reads the mode of the path the root resolves to and nothing else (not the parents, the owner, or whether it is a directory). Not changed: the 0700 target, who owns the root, and the serve socket's mode. A failing-before test per arm in tests/test_state_root_mode.py.
