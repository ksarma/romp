set_auth_default wrote sdk-defaults.json and touched no session, while docs/reference.md promised that a session with no pick of its own takes the new side at its next launch; per-session hosts and their CLIs outlive a kernel restart, so that launch never came and every follower stayed on the old side. The write now walks the live sessions and asks every follower whose CLI runs on the other side (the CLI's own report before the composed stamp, which a re-attach stamps untruthfully; an attach whose CLI has not reported yet stamps nothing, and the CLI's first init decides) to reconnect exactly as a per-session pick asks, with no pick written, so it keeps following the default; every landing of a follower runs the same comparison, so a session with no live object at the write is asked at its attach; the relaunches draw the machine-wide spawn-stagger slot at the arm, with the CLI still serving, and free it at the handshake; a follower's ask survives a kernel restart and is made again at the attach to the surviving CLI, held for the background work that CLI still runs (counted from the registry's mirror at the attach, and decided by the CLI's own turn-end report, the Stop hook's task list, at the first turn after it: a task it lists is confirmed, a shell it omits is retired, any other type it omits is kept until the CLI's own stream ends it, and a running task it names that the kernel never saw is counted); one follower's fault leaves the walk to the rest, through the one guarded entry point every caller of the follower's step shares; the launch and the per-init check read the file's auth only beside authExplicit, so one per-session pick no longer rings on every unpicked session. kernel/kernel.py carries the relaunch slot waiter's thread kind (sdk-slot in _THREAD_KIND_PREFIXES). The spawn's seed and the new-session picker's preselection still read a per-session pick's flag-less value, as before this change: making them read only the explicit default changes which account new sessions bill on a box with a remembered pick, so that change is split out into its own PR (the reviewer's round 2, 2026-09-19).

What a default change costs, with the reviewer's rounds 1 and 2 applied: every follower on the other side relaunches its CLI, staggered three at a time on the boot-resume budget, each at a quiet moment of its own (no turn in flight, no fed text, no live subagent, background task or Workflow run), and it keeps serving until its slot is granted; a follower that carried its ask across a kernel restart holds it for the surviving CLI's background work until the CLI's own stream ends that work or its turn-end report at the first turn after the attach retires it; a turn that ends with no report holds what nothing spoke for and says so (the round 3 pre-check of 2026-09-19; until it, the settle dropped those rows). The standing rule for that mechanism (round 2): nothing is torn down, reported to the session as cut off, or wiped from the registry's mirror on the inference that work ended, only on the CLI's own report; without one the row is held and the log says so. Sharpened in the round 3 pre-check: a report's presence is always trusted, its absence only for the task types the reporter is known to enumerate completely, and one predicate (report_absence_decides, in kernel/sdk_backend.py) answers that for both reconciles of the Stop hook's list: shells alone, on a probe of 2026-08-28 and a read of the bundled CLI 2.1.266's producer on 2026-09-19 (the list is built from the whole task registry on that build, so it is type-agnostic there; the read is not a probe, and the kernel launches whichever claude the PATH resolves, so the unverified types stay on the restricted side until one probe per type widens the set). A retry after a handshake that timed out against a surviving CLI retires nothing (round 2's high), and a stand-down after four such timeouts holds the rows and the mirror for the next attach instead of filing a death notice for a CLI still alive (the round 3 pre-check). The Stop hook reads the report before any of its bookkeeping, so a bookkeeping step that raises cannot turn a report into a no-report, and a payload without the list is a no-report, never an empty one. Two residuals are disclosed, not closed, since both are one design question (what the authoritative read of a surviving CLI's live work is at attach time, for background tasks, Task agents, Workflow runs and hook-only subagents alike), which the reviewer has queued: a recorded task whose closing record never reaches the kernel holds the ask, the pending dots and a stoppable-task row until the CLI's own report or stream speaks for it, and for a task other than a shell until its end frame alone, across turns and restarts (a replayed end frame pops the row but releases no pick); and a subagent known only to the SubagentStart hook has no registry mirror and is never counted, so a survivor whose only live work is such a subagent can be re-armed at the attach. One consequence for the user's packet, decided by nothing here: a session spawned while a default stands (the explicit one, or a per-session pick's remembered value) carries it as a pick of its own and is not moved by a later change; whether such a session should follow instead is a semantics question for the user. The kernel side goes live at the next kernel restart of the box that serves the sessions. An offer waits on the user's word.
