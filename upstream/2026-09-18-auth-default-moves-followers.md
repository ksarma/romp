set_auth_default wrote sdk-defaults.json and touched no session, while docs/reference.md promised that a session with no pick of its own takes the new side at its next launch; per-session hosts and their CLIs outlive a kernel restart, so that launch never came and every follower stayed on the old side. The write now walks the live sessions and asks every follower whose CLI runs on the other side (the CLI's own report before the composed stamp, which a re-attach stamps untruthfully; an attach whose CLI has not reported yet stamps nothing, and the CLI's first init decides) to reconnect exactly as a per-session pick asks, with no pick written, so it keeps following the default; every landing of a follower runs the same comparison, so a session with no live object at the write is asked at its attach; the relaunches draw the machine-wide spawn-stagger slot at the arm, with the CLI still serving, and free it at the handshake; a follower's ask survives a kernel restart and is made again at the attach to the surviving CLI, held for the background work that CLI still runs (counted from the registry's mirror at the attach); one follower's fault leaves the walk to the rest; the spawn seed, the launch, the per-init check and the new-session picker all read the file's auth only beside authExplicit, so one per-session pick no longer rings on every unpicked session or turns picker-created sessions into picked ones. kernel/kernel.py carries the picker's copy of the explicit-default gate (_auth_avail, and _auth_avail_status's contract sentence) and the relaunch slot waiter's thread kind (sdk-slot in _THREAD_KIND_PREFIXES).

What a default change costs, with the reviewer's round 1 applied: every follower on the other side relaunches its CLI, staggered three at a time on the boot-resume budget, each at a quiet moment of its own (no turn in flight, no fed text, no live subagent, background task or Workflow run), and it keeps serving until its slot is granted; a follower that carried its ask across a kernel restart holds it for the surviving CLI's background work until the CLI's own stream ends that work, or the first turn's end drops what the stream never confirmed. Two consequences for the user's packet, decided by nothing here: (1) a box whose last per-session pick was the login and whose settings carry an apiKeyHelper bills NEW sessions on the key from this kernel on, since a per-session pick's remembered value no longer seeds a new session (neither of the user's boxes is in that state: one default is already explicit, the other remembers no pick); no migration, since writing the flag beside the remembered value would promote a per-session pick into a machine-wide default and move every following session. (2) A session spawned while an explicit default stands carries that default as a pick of its own and is not moved by a later change; whether such a session should follow instead is a semantics question for the user. The kernel side goes live at the next kernel restart of the box that serves the sessions. An offer waits on the user's word.
