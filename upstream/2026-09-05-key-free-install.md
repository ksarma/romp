title: Key-free installation mode: a second key source beside upstream's `service.env` file. With `ROMP_CREDENTIAL_COMMAND` set (non-secret; in `service.env` or a systemd drop-in: a line added to the unit or the plist by hand does not survive `romp-service install`, which rewrites both) the kernel runs that command with a one-token selector file as `$1` and merges the `NAME=VALUE` set it prints into every session CLI's launch environment (the key only where the session's Billing pick is the key), every judge call's (minus the key, re-added for key-billed calls) and the catalog fetch's `ANTHROPIC_LP_API_KEY`, never into its own environment or a file. Event-cached (a refresh, a cycle or an authentication failure invalidates; a failed run keeps the previous set, loudly, and never refuses a launch), coalesced, value-free everywhere but one accessor; failure reasons carry counts and exit codes only. Sessions are stamped at connect with the fingerprint they launched under (the set's key, or the configured `apiKeyHelper`'s output hashed inside the module), and `cycle_key` converges on it, which replaces the fold's always-reconnect helper outcome. The mode is pinned at backend construction (`envsource.pin_mode`): a `service.env` edit reaches the kernel at its next start (`romp refresh`), never a running one. The CLI's own auth and endpoint names (`ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS`) are dropped like `ROMP_*`; an authentication failure invalidates once per credential; a failed run is re-run by the next caller; the selector is rendered by name only when `ROMP_CREDENTIAL_NAMES` declares it (else `(undeclared, N chars)`); a set with no key and no `apiKeyHelper` is the login, a state not an error. A pure `key_source_verdict` at boot rings on credential-shaped lines in the env file, unit, drop-ins or plist, a startup key, a shell-wrapped ExecStart, `login` declared while the command prints a key, `key` declared with nothing to inject and no helper, dropped names, a bad timeout; `/api-health` gains `keySource` (with `lastRun.stale`, `failures`, `lastOkAt`), `/keycycle` gains `keySource`, `keyKind`, `keyErr`, `setFp`, `selector`, `launched`, `refreshed` and per-row `from`. A failed credential-command run is one problem line per failure episode on every path that can run the command — the connect, the boot, the refresh, the judges' and the catalog's `credential_set`, a judge's `work_api_key`, the status report, `/api-health`, the key cycle — through one noter (`_noted_take`), the boot included: the boot verdict's lines are the boot's one report of the first run and it hands the record to the noter as already said, a boot on a failing command runs the command once (the verdict reads whether a key is injected from the record, not from a second live read), and every record carries the ordinal of the run that produced it, which the noter keeps as a watermark so an older record is never noted after a newer one; a backend's own readers (the status report, `/api-health`, the key cycle) note on that backend, and the module-level noter is a weak reference, so a test process's dropped backend receives nothing. Before, only the connect, boot and refresh paths said anything, a failure first met on a judge call was silent until the next connect, and the boot said a failure twice. The boot verdict on an explicit environ is pure on its inputs (its mode from the environ's own line, else the `service_env_text` handed in), never the env file this process names. Surfaces: `romp keyswap` reports both sides by fingerprint with MISMATCH lines, `<name>` writes the selector (declared names only, undone when nothing moved), `--refresh`, a converging `--cycle`; `romp-service status` prints the mode, the ExecStart shape and credential-shaped names; docs split into "API keys on disk: the file mode" and "Installing without keys on disk"
