A bus whose peer only dials it (the peer's kernel holds an ssh forward to this bus; this bus's own kernel holds no tunnel to the peer, so PEERS has no row for it, or a portless or held-down one) answered every /send to that peer with "parked for <host> (unreachable)" and posted a /redial (a silent no-op for a host with no row or a portless one), and check_sent read "(unreachable)" too, although the mail crossed on the peer's next long-poll exchange. The send path and the receipt read only PEERS, which only this bus's own kernel's tunnel notifies fill.

The fix counts a host reachable while its inbound exchange link is open, keyed on events, with no seen-at window: an exchange's arrival opens it, and a response write that returned with a 200 keeps it open across the gap before the next dial. The dialer's FIN or reset (read by a non-blocking peek on the live exchange's socket, before the response write), a write that raised, and a handler exception after the arrival close that exchange alone, so another live dial under the name keeps the link open. An exchange the handler refused, or raised on, before the arrival (not one the token gate or the body checks refused, which close nothing) closes the link of the name it resolves to and every link whose arrivals declared its host, and an arrival closes each other link whose arrivals declared the name it declares, wherever the two are filed (the link filed under that name and an alias's link, either way round, or two aliases' links: a newer process of the host under the name or under a second alias, the same bus under a second dialable name, an alias pointed at another machine while the one it reached keeps dialing, or a namesake), and each other link that holds the busId it carries (the same process declaring another name, a rename while it runs); and this bus's kernel's down notify for a host's port row, the event that marks its row linkDown, closes the link filed under that name until a dial filed under it arrives: every down notify does, whether the row was up, held down, portless or absent, and it changes only the link's reading, leaving the names and busIds the link's arrivals brought as they were. Each of these outranks every older exchange, a parked dial that ends ok after it included. Otherwise the newest evidence decides. A link's declared names and busIds reset when an arrival brings both a name it has not seen and a busId it has not seen, or none (an alias pointed at another machine). A send to an open link answers "queued for '<name>' on <host>: it goes out on <host>'s next poll of this machine" and keeps the parked key; a send that parks mail for a host with a port row posts /redial whatever the link says, and one for a host without a port row posts none. The receipt's parkedUp reads the same rule. So a host whose port row the kernel holds up when it goes silent (a check-in peer, whose one ssh carries the -L to this bus and the -R back, or two machines that attach each other) reads relaying while the row is up, as before, and unreachable from the down notify until its next arrival. That close costs a false unreachable while the host's dials still carry its mail, where reading PEERS alone also said unreachable: a dial that arrived before the notify carries the mail a send wakes it for until it writes; where the host's dials stay healthy, the false unreachable lasts until that dialer's next request arrives, which waits on this bus's read of its own kernel's session listing, for the response it writes to the dial the notify's wake released, and then on the host's read of its own (each up to about 6 s), the host's read slowest when its kernel's slow answer is what failed the poll, and, for a dial that cleared the notify's wake on its way to its park, up to EXCHANGE_WAIT or until a send's wake; and after the reopen, a process whose busId stayed in the link's set supersedes it when it dials under another name, as without the notify. Examples, not a list, of notifies while the host's dials stay healthy: a check-in row's flap at one unanswered poll; between two machines that attach each other, this side's tunnel dropping or the far kernel not answering; a switch to isolated. The re-tells of a row held down, each closing the link until a dial filed under that name arrives, include a change of its trust, each restart of the kernel or of this bus, the re-send of a notify the bus did not acknowledge within the kernel's 2 s timeout, and a check-in row's re-check-in; the notifies at the attach dedupe's absorption of an alias and at a detach close it the same way. The DOWN NOTIFY bullet at `_inbound_links` states the rule and these examples. A host's going silent brings no event to this side when it has no port row or a portless one, when its link is filed under another name than the row's, which the notify does not reach, or when its port row is held down already, since a row already down does not change (a later re-tell of the down row closes the link as any down notify does); until one comes the link stays open and the note says queued: THE RESIDUE at `_inbound_links` lists the shapes (a silent partition, a bus that dies between exchanges, a kernel mark-down that leaves the tunnel up, a dialer that leaves after the pre-write probe, a dial refused before the route, a write blocked on a stalled peer, each a delay rather than a loss; and two moves that share neither a declared name nor a busId with the link they leave, a host whose next process declares another name under a new busId and an older peer that sends no busId and declares another name, whose mail, when the old process left no EOF this side saw or the move came between exchanges, waits for a dial filed under the old name again or for that name's own tunnel, which never comes for an alias the kernel's attach dedupe absorbed). THE NAMESAKE COST there gives the opposite shape: a second bus declaring the same name closes a healthy link when it is refused, when it dials with success under another name than that bus's, when it leaves while that bus is between exchanges, or through a busId it left in the link's set. So two different machines that share a short hostname, each filed under its own alias by busId (two PEER_STATE rows, not a collision), supersede each other's link at every arrival, and the note says unreachable while the mail crosses.
