A bus whose peer only dials it (the peer's kernel holds an ssh forward to this bus; this bus's own kernel holds no tunnel to the peer, so PEERS has no row for it, or a portless or held-down one) answered every /send to that peer with "parked for <host> (unreachable)" and posted a /redial (a silent no-op for a host with no row or a portless one), and check_sent read "(unreachable)" too, although the mail crossed on the peer's next long-poll exchange. The send path and the receipt read only PEERS, which only this bus's own kernel's tunnel notifies fill.

The fix counts a host reachable while its inbound exchange link is open, keyed on events, with no seen-at window: an exchange's arrival opens it, and a response write that returned with a 200 keeps it open across the gap before the next dial. The dialer's FIN or reset (read by a non-blocking peek on the live exchange's socket, before the response write and at each read of the link), a write that raised, and a handler exception after the arrival close that exchange alone, so another live dial under the name keeps the link open. An exchange the handler refused, or raised on, before the arrival (not one the token gate or the body checks refused, which close nothing) closes the link of the name it resolves to and every link whose arrivals declared its host, and an arrival filed under another name closes each link whose arrivals declared the name it declares (a newer process of the host, the same bus under a second dialable name, an alias pointed at another machine while the one it reached keeps dialing, or a namesake) or that holds the busId it carries (the same process declaring another name, a rename while it runs); each of these outranks every older exchange. Otherwise the newest evidence decides. A link's declared names and busIds reset when an arrival brings both a name it has not seen and a busId it has not seen, or none (an alias pointed at another machine). A send to an open link answers "queued for '<name>' on <host>: it goes out on <host>'s next poll of this machine" and keeps the parked key; a send that parks mail for a host with a port row posts /redial whatever the link says, and one for a host without a port row posts none. The receipt's parkedUp reads the same rule. Where no event reaches this side the link stays open and the note says queued: THE RESIDUE at `_inbound_links` lists them (a silent partition, a bus that dies between exchanges, a kernel mark-down that leaves the tunnel up, a dialer that leaves after the pre-write probe, a dial refused before the route, a write blocked on a stalled peer, each a delay rather than a loss; and two moves that share neither a declared name nor a busId with the link they leave, a host whose next process declares another name under a new busId and an older peer that sends no busId and declares another name, whose mail, when the old process left no EOF this side saw or the move came between exchanges, waits for a dial filed under the old name again or for that name's own tunnel). THE NAMESAKE COST there gives the opposite shape: a second bus declaring the same name, refused, dialing under another name, or leaving while that bus is between exchanges, closes a healthy link (two buses under one name already collide in PEER_STATE).

The project's public tree (upstream/main, last updated 2026-09-24) carries the same send-side branch (postal/postal_service.py `if PEERS.get(phost, {}).get("up"):` and the parkedUp read).
