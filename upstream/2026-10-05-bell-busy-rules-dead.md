The phone bar's CSS carried `#mtabs #mbell.busy{opacity:.45}` and `.rail-acts #rail-bell.busy{opacity:.45}` under a comment calling the dim the tap's acknowledgement while the subscribe request ran. That was true when the rules came in, when a bell tap subscribed this device and the push script put busy on the bells until the request answered. Since the popover took the tap (294d8b8ff, 2026-09-05) a tap only opens or closes the popover, the popover's rows show their own busy state while their requests run (setBusy, `.rbp-row.busy`), and no script puts busy on a bell, so the rules and the comment described a state the page never shows. In the served lab (Chromium, a desktop window and a phone-sized touch viewport, five taps each) the popover opened inside the tap's own click handler and was painted by the second frame, and no request ran between a tap and the popover's opening except an unrelated 3 s poll. Both rules go, and the comment now describes the on state and the [hidden] rule, whose old reason (a capability-gated bell) was stale as well. The two bells' markup comments, which said the script reveals a bell only where the Push API exists, now say it reveals both on every page and a tap opens or closes the popover. A census in tests/test_kernel_mobile.py reads the served shell: every class a parsed CSS rule names in a compound carrying a bell's id must be one the served scripts set on that bell when they run on the module's stub shell through the bells' taps, the kernel's frames, and every popover row answered, refused and pending. The rule half reads the forms it models and refuses loudly the ones it does not, so a rule that names a bell by its id is read or refused, never passed over: it refuses an id attribute selector, a class attribute selector on a bell, an attribute selector it cannot parse, a comment inside a selector (served_css blanks a comment to spaces, which read as a descendant combinator, where a browser drops it), a quoted bracket or paren in a selector (which the read's compound split counts as nesting), a selector whose parentheses or brackets do not balance (served_css leaves one when it cuts a rule at a brace a browser keeps inside them), a selector character outside printable ASCII (which can continue a class name past the read), a `{` inside a rule's block (a nested rule, which served_css reads as the outer rule's declarations when the outer brace is left off), anywhere in a style element a CSS escape, a quoted string holding a brace or a newline, or an unquoted url() holding a brace, a quote or a comment marker (served_css reads those braces and comment markers as structure, where a browser reads them as text, and runs a string on past the newline where a browser ends it), and an at-rule whose prelude can hold a selector (@scope, @custom-selector, a selector() test); BellRuleReader pins each refusal, and the served CSS carries none of them. A rule that reaches a bell with no id at all (through a tag, a markup class such as `.mact`, or another attribute) is not read, a stated limit. The census is red before the change on busy for both bells and green after. RailBell in tests/test_kernel_webpush.py drops its pin on the rail bell's busy rule.

upstream/main (last updated 2026-09-24) has the same dead rules: its kernel/kernel.py carries both busy rules under the same comment, byte for byte, in the phone media block, and its push script is byte-identical to the fork's, so there too a bell tap only opens or closes the popover, setBusy acts on the rows alone, and no script sets busy on a bell. Its two bell markup comments carry the same stale clause, that the script reveals a bell only where the Push API exists. Its tests/test_kernel_webpush.py pins `.rail-acts #rail-bell.busy{opacity:.45}` in RailBell, which an offer drops. Its tests/test_kernel_mobile.py has a _BELL_HARNESS with the same element and global names the census's driver uses, but no _mobile_js helper, and upstream has no tests/served_css.py, which the census's rule half and its script extraction read; an offer carries those reads in upstream's own form (not run against that tree).
