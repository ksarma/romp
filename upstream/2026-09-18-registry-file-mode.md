Upstream has the same writers byte for byte: write_reg publishes sdk/<sid>.json through a write_text temp at the umask mode (0644, or 0664 under umask 002; every live registry file and the parked-ops mirror sat at 0664 under the 0700 state root, only remotes.json was owner-only) and _save_pending_ops mirrors a parked ("env", {...}) op through _atomic_write with no mode, so a per-session env value under a token-shaped name sits in both files at that mode; the sibling writers of the same values (flag_settings_path, host_transport.write_spawn_spec) publish 0600 but tightened a pre-existing looser file only after the write. Every one of these writers now sets 0600 on the descriptor before the first write (os.fchmod, the shape cli/perf_export.py and the Codex registry lock already use): exact under any umask, no window with the text at a wider mode, and os.replace carries it onto the published path, so an older file tightens on its next write; a file never written again keeps its mode behind the owner-only root, and no boot-time re-mode is added (the reviewer's call). Every reader is the same uid. A mitigation behind the 0700 state root, not a fix for the value living in a file. Found in PR 776's review round (kernel-1, extra5-2) and deferred to its own fix; review round 1 of PR 789 replaced the first cut's exclusive create at the mode (a leftover temp became an error and the mode passed through the umask) with the descriptor shape.
