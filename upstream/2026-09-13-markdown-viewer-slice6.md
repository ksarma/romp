Upstream ships the same viewer, the same Files pane, the same todo surfaces and the same landing shell, so every item applies there once the slices before it have landed: a file opened in the viewer takes the keyboard, so PageDown and Space scroll it with no click first while a box the person was typing in keeps the keyboard; an Outline button above a rendered note lists its headings by depth and a pick puts the heading at the top of the view, opening a closed fold around it; a note left and reopened, in the same page or from the Files pane's Recent list across a page load, comes back to the place it was read, by the top block's source span with the pixel count as the fallback and never a word of the file in the store; a todo's `docs/report.md:12` or `docs/report.md#results` opens the file at that line or heading from the chat's todo card and from the Waiting-on-you pane, in the document or through the Files pane, where before the target stayed prose, and a section the file does not have is named in the notice bar rather than a silent open at the top; and a file that changed on disk while the Comments panel was closed says so above its text the next time the window has the focus or the tab is visible again, with a Reload that keeps the place. Built as Slice 6 of plans/markdown-viewer.md on Slice 8's head (fork PR 752, 2026-09-12-markdown-viewer-slice8), so the offer stacks on the six slices before it, each with its own entry (Slice 1 #390, Slice 2 #396, Slice 3 #407, Slice 4 #707, Slice 5 #749, Slice 8 #752). The files it changes are the viewer's own and the ones those entries already name: file-view.ts, the sheets' viewer regions, files.ts, files-recent.ts, path-links.ts, render.ts's openPath and todo walks, waiting.ts and the tests beside them travel with the viewer candidates; the guide and the plan port as they are. The store format is untouched (the Recent row's `place` is a field of the Files pane's own localStorage entry, validated on read and dropped when malformed, never the comments store), and the kernel's Python is untouched: the two lines that change in kernel.py are the landing shell's JavaScript, where the viewFile relay's two forwarders rebuild the message field by field and now copy `at`, so a deployment reads the field only after its kernel restarts. The `line` and `frag` options of openFileView are replaced by the one `at` option (`{ line } | { offset } | { heading }`), not aliased, so a host that passed either moves to `at`; the four callers in this repo moved with it.
