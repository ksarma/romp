PeerTokenPlumbing in tests/test_postal_token.py pointed a peer at 127.0.0.1:45001 with up: true, so the bus started a real dialer that POSTs there with a 30 s timeout. 45001 is inside the range the system hands out as source ports and bind(0) ports, so any process can hold a listener on it, and a listener that accepts and never answers keeps the dialer inside its request past the test's 10 s cleanup deadline: the test fails for a reason outside it (a fork sweep's red, reproduced with a silent listener on a port the system picked). Every test that wrote a fixed port in that range (32768-65535: Linux's default range and the macOS range together) now names a port below 1024, where nothing unprivileged can listen on Linux: port 1 for a dial that never lands, and 2, 3 and on where a test reads several ports apart. The postal sentinels a hermetic child reads back are 27201-27203, below the range. tests/test_ephemeral_port_census.py holds the rule: it walks tests/ and every *.test.* and fixtures file, reads Python by AST and everything else as text, and fails on any number in the range written as a port (a port-named key, keyword, assignment target or parameter default, a positional argument whose parameter is port-named, an address tuple, a URL, a port environment variable, a bounded computed value), and leaves prose, parser input, ids, sizes and durations alone. Tests only, so docs tier.

The public upstream tree (upstream/main, last updated 2026-09-24) has the same shape: this census run over it finds 98 fixed ports written as a port in 24 files, among them tests/test_postal_token.py's 45001 with a real dialer and the peer rows of tests/test_postal_peers.py and tests/test_postal_quarantine.py. Its vscode-extension/src/kernel-base.test.ts, which the fork does not carry, writes http://localhost:53021 as a resolver's answer; the census counts a URL wherever it is written, since it cannot tell a URL a test dials from one it only compares, so that line would move too.
