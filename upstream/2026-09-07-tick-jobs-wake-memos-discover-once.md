Three pusher-thread costs upstream shares, each keyed on an event rather than a clock. P1: both writers the tick's inline push served already end in `_mark_views_dirty`, which stamps the dirty mark and wakes the pusher, so the inline call spared no rebuild and on the stand-down path pushed with nothing new; the retry-pause writes are in no view signature, so they ask for a push rather than a dirty mark, `_mark_views_dirty` fires only on a real re-arm, and the push-caller census now admits only `_push_all` and `_pusher_cycle_jobs`, so a tick job that builds inline fails it. P2: the tick, the nudge tick, `build_feed` and the user-todo floor each re-tallied a session's user atoms every cycle over an unchanged parse; the result is a pure function of the atoms and the (cut_t, cut_cause) pair, so a new parse object or a moved stamp is exactly the event that can change it, and no clock enters the key; one entry per (sid, family) (the judge's parse object or the display cache's) so the two stop evicting each other; the interrupt tick evicts entries for sids that left the alive set and a 512-entry cap clears the memo whole. P3: `_sessions` ran a discover fingerprint and a stat per row 34 to 37 times per cycle on the profiled kernel, all returning the same rows; every read hands out a copy and outside a cycle every read is fresh. P3 also fixes a path: `_path_of` searched only the 48 h set, so for a live session idle longer than that the compaction gate read an empty parse, and an optimistic compact click could not be disproved by the session's own compact_boundary for the 180 s cap, during which the tick skipped the row. Tick micro-bench: `_interrupt_block_tick` 128.7 to 7.3 ms per cycle; `build_feed` 784 to 651 ms; `push_steady` -7.6%.

Top of the round-2 kernel stack (on P5+P8 #270, P9 #267, J4 #266, P6 #264). `romp-perf` (fork #199) for the two memo blocks only.
