Both halves of fork PR scope-oompolicy-continue, as one fix. Upstream carries the scope wrapper (their #953, landed as b570ef491) with the limits-only OOMPolicy line (their #1008, landed as 30be58404), so every limit-free session scope there keeps systemd's default `stop`, and one OOM-killed tool child ends the whole session (41 background tasks at once on this fork, 2026-09-10). The wrapper half puts `OOMPolicy=continue` on every scope, and the kernel's boot probe settles the policy apart from the memory limits: a systemd before 253 refuses the property and takes the limits, so the limits are probed alone once more and stand, the marker `ROMP_CLI_SCOPE_OOM_POLICY_REJECTED` goes down on every launch with an explicit value, and only a refused limit is a problem line. The heal half: when a session's CLI dies mid-turn, the heal asks systemd about the exact scope unit that CLI ran in (recorded from its /proc/<pid>/cgroup at connect) and reads three signals, primary first: the CLI's own exit (a SIGKILL is the OOM killer's signature under `continue`); the cgroup's memory.events oom_kill count against the turn's baseline (read for the sigkill kind, where a flat counter names a kill the counter did not see, and to tell a contained child kill apart); and Result=oom-kill for a scope without the property (third because under `continue` systemd records no Result), with the journal standing in once the unit is collected: its `Failed with result 'oom-kill'` line for the whole-scope stop, and for a SIGKILL exit its `A process of this unit has been killed by the OOM killer` line, which survives the collection and tells the OOM killer from a kill by hand. It then names the OOM kill in the kernel log and queues an out-of-memory form of the crash resume notice instead of the bare one. An upstream port also needs the consumer at their kernel/sdk_backend.py that keeps a nudge at the queue head by equality with CRASH_RESUME_NUDGE widened to is_crash_resume_nudge, the heal's own queue de-dup filter widened the same way, and their test_kernel_interrupt_machine_cut.py source pin (`reg["queue"] = [CRASH_RESUME_NUDGE]`) moved to the `nudge` pick. Round 3 (2026-09-10): a SIGKILL whose scope counter was read and did not rise over the turn's baseline is named a kill the counter did not see (a third form of the notice, CRASH_RESUME_NUDGE_KILLED), never out of memory; a collected unit has its journal tail read, since the Result leaves with the unit; the SDK's -1 exit reads as unreported and 137 as a plain exit; the heal names a memory limit only when one is set and not known to be unapplied, in the boot line's words, and the loop top no longer reads the old scope's counter at a reconnect. Round 4 (2026-09-10): the SIGKILL + collected cell is decided by the journal's kill line (oom with it, the hedged kill without it or with no readable record); the heal's scope reads run before the dead session is popped, so a send in those milliseconds lands behind the nudge; the journal read keeps the manager's own lines (`-t systemd`) and this life's (from the last Started line).
