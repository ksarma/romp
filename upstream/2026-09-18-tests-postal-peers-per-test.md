Upstream's tests/test_kernel_tunnels.py writes ROMP_POSTAL_PEERS=0 at module level (line 35 at 25e748130), and the kernel's _postal_peers_on reads the variable at call time. Under pytest-xdist every worker imports every collected module before it runs a test, so the value reaches every module on every worker whether or not that worker runs a tunnel test: tests/test_kernel_remote_identity.py's absorb case, whose bus notice is gated on peers, was red in 5 of 6 full runs on the fork (2026-09-18), and tests/test_postal_via_dedupe.py's relay case had gone red the same way (2026-09-16). The fix moves the value into a per-test setUp, put back by a cleanup, for the two classes that attach or detach (the 0 stays: with peers on, a detach's refused bus notice revives the bus from inside the test process), pins the default in RemoteIdentity's setUp with the module-alone red as its fails-before, and re-aims the hermetic pin: the port stays before the load (the kernel reads it at import), client-only before the load or in setUp, peers in setUp and put back by a cleanup registered there (a tearDown restore is skipped when a subclass's setUp raises after the write, found in review round 1) and never at module level, read by ast position over the real module and over synthetic copies with the leak planted, by a scan of every module under tests/ for a module-level write, and by an executed import probe that also runs a setUp that raises. The same round fixed the identical shape in tests/test_postal_bus_lifetime.py: KernelUp put ROMP_SESSIONS_FILE back only when a prior value existed, so the path its seam test wrote outlived the class, and a set value means a test with no live kernel to every postal call afterwards; the restore is a cleanup now, with a pin that runs the case. Reproductions, all red before and green after: the identity module alone with ROMP_POSTAL_PEERS=0 in the environment; the tunnels module collected before it in one worker; -n 2 with the tunnels module collected but deselected; a subclass setUp raising after the peers write; the bus-lifetime module alone with the seam unset. Review round 2 (2026-09-18) moved the two remaining tearDown restores of the variable, RemoteIdentity's and the dedupe module's _Seeded's, onto cleanups registered right after the write, each pinned by a case that runs a subclass setUp that raises; widened the repo-wide import-time scan from the subscript and setdefault to every write shape (update of a literal, of keywords or of a name bound to a dict literal, |=, a name bound to os.environ, os.putenv), loud on a write whose keys it cannot read; and states the walk, every .py under tests/ recursively, 941 files at that commit. Tests and docs only.

2026-09-22: fork PR #894 moves the port and client-only per test as well, so no leg of the trio is written at module level in tests/test_kernel_tunnels.py: all three are set in the setUp of each class that attaches or detaches, beside the kernel's BUS_PORT (read at import) patched to the test's own port and its _ensure_postal_bus stubbed, all five put back by cleanups registered right after the writes. The rule above that kept the port and client-only before the load is retired, and _PeersOff became _PostalTrio.
