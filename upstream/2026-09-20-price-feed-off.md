The kernel fetched a third party's price table (the public LiteLLM list on raw.githubusercontent.com, no credential) whenever the Token usage modal opened with a cache older than six hours, with no off switch and no trace: a table served from the baked-in defaults read as live, and a failed fetch was swallowed by a bare return. ROMP_PRICE_FEED=off copies the model catalog's switch (ROMP_MODEL_CATALOG=off: the same stripped, case-folded read, placed as the first statement of _refresh_remote_prices, the one function a fetch can start in, before the TTL check and the stamp) and goes one step past the catalog's silent off: the state is said where the user looks. One function, _price_feed_status, computes the block the /analytics payload carries as priceFeed (outside the 15 s memo on both roads) and /version carries beside modelCatalog, so the modal, /version and a curl cannot disagree.

What the user sees, on one muted line under the modal's footnote, worded by gear.js raPriceNote from the payload's block: with the feed live, `prices: live feed, fetched 4 minutes ago` (the age in plain words from the kernel's ageS); when the feed priced some of the table's models and not all (`rows` below `known`, the ids the baked-in table holds), `prices: live feed for 1 of 6 models, fetched just now; baked-in defaults for the rest`; with the switch on, `prices: baked-in defaults; live feed off (ROMP_PRICE_FEED=off)`; after a failed fetch, `prices: baked-in defaults; the last feed fetch failed (HTTPError: HTTP 500)` (a reason class, never the response body or the URL: the exception type, an HTTP status, a wrapped socket error's type and errno, an SSL failure by OpenSSL's reason token and verify message such as `SSLCertVerificationError: CERTIFICATE_VERIFY_FAILED (self-signed certificate)`, a resolver failure by the EAI_ constant's name and libc's text such as `gaierror: EAI_NONAME (Name or service not known)`, never a system errno's text for a library code); on the modal's first open, `prices: baked-in defaults; fetching the feed now` (the payload is built before the fetch it starts lands, and the next open reads the feed); before any attempt, `prices: baked-in defaults; nothing fetched from the feed yet`; after a fetch that landed and left no usable row, `prices: baked-in defaults; the feed matched no known model` when no row signed to a baked-in id (`matched` 0), or `prices: baked-in defaults; the feed's rows for 2 known models could not be read` when rows did and none parsed. A landed or failed result outranks a fetch in flight, so the TTL re-attempt keeps saying failed or empty while its worker runs. Under off a cache already in process memory keeps serving with its age said, and the feed line then carries the refresh's own state, `prices: live feed, fetched 10 minutes ago; refresh off (ROMP_PRICE_FEED=off)`, or after a refresh that failed while the rows still serve, `; the last refresh failed (HTTPError: HTTP 500)`: the switch stops traffic, not data, and there is no cache file. Rows from the user's ~/.config/romp/model-prices.json price their models whichever table the line names, so the block counts them (`overrides`, from the merge that prices) and either line ends `; 1 row overridden by model-prices.json` when one is in effect. A payload without the block (an older kernel) renders no line, and a block without a newer key (`matched`, `known`, `overrides`) is worded as the older shape. Stderr, in the catalog's idiom, each line's tail read from the same status so the log and the modal cannot disagree: `price feed: off (ROMP_PRICE_FEED=off); the cost view prices tokens from the baked-in defaults` once per kernel life at the first refused attempt (a kernel where nobody opens the modal says nothing; with rows already in memory the tail reads `the feed rows in memory, fetched 2 h ago`, and an override in effect appends `, 1 row overridden by model-prices.json`); `price feed: fetch failed (<reason class>); ...` with the same tail, once per failed fetch, which the six-hour TTL bounds to one line per six hours; `price feed: fetch landed with no usable row (2 signed to a baked-in id, none parsed); ...` once per such fetch; and `price feed: fetch failed (<reason class>), the worker thread did not start; ...` when the refresh's thread could not start, which clears the in-flight mark and records the failure instead of leaving the status reading inflight for the TTL.

T350 kept: _model_prices(refresh=False), the spend guard's road on the pusher's path, is unchanged and never enters _refresh_remote_prices, so it cannot start a fetch with the switch off, on or unset (tests/test_spend_guard.py test_the_guard_never_starts_the_price_feed_fetch, tests/test_price_feed_off.py GuardRoad). The signature _refresh_remote_prices(now), the price-refresh thread kind and the inner def name work are unchanged, so the _THREAD_KINDS register, the stage-marks census, the perf-bench positional call and the test_token_usage.py harnesses that replace the refresh with `lambda now: None` all hold. The suite floors the switch for every test (tests/conftest.py, the model catalog floor's shape, set at import and re-asserted per test; tests/test_price_feed_floor.py pins both), so no test kernel reaches the feed's host; the feed's own tests pop it in setUp.

What the switch stops is one request, the price feed's; every other request romp makes leaves as before. The list below is a census of the code at this head, not a promise: a later commit can add a road without touching this entry. The census reads every urlopen, http.client and socket site, and every subprocess argv naming gh, git ls-remote, fetch or push, ssh or npm, over kernel/, cli/, postal/ and bin/; connections to 127.0.0.1 (the manager, the postal bus, the tunnels' local ports) are set aside as local. With the feed off, these still leave the machine. To the model providers: each session's own model calls (the claude CLI to Anthropic; a Codex session's codex CLI to its provider) and the judges' calls to Anthropic; the kernel's Models API catalog refresh, on the apiKeyHelper's key or, on a box with no helper, on the ANTHROPIC_AUTH_TOKEN bearer the kernel claimed from its environment at startup (ROMP_MODEL_CATALOG=off stops it); and the fast-mode organisation probe on the helper's key at a key-billed session's launch, the second of the two API calls the reference's Service environment and credentials section names as the kernel's own. To GitHub, or whatever host the release remote and a checkout's origin point at: the release check's `git ls-remote --tags` and the drift check's `git ls-remote` of main (ROMP_UPDATE_CHECK=off, or the gear's update mode off, stops both) and the `git fetch` of an update taken from the banner or by the gear's auto mode; the PR watch's `gh pr view`, about once a minute per pull request a session registered with `romp watch-pr`, on gh's own token, re-armed at boot from the saved rows, with no switch; and the file viewer's `git ls-remote --heads origin` in a viewed file's checkout when its branch has no local tracking ref (a no from origin is remembered per branch where the clone's fetch refspec tracks it; anything else is asked again on each open; every credential prompt is closed), with no switch. To the push service of any subscribed phone: web push delivery. To attached machines: the ssh tunnels and everything over them, and the `git push` to and `git fetch` from an attached machine's checkout when you update it from here. To the npm registry: `npm install` in vscode-extension when a bundle rebuild at boot fails with node_modules present, the one retry.
