The kernel fetched a third party's price table (the public LiteLLM list on raw.githubusercontent.com, no credential) whenever the Token usage modal opened with a cache older than six hours, with no off switch and no trace: a table served from the built-in defaults read as live, and a failed fetch was swallowed by a bare return. ROMP_PRICE_FEED=off copies the model catalog's switch (ROMP_MODEL_CATALOG=off: the same stripped, case-folded read, placed as the first statement of _refresh_remote_prices, the one function a fetch can start in, before the TTL check and the stamp) and goes one step past the catalog's silent off: the state is said where the user looks. One function, _price_feed_status, computes the block the /analytics payload carries as priceFeed (outside the 15 s memo on both roads, and describing the table that priced the figures beside it: a landing that changes the rows clears the memo, so the click after it prices from the landed table instead of serving the old table's dollars under a block that reads live, and a build whose fetch landed during its sessions walk, after its pricing merge, prices once more from the table now) and /version carries beside modelCatalog, so the modal, /version and a curl cannot disagree. The worker publishes a landing (the cache and the fields that describe it) under _price_feed_lock, the lock the status reads its one snapshot under, so no read pairs one fetch's rows with another's counts.
