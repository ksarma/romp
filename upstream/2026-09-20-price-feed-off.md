The kernel fetched a third party's price table (the public LiteLLM list on raw.githubusercontent.com, no credential) whenever the Token usage modal opened with a cache older than six hours, with no off switch and no trace: a table served from the built-in defaults read as live, and a failed fetch was swallowed by a bare return. ROMP_PRICE_FEED=off copies the model catalog's switch (ROMP_MODEL_CATALOG=off: the same stripped, case-folded read, placed as the first statement of _refresh_remote_prices, the one function a fetch can start in, before the TTL check and the stamp) and goes one step past the catalog's silent off: the state is said where the user looks. One function, _price_feed_status, computes the block the /analytics payload carries as priceFeed (outside the 15 s memo on both roads, and describing the table that priced the figures beside it: a landing that changes the rows clears the memo, so the click after it prices from the landed table instead of serving the old table's dollars under a block that reads live, and a build whose fetch landed during its sessions walk, after its pricing merge, prices once more from the table now) and /version carries beside modelCatalog, so the modal, /version and a curl cannot disagree. The worker publishes a landing (the cache and the fields that describe it) under _price_feed_lock, the lock the status reads its one snapshot under, so no read pairs one fetch's rows with another's counts.

What the user sees, on one muted line under the modal's footnote, worded by gear.js raPriceNote from the payload's block: with the feed live, `prices: live feed, fetched 4 minutes ago` (the age in plain words from the kernel's ageS); when the feed priced some of the table's models and not all (`rows` below `known`, the ids the built-in table holds), `prices: live feed for 1 of 6 models, fetched just now; built-in defaults for the rest`, and when rows the feed had for known models could not be read (`matched` above `rows`) `; the feed's rows for 1 known model could not be read` follows the share; with the switch on, `prices: built-in defaults; live feed off (ROMP_PRICE_FEED=off)`; after a failed fetch, `prices: built-in defaults; the feed could not be fetched (HTTPError: HTTP 500)` (a reason class, never the response body or the URL: the exception type, an HTTP status, a wrapped socket error's type and errno, an SSL failure by OpenSSL's reason token and the verify code's entry in the kernel's copy of OpenSSL 3.0's verify-error table, such as `SSLCertVerificationError: CERTIFICATE_VERIFY_FAILED (self-signed certificate)`, `(hostname mismatch)` or `(format error in certificate's notBefore field)`, the verify message itself never read because CPython composes it with the server hostname for a hostname or IP address mismatch, and a code the table lacks, or any code under an OpenSSL before 3, reading `(verify code N)`, so the label never carries the URL or its host, a resolver failure by the EAI_ constant's name and libc's text such as `gaierror: EAI_NONAME (Name or service not known)`, never a system errno's text for a library code); on the modal's first open, `prices: built-in defaults; fetching the feed now` (the payload is built before the fetch it starts lands, and the next open reads the feed); before any attempt, `prices: built-in defaults; nothing fetched from the feed yet`; after a fetch that landed and left no usable row, `prices: built-in defaults; the feed matched no known model` when no row signed to a built-in id (`matched` 0), or `prices: built-in defaults; the feed's rows for 2 known models could not be read` when rows did and none parsed. A landed or failed result outranks a fetch in flight, so the TTL re-attempt keeps saying failed or empty while its worker runs. Under off a cache already in process memory keeps serving with its age said, and the feed line then carries the refresh's own state, `prices: live feed, fetched 10 minutes ago; refresh off (ROMP_PRICE_FEED=off)`, or after a refresh that failed while the rows still serve, `; the last refresh failed (HTTPError: HTTP 500)`: the switch stops traffic, not data, and there is no cache file. Rows from the user's ~/.config/romp/model-prices.json price their models whichever table the line names, so the block counts them (`overrides`, from the merge that prices) and either line ends `; 1 row overridden by model-prices.json` when one is in effect. A payload without the block (an older kernel) renders no line, and a block without a newer key (`matched`, `known`, `overrides`) is worded as the older shape. Stderr, in the catalog's idiom, each line's tail read from the same status and worded with the facts the modal's line words (the source, the share a partial feed priced, the age, the overrides), so the log and the modal cannot disagree: `price feed: off (ROMP_PRICE_FEED=off); the cost view prices tokens from the built-in defaults` once per kernel life at the first refused attempt (a kernel where nobody opens the modal says nothing; with rows already in memory the tail reads `the feed rows in memory, fetched 2 h ago`, or `the feed rows in memory for 1 of 6 models, fetched 2 h ago, and the built-in defaults for the rest` when the feed priced some of the table's models, and an override in effect appends `, 1 row overridden by model-prices.json`); `price feed: fetch failed (<reason class>); ...` with the same tail, once per failed fetch, which the six-hour TTL bounds to one line per six hours; `price feed: fetch landed with no usable row (2 signed to a built-in id, none parsed); ...` once per such fetch; `price feed: fetch landed with rows for 1 known model unreadable (2 signed to a built-in id, 1 parsed); ...` once per fetch that parsed rows for some known models and not others; and `price feed: fetch failed (<reason class>), the worker thread did not start; ...` when the refresh's thread could not start, which clears the in-flight mark and records the failure instead of leaving the status reading inflight for the TTL.

What the switch stops is one request, the price feed's; every other request romp makes leaves as before. The list below is a census of the code at this head, not a promise: a later commit can add a road without touching this entry. The census reads every urlopen, http.client and socket site, and every subprocess argv naming gh, git ls-remote, fetch or push, ssh or npm, over kernel/, cli/, postal/ and bin/; connections to 127.0.0.1 (the manager, the postal bus, the tunnels' local ports) are set aside as local. It does not read two kinds of request, named at the end of the list: the ones the browser showing the dashboard makes for itself, and the ones the install scripts make when you run them by hand before romp starts.
