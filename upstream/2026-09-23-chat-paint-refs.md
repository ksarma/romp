An inline svg's `fill`, `stroke`, `mask`, `clip-path`, `filter` or `marker-*` attribute holding a `url()` to another origin made the browser request that document the moment a chat message or a hovered file preview rendered, with no click: the sanitizer keeps all eight attributes and nothing after it on those two surfaces read them. What left was the reader's IP address, the time, the user agent, the page's origin for `mask` (a CSS image, sent as the Referer under the kernel's same-origin policy) and whatever path and query the author wrote into the `url()`. The surfaces reached are the kernel-served dashboard and the iOS web app, not the VS Code panes, whose `img-src` names only the webview's own resources and `data:` (read from the policy's text, not executed). Red before the fix, at 6cf6839ba and with the passes removed (2026-09-23, Chromium 151): the chat witness's logger received 19 requests and the hover witness's 10. `filter`, measured by the design study as fetching only same-origin in Chromium 151 (where figure-gate.ts's 2026-09-09 note said all eight fetched), reached neither logger; on the hover path the page's request event fired for it and no request arrived. It is removed by rule. The fix is one strip (paint-refs.ts dropRemoteRefs) run inside sanitizeMd by default and in the preview card's strip; the file viewer opts out and keeps its click gate.
