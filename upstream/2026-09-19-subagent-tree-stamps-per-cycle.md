Gated on fold 3 (fork PR #875) and the dependency-key fix (fork PR #910) landing first, and on a clean landing round for this PR.

Upstream already holds each subagents tree once per cycle, and this PR carries the follow-up that change names. romp-on/romp PR #1822 (cf0be377f) stores one sample per subagents root, the (directories, stats) pair _subagent_tree answers, on `_live_scope.subagent_trees` for each pusher cycle, jobs pass and connect push, and counts a read answered from a held pair under `scoped`. romp-on/romp PR #1788 is the walk memo underneath it (_SUBAGENT_TREES: a tree validated by one lstat per known directory instead of a listing). The commit message of romp-on/romp PR #1822 names the viewer frame's hit-path re-stats through _dir_stamps as a separate route and a follow-up. The dependency-key defect that romp-on/romp PR #1822 brings (the agent-file walk noted a sibling root under a stat taken after the held listing) is fixed by fork PR #910, which has its own entry, upstream/2026-09-24-subagent-tree-dependency-key.md.

This PR holds the agent-file lookup's re-checks and the launch folds on that scope. Upstream's _subagent_file re-checks a memo hit by stat-ing every directory its walk read, which for a nested agent's file or one found nowhere is the whole tree, and _awaiting_nest folds each awaiting agent's launches once per _session_awaiting call, several calls per session per cycle, so with nothing changed each call re-stats the tree's directories for every awaiting agent. This PR derives two slots from the held samples. The stamp index, `_live_scope.subagent_stamps`, is filled from each pair as the pair is stored, and _dir_stamp answers a directory it holds with no stat: the memo hit's re-check through _dir_stamps (a viewer frame's among them, when a pusher cycle or a connect push builds the frame) and the walk's stamp of a held root. A directory no held pair lists (the project directory on a miss walk) is stat'd once and that stamp is held for the rest of the scope. The launch folds, `_live_scope.subagent_launches`, fold each agent once per cycle, pass or push; a fold that did not read the file is held for the one _session_awaiting call that observed it and folded again by the next. Both slots open and clear at exactly the sites that open and clear `subagent_trees`: the try and finally of _pusher_cycle and _jobs_cycle, and on a connect push _chat_push_scopes_open, which records them as owned before the push's shared read, with _chat_push_scopes_close. So a value derived from a held tree lives exactly as long as the tree and where the tree lives, and a change on disk after the scope's sample, a root's removal included, is seen by the next scope's first read, upstream's one-cycle lag. Of the readers on handler threads, the connect push holds the three slots across its chat loop and viewer frames; the others (a viewer's open, the history and episode replies and the act-now nudge pass among them, the full list in _subagent_tree_memo_report's docstring) hold none and read per call. The measurements that motivated the change, dated 2026-09-19 (a py-spy profile of a deployed kernel with _dir_stamp's os.stat as its top self frame, and another kernel's memo counters), are in tests/test_subagent_tree_stamps_per_cycle.py's module docstring.

The fork's front differs from upstream's in two rules, each with a case that is red under upstream's rule. (i) A sample that reported a fault below its root (a listing, an entry's type or a child's lstat failing for a reason other than absence) is not stored in the scope, where upstream stores any answer with a directory: a held pair reports no fault to a later reader, so the agent-file walk served it would take the unread places for read ones (tests/test_subagent_tree_stamps_per_cycle.py Guards test_a_walk_with_a_failed_listing_is_not_held_while_a_clean_walk_is). (ii) A root whose lstat fails for a reason other than absence (EACCES from a parent, EIO) raises _SubagentTreeUnreadable from _subagent_tree_sample, where upstream's sample takes every OSError for absence and pops the entry (tests/test_subagent_tree_memo.py UnreadableRoot, an EIO by mock and a real EACCES). Under (ii) the root is neither absent nor held: its readers answer their standing entries unheld or an unreadable marker and the chat build is told to read again, except that with no entry standing the sidecar map answers {} and the agent-file lookup answers a caller that passes no faults list None, so the viewer says the agent's transcript is missing while the fault lasts (ViewerUnderAnUnreadableTree; having the viewer state the fault is a follow-up fix after #882). The agent-file walk excludes that tree from its search and nothing else, answering a file found under any other tree (FaultExcludesItsOwnTree), the shape stated once in _subagent_tree's docstring. A fault on the walk's read of any other place it searches (a place below a tree's root, a candidate file, a project-directory entry, the listing) excludes that place alone, the places stated once in _subagent_file_walk's docstring (FaultBelowTheRoot and FaultOnTheWalksOwnRead), and a lookup that excluded a place and found its file nowhere else memoizes nothing, so no miss is memoized under a fault. Nothing failed is held: a missing or replaced root, a stamp whose stat raises and a faulted launch fold leave no entry in the scope.

This PR also records more of the dependency key than fork PR #910 does. Fork PR #910 has the agent-file walk record every directory of each tree it looked through under the stat of the read that answered its lookup, and this PR adds two things. The walk's noted (path, key) pairs are stored with its answer, in the agent-file memo's entry and in the held launch fold's, and a lookup either one answers replays them unchanged (_subagent_file_notes_replay), so every build that looks the agent up records the keys of the walk behind its answer; without the replay, a lookup the memo answers records nothing for the trees its walk read. And a path one build reported under two different keys, whose payload then embeds reads of the path in two states, is recorded under _CHAT_DEP_KEYS_DIFFER, a key no stat produces, so the next signature misses and the tab is rebuilt (_chat_build_deps).

dirStats also counts _dir_stamp's stats: each os.stat it takes that succeeds and is not served from the stamp index (the walk's stamps of the own root, the project directory and each sibling root, and the memo hit's re-check), beside the validation's lstats. That joined on 2026-09-19; before it dirStats counted the lstats alone, so a figure from before the deploy and one from after are not one series. The population is stated once, at the _SUBAGENT_TREE_STATS comment. The cost, road by road on each loop, on a connect push and on a thread that holds no slot, each term with the executed case that pins it by equality: _subagent_tree_memo_report's docstring.
