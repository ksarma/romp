The agent-file lookup's memo (_subagent_file) re-validated a hit by stat-ing every directory its original walk read, which for a nested or missing agent's file is the whole subagents tree; _awaiting_nest resolves every awaiting agent's file per _session_awaiting call, and the pusher makes up to five such calls per session per cycle, the jobs pass one more. So one call over A nested agents paid (A+1) x D directory stats with nothing changed (two or more agents, or a command row whose owner is read from their transcripts). Measured on two deployed kernels on 2026-09-19: a 20 s py-spy profile of one had _dir_stamp's one os.stat as the top self frame, 28 percent of the samples by the profile's reading, over trees of 305, 383 and 72 directories; the other's memos.subagentTree counters showed 24.5 million validation lstats and 22.7 minutes in validateMs over 6.8 hours across 1,294 directories.

The fix keys the validation on the event a time window would have stood in for: the pusher cycle and the jobs pass. Each opens a thread-confined scope on _live_scope (_subagent_scope_open inside the try beside the other per-cycle slots, closed in the finally) holding three memos: the validated (directories, stats) pair per root, each directory's stamp in the shape _dir_stamp answers, and _awaiting_nest's per-agent launch ids keyed (transcript, agentId). The first reader of a tree in the cycle validates or walks it; every later reader on that thread in the cycle, the agent-file lookup's stamp re-check included, pays no stat. Each scope entry carries the root it depends on (the tree's own root for its pair and the stamps indexed from it, the transcript's own subagents root for a launch fold, since the fold is produced through the file's resolution under that tree) and the _SUBAGENT_TREES_GEN value read before its disk read; a root leaving _SUBAGENT_TREES (the forget, per evicted root; the missing-root and replaced-root pops when they removed an entry) moves the gen by one and records the new value against that root in _SUBAGENT_ROOT_EVICTED, and an entry is served only while no eviction of its root has happened since, so an eviction is honoured on both threads for that root's pair, stamps and launch folds and nothing else moves (round 2 of #882: until then one process-wide value emptied every scope's three maps on any root's eviction, which re-validated every held tree and re-folded every awaiting agent's file on both threads, once per forget rather than once per cycle). A stamp _dir_stamp took itself, whose tree the scope cannot name (the project directory on an agent-file miss), is vouched by no root and re-taken after any eviction. The table is bounded at 1024 roots; an eviction of a root not in a full table clears it and records the generation, which drops every held entry once. Nothing failed is held: a missing or replaced root, a walk with a failed listing or child lstat, a stamp whose stat raises and a launch fold that did not read the file are answered as before and leave no entry in the scope; the faulted fold is held for the one _session_awaiting call that observed it (each of the A agents' owner lookups consults every other agent's launches, so a fault re-folded per lookup cost A x (A - 1) folds per call where a call-local memo costs A) and is folded again by the next call, so a file that became readable is seen then. _dir_stamp now counts each successful os.stat into dirStats, so the counter reads both validators (the lstat half alone before), and a figure from before the deploy and one from after are not one series. The key a chat build records for a subagents tree the agent-file miss walk looked through (_subagent_file_walk) is the served read's (mtime, size) per directory (_subagent_tree_dep_note, the shape the sidecar map already recorded for the own tree), never a stat taken after it: round 2 of #882 found the walk recording each sibling root under a fresh stat taken after the served listing, so a file landing after the hold under a directory the listing lacked was recorded under its own post-landing key, equal to every later re-stat, and the tab that showed the agent's file missing was never rebuilt; and it recorded the root alone, which a landing under a listed child never moves.

Bound per tree per cycle and per pass, for the two loops' own reads: D os.lstat (the one validation) and 0 os.stat when the tree is read before any agent-file lookup, at most D of each when a command row's owner lookup re-checks stamps first, plus the miss path's project and sibling directory stats; plus, per root that left the memo in the cycle, one read of that root at its next lookup (a walk, or D lstats when a read on another thread re-inserted it meanwhile) and one fold per awaiting agent whose file resolved under it, its D plus its A, with every other root's pair, stamps and folds untouched (the module's lab: R roots of D directories and A agents with one unrelated root evicted between each pair of N reads cost the round-1 head R x D x N lstats and R x A x N folds per cycle, the scoped invalidation R x D and R x A, the figure with no eviction). Stale window: a change on disk after the cycle's validation is seen by the next cycle's first reader, one cycle later at most (the pusher's wake or its 0.5 s backstop under the 1 s minimum interval, the jobs thread's 0.5 s pace, plus the cycle's own duration). Handler-thread builds (WS and HTTP), connect pushes and the act-now nudge pass hold no scope and read per call as before.

tests/test_subagent_tree_stamps_per_cycle.py: a tree of eight directories with three nested workflow agents beside a synthetic session, driven through the real _pusher_cycle and _jobs_cycle with the tick jobs stubbed to three _session_awaiting reads each. Before the fix one cycle paid 72 os.stat on the tree's directories (3 x A x D), 24 os.lstat and dirStats +21; after, 0 os.stat, 8 os.lstat (D), dirStats +7 (D - 1), one hit and 3 agent-file stats. Also: a directory landing between cycles is seen by the next cycle and not by the same one; a pusher cycle and a jobs pass at once each validate once with their own scope; the forget, faulted-stamp, unclean-walk, faulted-launch-fold (the folds per call counted through the real fold with the reader's stat raising, at A = 3 and A = 6) and vanished-root guards are shown against the input each refuses and accepts, and the fault producer is driven for real (the reader's fail path, a raising fold, a readable file); the scoped invalidation: a held tree, a held stamp and held launch folds survive an unrelated root's eviction (0 lstats, 0 stats, 0 folds on the next read, where the round-1 head paid D, 1 and A), a cached agent-file path is not answered after another thread found its tree gone, held launch folds are re-read when their own root leaves the memo (a command the agent's transcript gained mid-cycle nests under it), and the table of evicted roots at its cap is cleared with every held entry dropped once; the dependency key: with a sibling's tree held earlier in the cycle, an agent's file landing under it in a directory the held listing lacks leaves the key the build recorded behind the next signature's re-stat, for the root when the landing moved the root's stamp and for the listed child when it moved that child's (the round-1 head recorded the root's post-landing key and no child), and the next cycle's lookup finds the file; and the miss path inside the bound: an agent row whose file is nowhere costs the one walk per cycle and 0 stamp stats on the tree's directories (the round-1 head paid 1, the own tree's fresh note). Red under the fix reverted and under each named broken variant (sticky scope, module-level memo, no eviction record from the forget or from the missing-root pop, a held fault, a held unclean walk, a launch fold's fault re-folded per owner lookup or held for the cycle, the fault producer deleted, a stamp or a launch fold served without its root's vouch, a table clear that records no generation, a dependency note from a fresh stat, a note of the root alone).
