The agent-file lookup's memo (_subagent_file) re-validated a hit by stat-ing every directory its original walk read, which for a nested or missing agent's file is the whole subagents tree; _awaiting_nest resolves every awaiting agent's file per _session_awaiting call, and the pusher makes up to five such calls per session per cycle, the jobs pass one more. So one call over A nested agents paid (A+1) x D directory stats with nothing changed (two or more agents, or a command row whose owner is read from their transcripts), and per pusher cycle or jobs pass, N reads per session, the two loops' own reads paid N x sum over the sessions read of (A_s + 1) x D_s directory stats and N x sum_s A_s launch folds: linear in the reads, the sessions, the agents and the directories at once (round 1 of #882 asked for the cost in this form, derived and with the lab below as its evidence, in place of a per-call figure and a per-root reading of two production totals, which no mechanism here predicts and two kernels cannot separate). The motivation, a dated reading: measured on two deployed kernels on 2026-09-19, a 20 s py-spy profile of one had _dir_stamp's one os.stat as the top self frame, 28 percent of the samples by the profile's reading, over trees of 305, 383 and 72 directories; the other's memos.subagentTree counters showed 24.5 million validation lstats and 22.7 minutes in validateMs over 6.8 hours across 1,294 directories.

The fix keys the validation on the event a time window would have stood in for: the pusher cycle and the jobs pass. Each opens a thread-confined scope on _live_scope (_subagent_scope_open inside the try beside the other per-cycle slots, closed in the finally) holding three memos: the validated (directories, stats) pair per root, each directory's stamp in the shape _dir_stamp answers, and _awaiting_nest's per-agent launch ids keyed (transcript, agentId). The first reader of a tree in the cycle validates or walks it; every later reader on that thread in the cycle, the agent-file lookup's stamp re-check included, pays no stat. Each scope entry carries the root it depends on (the tree's own root for its pair and the stamps indexed from it, the transcript's own subagents root for a launch fold, since the fold is produced through the file's resolution under that tree) and the _SUBAGENT_TREES_GEN value read before its disk read; a root leaving _SUBAGENT_TREES (the forget, per evicted root; the missing-root and replaced-root pops when they removed an entry) moves the gen by one and records the new value against that root in _SUBAGENT_ROOT_EVICTED, and an entry is served only while no eviction of its root has happened since, so an eviction is honoured on both threads for that root's pair, stamps and launch folds and nothing else moves (since 2026-09-21; until then one process-wide value emptied every scope's three maps on any root's eviction, which re-validated every held tree and re-folded every awaiting agent's file on both threads, once per forget rather than once per cycle). The two pops run only on a read the scope does not serve: a root held earlier in the cycle is served until its scope ends (the stale window below), its removal or replacement found by the next cycle's first read on that thread, or by a read with no hold on it (the other loop's first read of it in its own cycle, a handler thread's), whose pop records the eviction so that the holder's next lookup drops the pair. A stamp _dir_stamp took itself, whose tree the scope cannot name (the project directory on an agent-file miss), is vouched by no root and re-taken after any eviction. The table is bounded at 1024 roots; an eviction of a root not in a full table clears it and records the generation, which drops every held entry once. Nothing failed is held: a missing or replaced root, a walk with a failed listing or child lstat, a stamp whose stat raises and a launch fold that did not read the file are answered as before and leave no entry in the scope; the faulted fold is held for the one _session_awaiting call that observed it (each of the A agents' owner lookups consults every other agent's launches, so a fault re-folded per lookup cost A x (A - 1) folds per call where a call-local memo costs A) and is folded again by the next call, so a file that became readable is seen then. _dir_stamp now counts each successful os.stat into dirStats, so the counter reads both validators (the lstat half alone before), and a figure from before the deploy and one from after are not one series. The key a chat build records for a subagents tree the agent-file miss walk looked through (_subagent_file_walk) is the served read's (mtime, size) per directory (_subagent_tree_dep_note, the shape the sidecar map already recorded for the own tree), never a stat taken after it: round 1 of #882 found the walk recording each sibling root under a fresh stat taken after the served listing, so a file landing after the hold under a directory the listing lacked was recorded under its own post-landing key, equal to every later re-stat, and the tab that showed the agent's file missing was never rebuilt; and it recorded the root alone, which a landing under a listed child never moves.

Bound per cycle and per pass, for the two loops' own reads: the sum over the R roots read of D_r os.lstat (each root's one validation, whatever the readers, agents and reads consult it) and 0 os.stat when each tree is read before its agent-file lookups, D_r more for a root whose command row's owner lookup re-checks stamps first, and one launch fold per agent whose launches are consulted, sum_s A_s; per agent whose file is nowhere or under a sibling's tree, one stat of the project directory and one per directory of each sibling subagents tree that no read of the cycle holds (the cold walk, which lists the project directory and reads each sibling's tree, is paid once, when the agent-file memo has no entry for the agent or a stamp it read moved; round 1 of #882's fresh-4: stated before as the miss path's sibling directory stats, one per sibling on a flat sibling tree and one per directory on a nested one). A lab lifted from the module's world (R sessions of D directories, A agents and N reads, through the real _pusher_cycle and _jobs_cycle), run outside the repo with its records kept outside it, measured in each of the cells run, (R, D, A, N) in {(1, 8, 3, 1), (1, 8, 3, 3), (1, 8, 3, 5), (9, 156, 3, 1), (9, 156, 3, 3), (9, 156, 3, 5), (9, 156, 8, 3), (1, 156, 3, 3), (9, 8, 3, 3), (3, 96, 3, 3), (9, 32, 3, 3), (3, 32, 3, 3)}, before the scope N x R x A x D stats (72 at (1, 8, 3, 3); 2,592 at (9, 32, 3, 3); 12,636 at (9, 156, 3, 3); 21,060 at (9, 156, 3, 5); 33,696 at (9, 156, 8, 3)) and N x R x D lstats, and with it R x D lstats and 0 stats, nine roots of 32 directories costing what three of 96 cost (288 lstats): the total directories decide, not their split over roots, which the module's SumOverRoots cases pin in the tree at three roots of unequal size through the real cycles. Plus, per root that left the memo in the cycle, one read of that root at its next lookup (a walk, or D lstats when a read on another thread re-inserted it meanwhile) and one fold per awaiting agent whose file resolved under it, its D plus its A, plus one stat per stamp the scope took itself (vouched by no root: an agent-file lookup's re-check before the tree was read, the project directory on a miss), with every other root's pair, stamps and folds untouched (the same lab, at (R, D, A, N) = (1, 8, 3, 3) and (3, 8, 3, 3) with one or three unrelated roots evicted between each pair of the N reads: the one-generation design paid R x D x N lstats and R x A x N folds per cycle, the scoped invalidation R x D and R x A, the figure with no eviction). Stale window: a change on disk after the cycle's validation is seen by the next cycle's first reader, one cycle later at most (the pusher's wake or its 0.5 s backstop under the 1 s minimum interval, the jobs thread's 0.5 s pace, plus the cycle's own duration), the tree's own removal or replacement included (the pops run on a read the scope does not serve). Handler-thread builds (WS and HTTP), connect pushes and the act-now nudge pass hold no scope and read per call as before.

tests/test_subagent_tree_stamps_per_cycle.py: a tree of eight directories with three nested workflow agents beside a synthetic session, driven through the real _pusher_cycle and _jobs_cycle with the tick jobs stubbed to three _session_awaiting reads each. Before the fix one cycle paid 72 os.stat on the tree's directories (3 x A x D), 24 os.lstat and dirStats +21; after, 0 os.stat, 8 os.lstat (D), dirStats +7 (D - 1), one hit and 3 agent-file stats. and the held-root lag characterized: a root removed while the same thread's scope holds it is served, pair and stamps, at no stat until that scope ends, and the next scope's first read finds it gone), and the fault producer is driven for real (the reader's fail path, a raising fold, a readable file); and the miss path inside the bound: an agent row whose file is nowhere costs the one walk per cycle and 0 stamp stats on the tree's directories (the round-1 head paid 1, the own tree's fresh note); and the sum over roots: three alive sessions with trees of unequal size and unequal agent counts, their reads interleaved in one pusher cycle and in one jobs pass, cost the sum over their roots of D_r lstats (each root its own D_r), 0 stats and one fold per agent, the sum over the sessions of A_s. Red under the fix reverted and under each named broken variant (sticky scope, module-level memo, no eviction record from the forget or from either pop, the root checked on disk before the hold is served, a held fault, a held unclean walk, a launch fold's fault re-folded per owner lookup or held for the cycle, the fault producer deleted, a stamp or a launch fold served without its root's vouch, a table clear that records no generation, a dependency note from a fresh stat, a note of the root alone).
