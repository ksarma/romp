On the watchdog path of the node probe (no coreutils `timeout` on PATH, the normal case on a stock mac), a stand-down TERM that the shell handled after the watchdog forked its sleep but before `_s=$!` recorded the pid ran the trap with no pid, so the trap ended nothing and the sleep ran on to its bound (ten seconds by default) after the launcher had exec'd the manager. bin/romp-service's install probe has the same watchdog and the same race. In both, the trap now records the stand-down in a flag when it has no pid, and a check right after the assignment ends the sleep. The probe wrapper, which runs the copy's node and which the watchdog kills at the bound, had the same kind of race and gets the same fix (below).

On the fork's CI the race failed the launcher's session check twice in 964 completed runs of the Shell (bats, ubuntu-latest) job that carried the check, in the 30 days to 2026-09-30. A local loop over the launcher's own functions left a sleep, each time after a trap with no pid, in 10 of 1,500 iterations under CPU contention and in 18 of 20 with strace delaying every fork's return; on a quiet machine it left none in 3,000.

The fix covers every point where the TERM can land. Before the trap is set, TERM's default action ends the subshell before it forks anything. Between the trap and the fork, or between the fork and the assignment, the trap sets the flag and returns, and the check after the assignment ends the sleep. After the assignment, the wait included, the trap finds the pid, ends the sleep and exits. The trap never falls back to `$!`: before the fork, `$!` in the subshell is the probe wrapper's pid, inherited from the launcher, and ending the wrapper's tree would fail a good copy.

The probe wrapper had the same window. A TERM handled after the wrapper forked the node but before `_n=$!` (`n=$!` in the install) recorded the pid, the fork itself included, ran the trap with the pid unset, and under `set -u` the trap's expansion ended the wrapper with the node still running. A copy that hung there outlived the launcher, which ran the manager on the system node, or outlived the install, which removed the copy. The wrapper has to stall in that window from its fork of the node until the watchdog's sleep runs out, about the bound (ten seconds by default), so this is far rarer than the watchdog's race. The wrapper now follows the watchdog's rule: the trap records the TERM in `_halt` (`halt` in the install) when it has no pid, and a check right after the assignment kills the node's tree, waits for it and exits. The pid starts empty, so a value from the environment is never taken for it. The flag is not named `_stop` like the watchdog's, so the two checks differ in text and a test can stop each subshell at its own.

The new tests are deterministic. Under bash with `set -T`, a DEBUG trap read through BASH_ENV sends a subshell its TERM just before a named command of its own, so the pending TERM trap runs at that point. Each file gets three cases for the watchdog: before the fork, between the fork and the assignment, and after the assignment. Each case checks that the watchdog exited on that one TERM, that the probe's wrapper and the copy under it got no signal, that the sleep is gone and that nothing is left in the session. On the fork's main the case between the fork and the assignment failed 10 of 10 runs in each file, with the watchdog's sleep still running; the other two cases passed. With the watchdog's fix, all six cases passed 10 of 10 runs. Three broken versions of that fix each fail at least one case: a trap that falls back to `$!` kills the probe's wrapper, so the launcher runs the manager on the system node and the install removes a good copy; the fix without the check after the assignment leaves the watchdog waiting out its bound, which holds the launch for that long; a trap that exits even when it has no pid leaves the sleep, as on main.

Each file also gets four cases for the wrapper, with a bound of 30 seconds so the watchdog never fires and a copy whose probe run hangs: the TERM before the fork of the node, between the fork and the assignment, at the check after the assignment, and before the wait. Each case checks that the copy failed its probe (the launcher ran the manager on the system node, the install removed the copy), that the copy's node is gone and that nothing is left in the session; the launcher's cases also check that the node was already gone when the manager started. On the fork's main, and with the watchdog's fix alone, the case between the fork and the assignment failed 5 of 5 runs in each file, with the copy's node still running when the manager started (the launcher) or after the install returned; the case at the check failed too, since that check did not exist. With both fixes, all fourteen cases in the two files passed 5 of 5 runs. Three broken versions of the wrapper's fix each fail at least one case: without the check after the assignment, a TERM before the fork or between the fork and the assignment leaves the wrapper waiting on the hung copy until it answers and passes its probe; a trap that exits when it has no pid leaves the node running, as on main; a trap that only sets the flag leaves the wrapper waiting on the copy when the TERM lands before the wait, with the same result.

Each case first checks that the TERM was sent, and the cases at and after a fork check that the prelude recorded the forked pid. A script that respells the command a case stops at, or the assignment whose pid the prelude records, fails the case with a message naming that command, not at a later assertion that would read as a broken fix.

tests/romp-node-launch.bats passes 31 of 31 with the fix and 24 of 24 on main; tests/romp-service.bats passes 63 of 63 and 56 of 56; tests/shell-portability.bats passes 13 of 13 on both.

upstream/main, as of the last local fetch of it (2026-09-24), has the same code: its bin/romp-node-launch is identical to the fork's, and its bin/romp-service carries the same wrapper and watchdog lines in `_node_runs`. The diff applies to upstream's copies of the four changed code and test files in a patch dry run; it has not been run against that tree.
