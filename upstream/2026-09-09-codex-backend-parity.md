Upstream drift at the backend birth (6334a2fb): CodexBackend.prune_live took three positional arguments while kernel._merge_live_atoms passes four (human_floor), so every live merge of a Codex session with a queued send raised TypeError (chat build and feed merge failed; timeline bars logged live-merge failed). upstream/main still has the 3-arg def. The Codex model picker also opened blank with no reason: model_catalog answered [] silently (client backoff, a failed model_list, or an empty page cached for the process), /models swallowed it, and the gate flip at the first Codex spawn sent no models frame. Fix: the four-argument prune_live with the record-time text floor, the ABC signature, an AST parity test over every backend, a loud codex.error on /models, the models frame from both doors that open the gate (the spawn and the revive of a dead session), the closed gate naming itself, and the picker row that names the reason, re-reads on open, and says when that read fails. The Codex echo atoms also carry the `_echo_text` marker the kernel's echo rules key on (hidden behind the queued bubble, never counted as live work), the echo is stamped in whole seconds like the SDK's, and the backend's own retire takes one echo per landed text block, the oldest carrying the text, so a turn that batches several queued inputs (one text block per input in the user record) lands each of its echoes through both retires, the backend's and the kernel's prune; the dead-path retire drops only the echo the send minted. The models frame fires on each door's own before-snapshot of the gate or on the backend's closings counter (gate_closings, incremented under the backend's sessions lock at every write that leaves no live row) having moved since that snapshot, so two first creates that race still send at least one where a count of live rows after landing sent none, a kill interleaved with a create, which the snapshot alone missed, still sends one, and two creates racing that kill (both snapshots saw the row, both landings followed it), which a count of exactly one missed too, both send one (two frames per app, each a cheap re-read the rev check reconciles), while a kill after the row landed sends none, and a door whose spawn or revive aborts after landing its row still announces a gate it saw closed (another door may have snapshotted that transient row as the open gate and landed beside it, so the set never emptied and only the aborting door knows); the gate itself is one read under the backend's sessions lock (has_live), where the row walk live_sessions() could answer closed across a landing and a kill while a row was live; the picker's rebuild re-resolves its badge when the statusline was rebuilt under it (a menu placed from a detached button sat off-screen) and stays closed when no badge remains, or when the chat's tab it was opened on has since been dismissed (a thread popover's menu names its own sid and is unchanged); and the chat's picker records a non-2xx /models answer as its HTTP status rather than a JSON parse message (the timeline lane's own loader still swallows a failed read).
