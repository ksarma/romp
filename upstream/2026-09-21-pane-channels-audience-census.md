Upstream's PANE_CHANNELS in ui/webview/federation.ts (from PR 1839) is a hand-kept set of the four panes that render a pushed channel a remote host can be heard on, and ui/webview/federation-reconnect.test.ts drives the panes it names one at a time (the feed and the timeline on their own channels, the chat on the tab list, settings and files pending nothing), so nothing there reads the kernel's push audiences: a pane the kernel pushes to that the set misses pends no host and posts nothing to the shell, which is how this fork's fifth pushed-channel pane, the Waiting-on-you pane (app `waiting`, in the feed branch of kernel.py `_push` beside the feed pane and the Outline), dropped out of the pending signal at the fold that brought the set in. The fork's census case reads kernel/kernel.py's `_push` body and accounts for every read of the `app` key written as a string literal in it, however spaced or wrapped (a subscript or a `.get` with any whitespace around the literal and around the call's dot, name and paren, a subscript wrapped over a line), against three forms it can read (the body first normalised: comments dropped, a backslash continuation joined, a newline inside brackets folded, so a wrapped tuple reads as one line): a tuple of string literals, however wrapped or spaced and with members of any name (the feed branch and its twin in the except arm, the warm gate's pair), a singleton compared by `==` with a string literal of any name (the chat's and the timeline's, the Outline's through `c.get`), and a value formatted into text (the send log line's `%` operand), which is no audience; every other form (a membership test against a name, an attribute or a call, such as a named constant; a membership test against a list or a set literal; a tuple with a member that is not a string literal; a negated test; an equality test against anything but a string literal; a `.get` with a default; the read bound to a name; a read in any other position, a call's argument or a returned value) is named, counted over the body and asserted absent, so a pane added to any of `_push`'s audiences in any spelling of the key as a literal reads red, in the roster or as a named form with its statement and line (review round 3, 2026-09-21: a wider regex was defeated by a named constant, which no pattern over literals can read; the enumeration turns that red). A second scan lists every `app` literal in the body that the detectors did not read (the key, a tuple's members and a singleton's compared value are the reads) under one label, the app literal in a position the census does not read, whatever holds it (a binding of any shape, a default, a keyword argument, a passed value), and a third lists every subscript or `.get` whose key is a bare name, whatever the name if it is ASCII (a subscript only behind a receiver, as the receiver-class text below says); the census asserts both empty, so the road from inside the body to a key held in a name is red at both ends, the literal and, for an ASCII name, the read. The receiver-class text, word for word here, in the census's comment and in federation.ts's PANE_CHANNELS comment (the reconnect test's three-homes case holds the three equal): a subscript is listed only behind a receiver, which is whatever can end a subscriptable primary in Python's grammar: a name that is not a standalone keyword, a closing parenthesis, a closing bracket, a closing brace or a closing quote, double or single, so `pick(c)[k]`, `targets[0][k]`, `{**c}[k]`, `"abc"[k]`, `'abc'[k]`, `self.match[k]` and a generic annotation such as `list[str]` are listed, while a one-element list display (`xs = [c]`, `return [c]`) and a sequence pattern behind the soft keyword case (`case [k]:`) are not. The derived set: a name is a whole identifier token, ASCII or not; a number of any spelling, an Ellipsis or a keyword constant (None, True, False) before a bracket is unlisted; a name after a dot is an identifier only where Python allows one there (match and case). So a name never starts behind an identifier character: `1j[k]`, `0x1f[k]`, `0xff[k]` and `1e5[k]` are not listed through their tails, and a name with a character past ASCII is listed whole. Nor does a name start directly behind a number's trailing dot (a digit run that starts a token, then the dot): `1.e5[k]` and `1_0.j[k]`, one number token each, are not listed, while `v5.e5[k]` and `1.5.e5[k]`, attributes, are. Both rules are lookbehinds on the census's name alternative alone, so a closing parenthesis still ends `f(x)[k]`'s receiver. A hard keyword after a dot is still the keyword, so a list display behind a float's trailing dot or an Ellipsis (`1. in [k]`, `... in [k]`) is not listed. The key, unlike the receiver, is read as an ASCII name: a subscript or a `.get` whose key is a bare name holding a character past ASCII is not listed. Where such a name is bound to the app literal inside `_push`'s body, the unread-literal scan lists the literal; where it is bound outside the body (a module-level constant), the key is listed nowhere, and the census's premise case plants such keys, each asserted unlisted. Deliberately unlisted and disclosed, then: a key named with a character past ASCII and bound outside `_push`'s body; a number, an Ellipsis or a keyword constant before a bracket, none of which can hold the client record; and a bare variable named match or case, subscripted, which reads as the keyword. The census then asserts that the union of the read apps equals PANE_CHANNELS in both directions (an app `_push` addresses that the set misses; a set member `_push` never addresses, which would pend every attached host forever), and drives each member through the manager on the channel its audience names (a tuple naming feed places its members on the feed payload, one naming chat on the tab list, one naming timeline on the lanes, a singleton on its own name), asserting that the other two channels' frames retire nothing and that its own channel's first frame retires it. A second case plants a synthetic `_push` carrying every named form and every relaxed spelling (a tuple wrapped over three lines with a comment inside it, a hyphen and a digit in a member's name, a trailing comma, an unspaced pair, a tuple and a list with no space after `in`, a backslash continuation, the key spaced inside its subscript and inside its `.get` call, a `.get` spaced between its name and its paren and around its dot, a subscript wrapped over a line, a subscript by a bare name behind each receiver the grammar allows (a name, ASCII or not, a call, a subscript, a dict display, a string literal, double- or single-quoted, an attribute named by a soft keyword with the dot tight or spaced, an attribute after a name ending in a digit or after a float, the builtin `type` and the variable `_`), a generic annotation, two one-element list displays, a match statement with a sequence pattern, a number before a bracket in each spelling (`7`, `1j`, `0x1f`, `0xff`, `1e5`, `1.e5`, `1_0.j`), a list display behind the hard keyword `in` after a float's trailing dot and after an Ellipsis, a subscript and a `.get` keyed by a name holding a character past ASCII, first or later, and an audience keyed through a module-level constant so named, a `%` operand, an f-string field, a docstring naming the key) and asserts that each detector fires exactly where planted, that the roster reads the relaxed spellings, that the formatted values read as text, that the subscripts by a name and the generic annotation are listed where planted and the list displays, the pattern, the numbers and the keys named past ASCII are not (the audience so keyed read by no form), that no literal is listed as unread, and that every read of the key lands in exactly one form. A third case plants the literal in thirteen positions the census does not read (an assignment, a tuple unpacking, an annotated assignment with a spaced, an unspaced union or a string annotation, a walrus, a parameter default, a for target, a parenthesised target, a parenthesised and a call-wrapped literal, a keyword argument, a passed value) and asserts that the scan lists each with its line and none from a docstring's prose, another literal, a read key, a compared value or a tuple's member, and that each read through a bound name is listed as a subscript or a `.get` by a bare name. A fourth case, the three-homes case, reads the receiver-class text from this entry, from the census's comment and from federation.ts's PANE_CHANNELS comment, each span normalised for comment markers and line breaks, and asserts the three equal. The census reads `_push`'s body, the pusher's send loop, and no more: senders outside it test the app key themselves (`_feed_first`'s cold first feed frame, `_send_feed_now`'s ready-time frame, the tab strips of `_push_session_now` and `_confirm_close_now`), each addressing a pane `_push` also addresses today, and none is read, so a pane pushed only by a route outside `_push`'s body is outside the census's claim. The key is read as a string literal, and a key held in a name is listed at both ends rather than disclosed, at its read if the name is ASCII and at its literal if the body binds it (review round 6, 2026-09-21: a subscript or a `.get` whose key is a bare name, `c[APP_KEY]` or `c.get(key)`, is listed whatever the name, if the name is ASCII, and every key `_push` reads at the head is written as a literal, so that form has nothing to fire on until a key is held in a name; the literal a name would be bound to is listed in any binding's spelling); what stays outside the claim, disclosed rather than detected, is a key named with a character past ASCII and bound outside `_push`'s body (the receiver-class text above) and a key held in a dict or a list, reached through an attribute or returned by a call (`c[KEYS[0]]`, `c[self.key]`), whose value the body never spells as a literal; the test's title and federation.ts's PANE_CHANNELS comment state the same exclusions. A pane the set misses posts no `hostsPending` at all (round 3's refuters measured this): `pendingFor` returns an empty list for an app outside the set, so the shell loses its connected-loading caveat for that pane while the pane's own loading line still shows, the direction of the Waiting-on-you dropout; the forever-pending direction is the other miss, a set member `_push` never addresses, which the equality's second direction catches. The offer's only change to federation.ts is the `export` on PANE_CHANNELS, which the census imports. The fork-only member, `waiting`, stays in the fork's set and is no part of the offer, nor is the census's clause asserting that the union carries `waiting`, nor the fork's Waiting-on-you case above it; upstream's copy of the census reads upstream's own `_push`, whose reads of the app key at the fold's pin all take the three readable forms (the feed pane and the Outline in the feed tuples, the chat, the Outline and the timeline by singletons, the send log line's formatted value) and name exactly the four apps of upstream's set, so no named form fires and the equality holds there as it does here (the census and the premise case with the `waiting` clause dropped, run against upstream's kernel at the fold's pin and its four-name set in a scratch copy: green). The census yields reds by construction, each shown in a scratch copy of this tree: widening an audience with a name the set misses (the timeline's singleton made a tuple carrying a second app, a wrapped tuple gaining a member, a hyphenated name in a one-line tuple) fails the first direction naming that app; an audience rewritten as a named constant fails the premise assertion naming the form, the statement and its line; adding the new name to the set as well fails its drive, because `pendingFor`'s selector falls every app that is not the timeline or the chat to the per-host feed, so the host's feed frame retires a member whose audience names the lanes; a compliant rewrap of an audience with no new member stays green. The offer, the census case with its normaliser, its classifier and the named forms, the premise case and the export, and nothing else, waits on the offers pipeline; the three-homes case, which reads this entry, stays with the fork.
